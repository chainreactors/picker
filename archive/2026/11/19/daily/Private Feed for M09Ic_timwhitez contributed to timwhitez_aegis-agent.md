## 触发问题

MiniMax 及兼容聚合网关在 Anthropic Messages wire 上用 `output_config.effort` 暴露 OpenAI 的 effort 档位，而不是 Anthropic 原生的 `thinking.budget_tokens`。aegis 无法表达这个字段，因此在这类网关上 `--thinking-level max` 会静默退化成 provider 默认档。

对同一个题目实测 reasoning/thinking tokens：

| 端点与写法 | low | max |
| --- | --- | --- |
| `api.appintheloop.com/v1/responses`（`reasoning.effort`） | 66 | 66 |
| `api.minimax.cn/v1/responses`（`reasoning.effort`） | 638 | 1588 |
| `api.minimax.cn/anthropic`（`output_config.effort`） | 497 | 2236 |
| `api.minimax.cn/anthropic`（`thinking.budget_tokens`） | 无差异 | 无差异 |

## 改动后的行为

新增 provider 字段 `output_config_effort`，贯通 config -> session metadata -> runtime -> adapter。

* Anthropic adapter 仅在值非空时发送 `output_config`，**上游 Anthropic 不会收到未知键**。
* 该字段与 `thinking` 相互独立，两者可同时发送（已对真实端点验证）。
* `--thinking-level` 只在 profile 已声明该字段时改写它；未声明的 profile 行为完全不变。
* raw provider 诊断新增 `output_config_effort`；`thinking_strategy` 扩展为 `output_config_effort`、`manual_budget+output_config_effort`、`off+output_config_effort`。
* `streamjson` 的默认档位在声明了该字段时直接采用它，否则保持原有 budget 映射。
