Closes the two authorization gaps left after [#174](https://github.com/liamg/oriel/pull/174).

**Breaking for third-party plugins:** a plugin whose hook rewrites an event now needs `gate`, and a plugin that binds keys needs the new `keymap` capability in its manifest.

### Hook rewrites need `gate`

* A Lua hook that returns a changed event (a commit message before `ShipCommit`, a PR body before `ShipRaise`, a buffer before save) is checked like a veto or a decision. Without `gate` the hook errors and the event goes on **unchanged**: the check now happens before the rewrite is applied.
* `gate`'s consent text: "veto, decide and rewrite hooks: block or change commits, PRs and saves, and answer permission prompts automatically". Consent goldens, `docs/plugins.md`, the install help page and `docs/api.md` updated.
* `TestPluginRewritesNeedTheGateCapability` (fails without the fix: the message was rewritten).

### New `keymap` capability

* `oriel.keymap.set` needs `keymap` (medium risk, shown at install).
* A plugin may bind only what it could run itself with `oriel.run`: the command's Grant (and `GrantOn`, so `term.open` needs `exec` for that program); never a user-only command; never a function of the user's own config (those are now user-only commands); and a command not yet registered is refused until it is, since it can't be checked. Refused at bind time with an error naming the command.
