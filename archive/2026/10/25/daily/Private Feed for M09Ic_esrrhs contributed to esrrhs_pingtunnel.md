## Why

Community feedback: the authentication key is a **number**, there are **three separate knobs** (`-key`, `-encrypt`, `-encrypt-key`) with unclear roles, and the config surface feels chaotic. This PR is the v3 break that fixes it.

## The new model

One shared secret does everything:

```
sudo ./pingtunnel -type server -password SECRET
./pingtunnel -type client -l :4455 -s <SERVER_IP> -socks5 -password SECRET
```

* **`-password`** (min 8 chars, required on both sides) drives both authentication and encryption. Traffic is **always encrypted** — ChaCha20-Poly1305 by default.
* **`-encrypt`** survives only as an algorithm override (`chacha20` default / `aes256` / `aes128`); it can no longer disable encryption.
* The numeric `-key` and `-encrypt-key` flags are **removed**. The 31-bit auth code in `MyMsg.Key` is now derived from the password (PBKDF2-HMAC-SHA256, domain-separated salts, **600k iterations** — up from 10k). Old numeric peers no longer interoperate: this is the v3 break.

## Config file (v3)

```
{ "type": "client", "listen": ":4455", "server": "x.com", "socks5": true, "password": "SECRET" }
```

* `"password"` replaces `"key"`/`"encrypt_key"`; `"sock5"` is renamed to `"socks5"` (bool).
