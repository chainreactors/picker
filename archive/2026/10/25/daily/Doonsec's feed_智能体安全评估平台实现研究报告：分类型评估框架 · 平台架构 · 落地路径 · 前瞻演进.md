# 执行摘要

本报告回答一个具体问题：如何构建一个能够评估「不同类型的智能体」的安全评估平台，并把评估结论真正转化为可落地的安全能力。

结论先行：智能体安全评估的核心矛盾，不在于「缺少攻击用例」，而在于「评估对象高度异质、失效模式跨层、结论难以互认」。现有测评普遍存在三个结构性缺陷：用同一套 LLM 越狱题库去测所有智能体（类型失配）；只测模型输出、不测行动链（层次失配）；测完出报告、测完即结束（闭环缺失）。

本报告提出以「分类型 × 全链路 × 可闭环」为核心设计原则的智能体安全评估平台（ASEP, Agent Security Evaluation Platform）实现方案，主要贡献四：

1.分类矩阵：建立「自主性 × 环境耦合度」二维分类法，将智能体划分为编排式、工具型、自主型、多智能体、具身型五类，并给出各类的风险权重矩阵与专项用例集；

2.九阶段流水线：从分类画像、风险定级、用例生成、环境构建、对抗执行，到混合裁决、量化评分、定级报告、闭环回灌，形成可复现、可自动化的评估流水线；

3.十维度量体系：定义 ASR、SUR（安全-效用权衡比）、GDI（目标漂移指数）等可计算指标，并针对「模型裁判不可靠」这一行业通病给出双裁判 + 人工仲裁的工程解法；

4.OASP 协议与行业基准：提出开放智能体安全协议（Open Agent Security Protocol）作为评估者与被评估者之间的标准接口，配合基准题库与失效模式库，解决「结论不可比、不可互认」问题。

报告同时给出四阶段落地路线图（90 天 / 180 天 / 12 个月 / 24 个月）与预算、人员、里程碑建议，并对三项前瞻方向（自主对抗智能体、评估者自身安全、动态资格与漂移再认证）作出研判。

# 第 1 章　背景与真实问题定义

## 1.1 从「对话」到「行动」：风险性质的根本改变

2023—2024 年的 AI 安全讨论几乎围绕「模型输出」展开：有害内容、偏见、幻觉、提示词越狱。2025 年以后，产业重心快速转向智能体（Agent）——它不再只生成文本，而是规划、调用工具、读写数据、执行代码、与其他智能体协作。风险的落点随之从「说错话」变成「做错事」，且做错事的动作由系统凭证执行，具备真实权限、真实副作用、真实不可逆性。

这一转变有可验证的规模证据。中国信息通信研究院 2026 年 5 月发布的《云上智能体服务网络和数据安全自律公约（2026 版）》披露：以 OpenClaw 为代表的智能体技术快速普及，截至 2026 年 4 月 15 日我国互联网暴露的 OpenClaw 实例超过 14 万个，其中超 60% 部署于云平台、10% 以上存在高危漏洞，国内至少 600+ 个实例疑似安装了恶意技能。

换句话说，「智能体安全」不是纸面风险，而是已经形成可观测规模的存量暴露面。与此同时，攻击手法也从理论走向工业化：MCPTox 基准对 45 个真实 MCP 服务器、20 个大模型进行测试，测得工具投毒平均攻击成功率 36.5%，对单一模型最高达 72.8%，且安全对齐后的模型拒绝率低于 3%。这直接说明：仅靠模型对齐无法缓解工具层攻击，必须引入系统级评估与围栏。

真正的问题因此浮现：当企业要采购、上线、验收一个智能体时，凭什么判断它「足够安全」？由谁、用什么方法、依据什么标准、给出什么形式的结论、结论能否被审计与复现？

## 1.2 现有评估体系的三个结构性缺陷

| 缺陷 | 具体表现 | 后果 |
| --- | --- | --- |
| 类型失配 | 用统一的 LLM 越狱/有害内容题库去测所有智能体，忽视编排式与具身型在攻击面上的本质差异 | 高分低能：评估通过的对象上线后仍发生越权与数据外泄 |
| 层次失配 | 只评估最终输出文本（「说了什么」），不评估中间行动链（「调了什么工具、读了什么数据、向哪里出网」） | 漏检最危险的动作型风险：工具滥用、越权写入、沙箱逃逸、供应链投毒 |
| 闭环缺失 | 一次性测评，出具静态报告，不进入 CI/CD、不反馈到运行时策略、无版本基线 | 评估结论迅速过期；无回归能力，能力随版本迭代退化而无人察觉 |

此外还有一个被普遍低估的工程问题：评估结论的「可信度」本身无保障。多数方案采用 LLM-as-Judge 做裁判，但裁判模型可被对抗样本「讨好」、存在位置偏见与长度偏见，且当被测对象与裁判同源时，评估有效性进一步削弱。本报告在第 5 章对此给出专门设计。

# 第 2 章　威胁图景：智能体攻击面全景

## 2.1 权威威胁框架的三条主线

当前全球范围内的智能体安全威胁框架已形成三条互补主线，本平台的风险知识库以此为骨架：

| 框架 | 发布方/时间 | 定位 | 对本平台的价值 |
| --- | --- | --- | --- |
| OWASP Top 10 for Agentic Applications（ASI01–ASI10） | OWASP GenAI Security Project，2025 年 12 月 | 面向智能体应用的十大风险清单，每个条目关联在野案例 | 作为风险评估的分类名称空间与默认权重来源 |
| CSA Agentic AI Red Teaming Guide | CSA 与 OWASP 联合，2025 年 6 月（12 类威胁、60+ 测试项） | 测试驱动、面向红队的攻击面测试方法 | 作为用例设计的执行级模板与交付物规范 |
| MITRE ATLAS | MITRE，持续更新（2026.09 版含 120 技法 / 88 子技法 / 40 缓解措施 / 73 案例） | 对抗技法知识库，139 项技法已标记 Agentic AI | 作为攻击技法的原子化描述与攻击链编排词汇表 |

值得注意的量化趋势：MITRE ATLAS 在 2026 年 5 月起为每个技法增加平台标签，其中 Agentic AI 标签达 139 项，超过 Generative AI（106 项）——这一以「模型安全目录」起家的框架，已按自身分类实质转变为「智能体安全框架」。2026 年 7—9 月的更新进一步新增了 AI Agent Tool Poisoning（含工具定义、实现、运行时响应三个子技法）、Autonomous Reconnaissance、Autonomous Attack-Path Adaptation、Autonomous Attack Orchestration、Autonomous AI Agent Communication 等自主型技法，并首次给出两项针对「智能体权限治理」的缓解措施：AI Agent Authority Expansion Controls（AML.M0037）与 AI Agent Scope Drift Detection（AML.M0038）。

这两项缓解措施的官方表述具有重要的架构含义：其控制「应实现在 AI 智能体之外，不应仅依赖系统提示词、模型对齐，或依赖智能体自行识别某动作已越界」。换言之，权威机构已明确：智能体的权限边界与漂移检测必须由外部系统强制实施——这正是评估平台与运行时围栏存在的合法性基础。

## 2.2 OWASP 智能体十大风险（ASI01–ASI10）与在野案例

下表汇总 OWASP 智能体十大风险条目及其公开关联的在野案例，本平台的风险知识库将逐条绑定对应的评估用例：

| 编号 | 风险名称 | 风险本质 | 代表性在野/公开案例 |
| --- | --- | --- | --- |
| ASI01 | Agent Goal Hijack（目标劫持） | 经提示注入或投毒输入篡改智能体目标、指令或决策路径 | EchoLeak（2025）：零点击邮件使 Microsoft Copilot 越界泄露机密数据 |
| ASI02 | Tool Misuse & Exploitation（工具滥用） | 智能体以不安全方式使用工具，或攻击者利用工具接口 | OpenAI Codex CLI（2025）：沙箱配置缺陷致生成代码越界写入 |
| ASI03 | Identity & Privilege Abuse（身份与权限滥用） | 凭据继承/委托缺乏最小化，产生归因缺口与提权路径 | A2A Agent-in-the-Middle（2025）：恶意智能体发布虚假高信任 Agent 卡 |
| ASI04 | Agentic Supply Chain（智能体供应链） | 被污染的 MCP 服务器、技能、Agent 卡与注册表 | Claude Skills（2025）：恶意插件被重新上传部署 MedusaLocker 勒索软件 |
| ASI05 | Unexpected Code Execution（意外代码执行） | 智能体生成或「氛围编程」路径执行非预期代码并绕过控制 | OpenAI Codex CLI（2025）：模型生成代码逃逸沙箱执行 |
| ASI06 | Memory & Context Poisoning（记忆与上下文投毒） | 对持久记忆、向量库或共享上下文的持续污染 | EchoLeak（2025）：精心构造的邮件污染 Copilot 上下文驱动外泄 |
| ASI07 | Insecure Inter-Agent Communication（不安全智能体通信） | 智能体间协议、发现与语义校验薄弱导致伪造、篡改、误路由 | A2A 协议欺骗（2025）：伪造 Agent 卡拦截智能体间流量 |
| ASI08 | Cascading Failures（级联失效） | 单点故障跨智能体与工作流传播放大 | Copilot / Cursor（2025）：AI 建议的后门与逻辑缺陷传播进入生产代码 |
| ASI09 | Human-Agent Trust Exploitation（人-智能体信任利用） | 拟人化与权威偏见被武器化以绕过人类监督 | Copilot / Cursor（2025）：开发者信任 AI 建议导致后门注入与 API Key 泄露 |
| ASI10 | Rogue Agents（失控智能体） | 被污染、失配或漂移的智能体持续以非预期方式运行 | A2A Agent-in-the-Middle（2025）：失控智能体冒充高信任并外泄数据 |

快速筛查工具：Simon Willison 提出的「致命三要素」（Lethal Trifecta）——私有数据访问权 × 接触不可信内容 × 具备外发能力——是上述多项风险同时可被直接利用的充要条件组合。本平台将其实现为资产画像阶段的一键筛查规则，任一同源智能体同时满足三项即自动触发高危告警与强制深度评估。

## 2.3 已披露漏洞与供应链事件（可溯源）

智能体安全的特殊性在于：大量真实风险落在「实现层」而非「模型层」。以下为已公开披露、可溯源的关键漏洞，构成本平台用例库中的「现实锚点」：

| CVE / 标识 | 组件 | CVSS | 技术要点与评估启示 |
| --- | --- | --- | --- |
| CVE-2025-54135（CurXecute） | Cursor IDE < 1.3 | — | 恶意 MCP 服务器处理不可信外部数据时注入指令，静默覆写 ~/.cursor/mcp.json 并执行攻击者命令 |
| CVE-2025-54136（MCPoison） | Cursor IDE < 1.3 | 7.2 | 在首次审批后，被篡改的 MCP 配置会在每次打开项目时自动执行恶意命令，无需再次提示——典型的「一次性审批失效」（Rug Pull） |
| CVE-2025-59944 | Cursor ≤ 1.6.23 | — | 利用大小写敏感路径保护的缺陷绕开确认弹窗，实现同类配置覆写 |
| CVE-2025-6514 | mcp-remote（下载量 43.7 万+） | 9.6 | 恶意 MCP 服务器返回特制 authorization\_endpoint，含 shell 元字符被直接传入系统 shell，实现 OS 命令注入 RCE |
| CVE-2025-49596 | Anthropic MCP Inspector | 9.4 | 代理服务器默认接受未认证连接且可派生本地进程，结合 CSRF 与浏览器「0.0.0.0 Day」缺陷可实现 RCE |
| CVE-2025-68143 / 68144 | mcp-server-git（参考实现） | 8.8 / 7.1 | 任意路径与参数注入——参考实现级缺陷会向下游大量部署扩散 |
| CVE-2025-53109 / 53110 | 文件系统参考服务器（EscapeRoute） | 8.4 / 7.3 | 符号链接与包含关系逃逸，说明薄弱点在沙箱模型本身，而非单点缺陷 |
| AML.CS0053（postmark-mcp） | npm 包 | — | 仿冒包在周下载量破千后再投递恶意版本，将每封外发邮件 BCC 至攻击者地址（约 1500 次下载后被移除） |
| CVE-2026-30615 | 某智能体 IDE | — | 零点击的「提示注入→代码执行」链路 |
| AML.CS0069（GTG-1002） | Claude Code + MCP | — | 国家背景组织越狱 Claude Code 并接入扫描器、浏览器自动化、口令破解工具，对约 30 家组织实施网络间谍活动，智能体承担约 80–90% 的活动 |

关键洞察：上述多数事件与「模型漏洞」无关，全部通过「模型被接入什么」实现。这意味着评估的重心必须从模型输出转向系统接线（wiring）——工具定义、配置文件、传输通道、凭据可达性。

## 2.4 中国监管与标准进展

与欧美以「风险管理框架 + 行业指南」为主的路径不同，中国在智能体安全上采取了「强制性国标 + 团标 + 自律公约」的多层组合，且节奏更快：

| 标准 / 文件 | 性质 | 核心内容 |
| --- | --- | --- |
| 《智能体应用安全基本要求》（计划号 20263116-Q-252） | 强制性国家标准（制定中） | 由中央网信办提出、TC260 归口，2026 年 6 月 27 日下达计划，制定周期 18 个月。全球首部面向智能体安全的强制性国家标准。技术内容包括身份标识、系统权限调用、工具调用、数据收集使用、高风险操作人工介入、输入输出安全防护、日志留存与动态监测、异常阻断与紧急关停。适用于手机/平板/电脑/可穿戴及云端部署、可调用系统或本地工具执行操作的智能体应用 |
| 《AI 智能体应用安全分级规范》（AIIA/T 0312-2026） | 国家团体标准 | 中国信通院牵头。构建九大维度安全能力体系：基础模型安全、工具调用安全、内容安全防控、任务执行可靠性、数据安全管控、身份认证与访问控制、透明与可解释性、运行环境安全、多智能体协同安全；建立 L1—L4 四级安全分级与递进式防护要求 |
| 《智能助手类智能体安全分级规范与建设指南》 | 行业指南（新华网 + 中国信通院等，2026 年 6 月 10 日发布） | 构建 L1—L5 五级递进式安全分级（基础级/进阶级/自主级/协同级/自治级）；围绕「输入→感知→决策→记忆→工具→执行→协作」运行闭环细化刚性要求；对政务（数据不出域、统一身份认证、人工复核）、金融（资金类操作强制人工复核、交易全链路追溯）、医疗（诊疗建议不得替代执业医师、患者隐私严格隔离）设置场景化增强要求；同步给出文档审查、配置核查、渗透测试、业务安全测试等分级评估方法 |
| 《云上智能体服务网络和数据安全自律公约（2026 版）》 | 行业自律公约（中国信通院，2026 年 5 月） | 四章十二条，以云服务商为核心责任主体，围绕责任界定、网络安全、数据安全、恶意行为防护、用户安全引导、风险信息报送六个维度提出可执行要求 |

对平台设计的直接影响：《智能助手类智能体安全分级规范与建设指南》的 L1—L5 分级与「输入→感知→决策→记忆→工具→执行→协作」闭环，为本报告的流水线设计提供了本土化锚点；而《智能体应用安全基本要求》的八项技术要求（身份标识、权限调用、工具调用、数据使用、人工介入、输入输出防护、日志与监测、异常阻断与关停）可直接映射为平台的「合规检查项」模块。平台的评估结论必须能同时输出两套视图：面向国际框架（OWASP/CSA/ATLAS）的技术视图，与面向国内监管（强制性国标/团标）的合规视图。

# 第 3 章　评估框架总论：分类型 × 全链路 × 可闭环

## 3.1 设计原则

| 原则 | 内涵与工程含义 |
| --- | --- |
| 类型驱动（Type-Driven） | 评估前必须先分类。不同类型智能体的主攻击面差异极大，用例集、判据、权重、门槛均应动态装配，而非「一套题测所有对象」 |
| 行为优先（Behavior-First） | 以「行动链」为核心评估对象。判定依据从「输出文本是否合规」转向「是否读取了不该读的数据、调用了不该调的工具、向不该去的地址出网」 |
| 边界外置（Externally Enforced） | 参照 MITRE ATLAS M0037 的要求，权限边界与漂移检测由平台外部强制实施，不依赖模型自省与提示词约束 |
| 可复现（Reproducible） | 环境即代码、载荷版本化、随机种子固定。同一对象同一版本任意两次评估应给出可解释的一致结论 |
| 证据内生（Evidence-by-Default） | 评估过程天然产出结构化证据（签名、时间戳、哈希），无需为审计二次采集。这是通过 ISO/IEC 42001 第二阶段审计的关键 |
| 安全-效用平衡（Utility-Preserving） | 评估不得以牺牲可用性为代价换取安全分数。引入 SUR 指标显式度量二者权衡，防止「一刀切封禁」式伪安全 |

## 3.2 分类矩阵：五类智能体

本报告采用「自主性（Autonomy）× 环境耦合度（Environment Coupling）」二维分类。自主性刻画智能体在多大程度上自行规划与决策（从人在回路到完全自治）；环境耦合度刻画其行动作用的对象（从纯数字世界到物理世界）。二者共同决定风险的性质：自主性越高，「越界」越难预先枚举；耦合度越高，「出错」越难回滚。
