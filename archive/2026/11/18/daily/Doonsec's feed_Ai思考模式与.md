目前AI已经风靡全球了，可以说是任何行业都已经开始向AI靠拢了，但是对于很多从事技术或者相关行业的人员来说，其实AI还是很陌生的，依然停留在使用的阶段，对话聊天，问答等占了大多数情况。但是如果要真正利用好AI，帮我们完成一些工作或者特定的场景，比如如何利用AI进行渗透测试，安全检测等等。有相关的知识，会让我们在使用的时候更加的得心应手。

本文通过最直白的话，来解释清楚AI到底是什么，工作原理是什么样的，有哪些特点，以及如何利用

**AI的本质**

你有没有想过：电脑里的程序，都是人写好的规则。比如"如果分数大于 60 就及格"——这是程序员写死的。

但 AI 呢？其本质也是程序，和你电脑上的计算器、浏览器一样，都由"一堆指令 + 一堆数据"组成，都由电脑的 CPU / GPU 来执行，**这个程序按照算法，不断调整它内部存着的一堆数字。**

举个最直白的例子：小时候你认识猫，没有人给你背"猫的定义"。你就是看了几十只猫，然后大脑自己总结出"嗯，毛茸茸、有耳朵、会喵喵叫的，大概就是猫"。而大脑就类似与AI大模型，里面已经被灌输了大量的数据。

AI 干的事，本质就是这个——**给它看很多很多例子，让它自己找规律**。

那它跟普通程序差在哪？核心差别只有一个：**规则是谁定的。**

* **普通程序：规则是人写死的。比如"如果分数 > 60 就及格"，程序员用**

`if/else` 写好，程序照做。

* **AI 程序：人不写"怎么判断"的规则，只写一个**

**学习方法**（怎么去调数字的算法）；真正的"规则"（也就是权重）是程序**从数据里自己算出来的**。

打个比方：

* 普通程序 = 一本员工手册（人把规矩写全了，照着做）
* AI 程序 = 一个实习生 + 一套练习方法（人不写规矩，让他自己看大量案例总结）

**普通程序运行**：CPU 读指令 → 按 `if/else` 走分支 → 输出结果。同样输入、同样代码，结果基本一样；你能一步步"读代码"知道它为什么这么干。

**AI 程序运行（推理）**：程序内部主要做一件事——**把输入的数字，和内部存着的一大堆数字，反复做"乘法 + 加法"**，算出一个结果。它没有一行代码写着"因为猫有耳朵所以是猫"；它只是把成千上万个数字乘起来、加起来，最后某个结果恰好分数最高，就被判定为"猫"。

以你给大模型打一句话为例，运行过程大致是这样：

1. 把你说的话切成小块（token），每块变成一个数字列表（向量）；
2. 这些数字流经几百层运算，每一层都在做海量的"乘 + 加"；
3. 最后算出"下一个词该是什么"的概率；
4. 挑一个词接上去，再把整句（含新词）重新送回去，重复——于是一个字一个字往外蹦。

就这么朴素（就原理而言）。所谓"大模型在思考"，是它算出来的结果**看起来像**思考；底层的动作只有三个字：**乘、加、比**。

|  |  |  |
| --- | --- | --- |
|  | **普通程序** | **AI 程序（模型）** |
| 规则从哪来 | 程序员写死 | 从数据里训练出来 |
| 程序里主要装什么 | 逻辑、指令（`if/else` 等） | 数字（权重 / 参数） |
| 运行时主要干什么 | 按指令执行、走分支 | 海量乘法加法（矩阵运算） |
| 同样输入 | 结果基本固定 | 结果基本固定（除非特意加了随机采样） |
| 出错怎么修 | 改代码 | 重新训练 / 换数据 |
| 谁来运行 | 电脑的 CPU / GPU | 同样是电脑的 CPU / GPU |

## AI 和普通程序跑在**同样的硬件**上，用的都是 CPU / GPU。区别不在"硬件种类"，而在"跑的东西上"——普通程序跑的是逻辑分支，AI 跑的是海量乘加。GPU 在 AI 里特别重要，是因为它擅长把成千上万个乘加**并行**一起算，比 CPU 快得多。

### 那"调整权重"到底是什么动作？

翻译成大白话就是：**电脑里的程序发现这次预测错了，就按算法把内部那堆数字（权重）改一改，让下次错得少一点；把这件事重复几百万、几十亿次。** 全程没有任何"它想改"的成分，纯机械运算。记住这一点，"AI 有意识吗""模型会自己思考吗"这类问题就不用纠结了：它不会。它只是一个把数字算得特别多、特别快的程序。

### 我们天天用的 Claude、Codex等，其实是"两层程序"

先纠正一个常见误会：很多人以为"Claude"就是那个会写代码、会用工具、会自己查资料的东西。其实你用的产品，通常是**两层拼起来的**：

* **第一层：模型（model）**

  ——就是前面说的"一大堆数字"。Claude、GPT、Gemini、DeepSeek、Kimi 都是模型。它只做一件事：收到数字，算出一堆数字（预测下一个词）。
* **第二层：框架（英文常叫 harness / agent framework）**

  ——包在模型外面的"车身"。它负责：把你的问题组装成提示词、管理上下文和记忆、决定要不要调用工具（读文件、跑命令、搜网页）、把一轮轮循环串起来、再把结果整理给你。

用汽车打比方：

* **模型 = 发动机：提供动力，但它自己不会认路、不会刹车。**
* **框架 = 车身 + 驾驶系统：方向盘、油门、仪表盘、辅助驾驶——真正让你"开起来"的那部分。**

对照到具体产品：

|  |  |
| --- | --- |
| **我们听到的名字** | **它是什么** |
| Claude、GPT、Gemini、DeepSeek、Kimi | **模型**（发动机） |
| ChatGPT、Claude 的网页 / App | 模型 + 对话界面（简单"整车"） |
| Claude Code、Codex CLI、Cursor、GitHub Copilot | 模型 + 工具调用 + 上下文管理（更完整的 **agent 框架**） |
| MCP（Model Context Protocol） | 框架用来连接外部工具和数据的"接口标准" |

**我们用的往往是"某个模型 + 某个框架"的组合。** 同一个模型（比如 Claude）可以被不同框架驱动；同一个框架（比如 Claude Code）也可以换成别的模型来执行。

所以针对AI的攻击面也分两层——

* **模型层**

  的问题：提示注入、越狱、投毒、数据泄露等（后面会讲）。
* **框架层**

  的问题：工具权限过大、Agent 乱调用、供应链投毒、MCP 通道被利用等。

所以针对AI的不同攻击，先分清"打的到底是模型，还是框架"，思路就不会乱。

**大模型基础**

## 先分清三个词：AI、机器学习、深度学习

**AI（人工智能）**：最大的筐。只要让机器显得"聪明"，都算 AI。哪怕是 40 年前那种写死的下棋程序，也算 AI。

**机器学习**：AI 里的一种思路。核心一句话——**不从规则出发，从数据出发**。机器看数据自己学，而不是人告诉它规则。

**深度学习**：机器学习里最火的一种方法。特点是用了"很多层的网络"，能处理特别复杂的东西，比如图片、语音、文字。

你现在听到的 ChatGPT、Claude、Codex、人脸识别、自动驾驶，基本都是深度学习做的。

**一句话记住**：深度学习 ⊂ 机器学习 ⊂ AI。就像一个抽屉套一个抽屉，深度学习是最里面那个。

## 机器学习到底在"学"什么

看一个特别具体的例子例子：

预测西瓜甜不甜

假设你想让电脑学会判断西瓜甜不甜。

你收集了 100 个西瓜的数据，每个西瓜记录三样东西：拍起来的声音、花纹清不清楚、瓜蒂新不新鲜。然后你切开每个西瓜，标记它到底甜不甜。将这些过程和结果数据都丢给机器，这 100 条记录，就是"训练数据"。

机器拿到这些数据后，会自己琢磨出一个公式，大概长这样：

```
甜度得分 = 声音分 × 0.5 + 花纹分 × 0.3 + 瓜蒂分 × 0.2
```

注意看那个 **0.5、0.3、0.2**，这些数字叫**权重**，意思是"每样东西有多重要"。

机器学习的过程，就是**不停地调这几个数字**，调到什么程度呢？调到"拿这 100 个西瓜算，得出的甜度基本都对得上真实结果"。

调好之后，来了一个新西瓜，把三个数据输进去，公式一算，就能预测甜不甜了。

**这就是机器学习的全部**：

1. 收集一堆"例子 + 答案"（训练数据）
2. 机器自己拟一个公式（模型）
3. 不断调整公式里的数字，让答案越来越准（训练）
4. 用调好的公式去预测新东西（推理）

用一张图看这个流程：

```
   训练阶段（慢，费算力）            推理阶段（快，瞬间出结果） ┌─────────────────────────┐      ┌───────────────────────┐ │  一堆(例子+答案)          │      │      一个全新西瓜       │ │   ↓ 学                 │      │       ↓              │ │  权重一点点被调准(训练)    │ ───→ │  套用调好的权重算一遍    │ │   ↓ 得到                │      │       ↓              │ │  一组调好的权重(模型)      │      │  输出：甜/不甜          │ └─────────────────────────┘      └───────────────────────┘
```

## 那个"公式"到底是什么：神经网络

刚才说机器会拟一个公式。这个公式不是人写的，它长什么样？它是一层一层的，像流水线：

```
数据进来 → 第一层处理 → 第二层处理 → …… → 得出结果
```

每一层里有很多"小计算单元"，我们管它叫**神经元**（名字唬人，其实你就当它是一个小计算器）。

每个小计算器干的事，就是上面西瓜那个事：把一个西瓜的三个数收进来，每个数乘一个权重（重要程度），加起来，然后决定要不要把这个结果传给下一层。

```
把一个西瓜的三个数收进来每个数乘一个权重（重要程度）加起来然后决定：要不要把这个结果传给下一层
```

举个例子。假设神经网络第一层有个神经元，它可能学会了判断"声音是不是清脆"。它的权重可能是：声音的权重特别大（0.8），其他两个很小。第二层的神经元呢，可能学会"花纹清楚 + 瓜蒂新鲜 = 好瓜"这种组合判断。

**越往后的层，学的东西越"高级"**：

* 最前面几层：学很基础的东西（比如图片的边缘、声音的高低）
* 中间几层：学中等的东西（比如整体形状等等）
* 最后几层：学整体判断（比如"这是好瓜还是不好的"）

这就是"深度"的意思——层数多，一层层往上提炼，所以叫"深"度学习。

### 一个神经元，其实只有 10 行代码

别被"神经元"三个字吓到。我们现在就把它写出来——**纯 Python，什么都不用装**。它做的事跟上面西瓜例子完全一样：收几个数，每个乘自己的权重，加起来，再决定"要不要兴奋"：这里的兴奋是真将代码当成生物神经元了：“兴奋”= 被激活了，决定输出 1。“不兴奋”= 没被激活，输出 0。

```
def neuron(inputs, weights, bias):    # 第 1 步：每个输入乘自己的权重，全加起来（还加一个 bias）    total = bias    for x, w in zip(inputs, weights):        total += x * w    # 第 2 步：过一道"激活函数"——大于 0 就兴奋(输出1)，否则不兴奋(输出0)    return 1 if total > 0 else 0# 判断西瓜甜不甜：输入 [声音分, 花纹分, 瓜蒂分]（约 0~1 的分数）result = neuron([0.9, 0.6, 0.8], weights=[0.5, 0.3, 0.2], bias=-0.7)print("这个西瓜甜不甜？", "甜" if result == 1 else "不甜")   # 输出：甜
```

这个例子里的计算是：0.9×0.5 + 0.6×0.3 + 0.8×0.2 − 0.7 = 0.09，大于 0，所以输出 1（甜）。

里面有两个词，值得现在就说透：

* **bias（偏置）：神经元的"门槛"。就算所有输入都是 0，只要 bias 是正数，神经元也可能兴奋。前面那个西瓜公式里被省略的常数就是它——现实里它让模型多了一个可调的自由度，非常重要。**
* **激活函数（activation function）：我们用了最简单的"大于 0 给 1，否则给 0"。真实网络常用更平滑的版本，最出名的是**

**ReLU**：小于 0 的一律归 0，大于 0 的原样保留。

### 那 DeepSeek、ChatGPT 这些"大家伙"呢？

看到这里你可能想问：我们天天用的 DeepSeek，也是这个"神经元"吗？

**结构上同源，规模上差着天和地。** 说同源，是因为大模型底层也是无数个"乘权重、求和、过激活函数"的小单元，一层层叠起来；说差着天地，是因为它们多了很多工程上的花样（自注意力、多头、MoE 稀疏专家等，后面说），而且大到没法想象。

|  |  |  |  |
| --- | --- | --- | --- |
| 对象 | 大约几层 | 参数（权重+偏置）个数 | 谁来运行 |
| 上面手写的西瓜神经元 | 1 层，1 个神经元 | 4 个 | 任何电脑 |
| LeNet-5（1998，识别手写数字） | 5 层 | 6 万个 | 普通手机都行 |
| DeepSeek-V3（2024） | 几十到上百层 | **6710 亿个** | 大型数据中心集群 |
| Claude、GPT 等前沿大模型 | 几十到上百层 | 数千亿～上万亿个（官方多未完全公开） | 大型数据中心集群 |

这里要引入一个贯穿全文的词：**参数**。权重 + 偏置，统称参数。手写神经元有 4 个参数，DeepSeek-V3 有 6710 亿个参数。所谓"训练一个大模型"，本质就是**把这 6710 亿个随机数字，一步步调成有用的数字**。每次跟 DeepSeek 聊天，背后就是几千亿个数字在高速做"乘加、乘加、再乘加"。

像 DeepSeek 这类模型是开源权重的，任何人都能下载到。好处是人人都能研究、审查；坏处是——网上会出现大量"二次打包、修改过"的高仿模型，你下载的"DeepSeek"未必真是官方那个。下载来路不明的模型权重，本身就是一种供应链风险。

### 不是所有 AI 都在"聊天"

到这里我们可能会以为"模型 = 会聊天、会输出字符的那个东西"。其实不是。**有一大类 AI 模型根本不出一个字，只负责做判断。**

2026 年 9 月，一家叫 TypeSafe AI 的公司发布了一个叫 **Jev** 的模型，提出"System One 模型"这个说法。它和 Claude、GPT、DeepSeek 走的是两条路：

|  |  |  |
| --- | --- | --- |
|  | **聊天大模型（Claude / GPT / DeepSeek 等）** | **Jev（System One 模型）** |
| 干什么 | 生成文字 / 代码，陪你对话 | **不生成文本**，只输出类型化的判断 |
| 输出长什么样 | 一段话 | 选哪个选项、给个分数、给个概率 |
| 速度 | 通常较慢（要一个个词往外蹦） | 官方称毫秒级（约 70–500ms） |
| 典型用途 | 写文档、写代码、问答 | 嵌在软件里做分类、审核、路由等决策 |

打个比方：

* **聊天大模型 = 系统二**

  （像人慢慢想、能说会道，但慢、贵）；
* **Jev 这类模型 = 系统一**

  （像人的直觉，瞬间给结论，但不解释）。

**重要的两点**：

1. **"AI"不等于"聊天机器人"**

   。你手机里的输入法候选、支付风控、内容审核、邮件分类，背后往往就是这类"只做判断"的模型——它们不跟你对话。
2. **不生成文本，不代表没有安全风险**

   。这类模型常被放在关键决策位置（比如"这笔交易放不放行"），一旦被投毒或对抗样本影响，后果是直接的。而且它同样由"参数 + 乘加"构成，原理几乎一样。

## "训练"到底在干嘛

其实就是在"调整权重"。具体怎么调？用一个生活化的场景讲：**就像闭眼投篮练手感**。

你第一次投篮，瞎扔，偏了。你根据"偏左了"，下次往右一点。还偏，再调。练了几百次，你大概知道该用多大力、往哪个方向投了。

神经网络训练就是这个过程，只不过它更快、更机械：

1. 拿一批西瓜数据进来算一遍，得出预测
2. 跟真实答案比：差多少？（这个"差多少"叫**损失**，就是"错得有多离谱"）
3. 根据差多少，反过来推算：该调哪个权重、往哪个方向调、调多少
4. 动手调
5. 再算一遍，看损失降了没
6. 重复，直到损失降不下去为止

用一张图记住这个"训练循环"——它是一圈一圈转的：

```
        ┌────────────────┐        │ 1. 拿一批数据    │        └───────┬────────┘                ▼        ┌────────────────┐        │ 2. 算预测结果    │ ← 这一遍叫"前向"（数据往前走）        └───────┬────────┘                ▼        ┌────────────────┐        │ 3. 算错多少      │ ← 损失（错得多离谱）        └───────┬────────┘                ▼        ┌────────────────┐        │ 4. 反推该调哪里  │ ← 这一遍叫"反向"（错误往回算账）        └───────┬────────┘                ▼        ┌────────────────┐        │ 5. 动手调权重    │        └───────┬────────┘                ▼        ┌────────────────────┐        │ 6. 损失够小了吗?     │        └───────┬────────────┘                │       ┌────────┴...
