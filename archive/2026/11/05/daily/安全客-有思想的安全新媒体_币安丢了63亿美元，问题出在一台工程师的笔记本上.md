# 币安丢了63亿美元，问题出在一台工程师的笔记本上

发布时间 : 2026-11-05 11:36:50

十月底这三天，币安的安全团队大概没合眼。

10月29日，链上先动的手。Arkham 首席执行官 Miguel Morel 在社交平台上说，数据显示币安相关钱包里有数十亿美元资产被身份不明的攻击者转走，具体原因还没确认。Glassnode 引用链上数据给出的数字更具体：约53亿美元资产流失，其中16.6亿美元的 USDT、17985枚以太坊（价值约14.5亿美元）、7.67亿美元的 USDC。

市场先跌为敬。比特币盘中最大跌幅3.7%，跌破79000美元；以太坊跌近4%，索拉纳跌3%，币安自己的BNB跌了7%。

10月30日，币安给出正式口径：正在全力推进问题解决，将承担全部损失；作为预防措施，充值和提现全部暂停；已联合执法机构、代币发行商和区块链情报公司在链上冻结约30亿美元，后续可能继续增加；用户存款没有受到影响，预计48小时内恢复提现。

外界估算总影响约63亿美元。如果最终坐实，这会超过2025年2月Bybit那次的15亿美元，成为加密货币行业有史以来最大的一起盗窃案。

真正让安全圈坐直身子的，是币安初步调查里的那句话：事件可能涉及一名开发运维工程师的笔记本电脑遭到入侵，攻击者由此访问了某个服务容器，并提交了未经授权的提现交易。目前没有发现钱包私钥泄露的证据。

私钥没丢，钱没了。

# 一、攻击者绕开了所有人盯着的地方

过去十年，交易所的安全叙事基本围绕一个词展开：私钥。

离线冷钱包、多重签名、硬件安全模块、密钥分片，行业把最多的钱和最多的注意力放在”怎么让私钥不落到别人手里”。这套逻辑没错，它确实挡下过很多次攻击。

但这次攻击者根本没往那个方向走。

一台运维工程师的笔记本，一个能访问服务容器的身份，一条看起来完全合法的提现请求。签名是真的，接口是对的，权限是有的。风控系统看到的，是一个有权限的人在做他有权限做的事。

这是当下最难防的一类攻击：不偷钥匙，直接冒充拿钥匙的人。

# 二、一台笔记本能装下多少生产权限

币安没有披露笔记本具体是怎么失陷的。但从这类事件的常见路径看，答案基本逃不出几种：钓鱼邮件里的恶意宏、浏览器保存的后台密码被拖走、SSH 私钥和云平台访问密钥被复制、Kubernetes 的 kubeconfig 落在桌面文件夹里、聊天工具里传过的临时口令。

开发者机器上通常同时躺着这些东西：VPN 或堡垒机凭据、SSH 私钥、云平台长期访问密钥、CI/CD 部署令牌、代码仓库的 personal token，还有一堆后台的管理员密码。为了方便调试，很多人还会把它们写进脚本、环境变量、注释，甚至工单描述里。

攻击者拿到其中任意一样，就不需要再去找漏洞了。

更麻烦的是这些凭据的性质。它们大多长期有效，绑定的是”人”而不是”设备”和”任务”。登录时的一次短信或动态口令，只能证明”此刻是你在登录”，证明不了”接下来这条请求是你发的”。会话令牌一旦被复制，后面的所有操作都合法。

有人会说，不是有 EDR 吗。现实是，不少公司的 EDR 覆盖率在服务器上接近百分之百，在开发机和办公终端上打了对折。安全团队盯着生产网，攻击者进的是办公网，而这两张网之间那条”可信通道”，恰恰是最宽的。

供应链也在给这条路添砖加瓦。10月中旬披露的 LiteLLM 事件里，攻击者利用一个误传到公共仓库的主密钥，往 PyPI 推了带窃密器和远控的版本，下载量约4.9万次；9月，npm 上的 OpenClaw 记忆插件和 PyPI 上的 MemoryOS 被打进一个叫 sckit 的 Go 窃密程序，导入即运行，专挑 npm、PyPI、GitHub、GitLab、AWS、Vault、SSH 的凭据文件。开发机中招，常常就是从这里开始的。

# 三、”没有私钥泄露”安慰不了任何人

对普通用户来说，这句话听起来还行。对做安全的人来说，这句话的含义正相反：防御方最贵的那层保护没被攻破，但攻击者从旁边绕过去了。

交易所的热钱包是一套自动化系统。提现请求进来，先过风控规则，再走审批流，然后由签名服务完成签名，最后广播上链。这条链路上任何一环被人用合法身份驱动，钱就会按流程走掉。

所以这次真正失守的不是密码学，是控制面：谁能发起请求、请求从哪台机器发出、这台机器当前是否可信、这个身份在什么条件下可以动钱。

行业习惯把控制面当成”内部设施”，默认它比业务系统安全。可控制面往往跑着最老的组件、用着最宽松的权限、享受着”内网免检”的待遇，还经常被排除在渗透测试范围之外。

63亿美元这个数字，本质上是一次资产定价：市场认为这套控制面的价值，远远超过过去十年投在它上面的钱。

# 四、如果明天轮到你，先查这六件事

第一，生产凭据的寿命。有几套云密钥、数据库口令、CI 令牌超过90天没轮换？能不能改成按需申请、短期有效、绑定设备？

第二，运维终端的覆盖率。开发机、跳板机、CI runner 在不在资产清单里？装没装 EDR？能不能被统一策略管理？这一项不做，后面的检查都是空的。

第三，出金链路的独立性。限额、地址白名单、双人复核、异常行为基线，是不是和业务审批共用同一套账号体系？如果攻击者拿到运维身份就能一路批到底，这几道闸门等于没有。

第四，服务容器的权限。容器里跑着的进程，有没有必要持有能直接发起提现的凭据？能不能把权限收到”只能读、只能算、不能动钱”？

第五，检测规则的方向。现在的告警大多在找”异常的人”，很少有人找”合法的身份做了不合法的事”。同一账号在凌晨三点从新设备发起大额提现、同一令牌在两个 IP 段并发使用，这类信号有没有人看？

第六，应急的预演。真出事那天，谁负责联系交易所和发行商做链上冻结，谁负责对外发声，谁负责判断要不要停掉充提？这次能在短时间内冻住30亿美元，靠的是平时就存在的协作通道，不是临时拉的群。

# 五、写在最后

币安这次大概率能扛过去。它有 SAFU 基金，有足够的现金，也愿意全额赔付。用户的账面数字最终会回来，市场的恐慌也会过去。

但行业该记住的不是63亿美元，而是那台笔记本。

过去我们总说，安全是一个木桶，最短的那块板决定水位。现在的情况是，木桶本身没漏，提桶的人把钥匙插在门上就走了。

真正该重新定价的，是那些”看起来不像生产环境”的生产环境：工程师的笔记本、跳板机的登录态、CI 流水线里的一个环境变量。它们不进等保测评的范围，不出现在架构图上，也没有人给它们定级。可它们连着金库。

下一次再有类似的事件，希望复盘报告的第一页写的不是”私钥未泄露”，而是”我们早就把这条路的权限收到最小了”。
