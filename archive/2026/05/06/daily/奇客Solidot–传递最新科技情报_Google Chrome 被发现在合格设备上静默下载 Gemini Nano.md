## Google Chrome 被发现在合格设备上静默下载 Gemini Nano

[![人工智能](https://icon.solidot.org/images/topics/topicAI.png?123)](/search?tid=151 "人工智能")
[![Chrome](https://icon.solidot.org/images/topics/topicchrome.png?123)](/search?tid=154 "Chrome")

[Edwards](/~Edwards) (42866)发表于 2026年05月06日 21时00分 星期三 [新浪微博分享](//service.weibo.com/share/share.php?url=//www.solidot.org/story?sid=84223&appkey=1370085986&title=Google%20Chrome%20%E8%A2%AB%E5%8F%91%E7%8E%B0%E5%9C%A8%E5%90%88%E6%A0%BC%E8%AE%BE%E5%A4%87%E4%B8%8A%E9%9D%99%E9%BB%98%E4%B8%8B%E8%BD%BD%20Gemini%20Nano "新浪微博分享")
![](https://icon.solidot.org/images/a7c7.png)

**来自乌鸦从高塔坠落**

Google Chrome 被发现在合格设备上静默下载了 4GB 大小的 Gemini Nano 模型，而且会在用户删除之后重新下载。Gemini Nano 就是 Google 受争议的 Prompt API 所针对的本地模型，运行该模型需要至少有 4GB 显存、16GB 内存和至少 22GB 可用空间（浏览器安装包所在分区）。Google Chrome 有 38 亿用户，是市场份额最高的浏览器，满足运行 Gemini Nano 要求的设备至少数以亿计，即使不考虑重复下载，为如此多的设备静默下载 4GB 数据也是难以想象的资源浪费。此外值得一提是 Chrome 安装包大小是 1GB 左右，悄悄下载的模型大小四倍于浏览器本身，超出了大多数用户对额外功能大小的预期。Gemini Nano 下载在被称为 OptGuideOnDeviceModel 的文件夹内，该名字代表 OptimizationGuide on-device model storage。
