我的判断先放在前面：CrowdStrike 公开的材料，使“攻击服务器上只有一个伪造的 ARTEX 标题”难以解释全部现象；但公开博客没有给出足以让外部读者排除整体复制、共享或失陷主机、事后植入和刻意诱饵的底层材料。报告同时出现 VPS 技术映射和九个 proxy IP，却没有公开二者在具体请求中的逐跳关系，也没有说明这些代理是公共、共享还是独享。尚未闭合的问题，是“谁发起或使用会话、谁控制服务器环境、谁使请求到达银行”这三个主体是否为同一方。

最早进入公众视野的，只是疑似攻击服务器页面上的 `ARTEX` 字样。CrowdStrike 随后公开了另一组材料：ARTEX 实例、开放目录、`CLAUDE.md` 指向的第二台服务器，以及会话、配置和 memory 文件。证据从一个容易复制的字符串，推进到了内部相互关联的工作环境。

内部一致性不是事件因果。公开博客仍没有展示一条可逐笔复核的链：哪个 ARTEX 任务在什么时间发出了什么请求，哪个代理转发了请求，银行处理了哪个账户或业务对象，返回了哪些敏感数据，这些数据又如何离开受害环境。CrowdStrike 已经给出调查判断；外部读者无法只凭博客重建这条链。

> **核验边界**：本文逐项核对了 CrowdStrike 报告标题、日期、正文段落、IOC 与 ATT&CK 表，以及韩国金融委员会相关通报。本文没有接触银行原始日志、疑似攻击者主机镜像、开放目录原件或厂商未公开的取证材料，也没有运行 ARTEX。下文中的“报告发现”“报告判断”均指 CrowdStrike 的公开表述，不是本文的本地取证结果。

## 事件端先定基线：泄露已经发生，原因仍要单独证明

韩国金融委员会确认金融机构发生个人信息泄露，并启动现场检查和行业安全排查。监管部门截至 10 月 6 日公开的边界包括：当时没有确认密码、OTP 等认证信息泄露，没有发现泄露信息已造成资金被盗，没有确认可直接用于金融交易的账户信息泄露，也没有确认数据流向中国。韩国金融委员会紧急检查材料 · 消费者警报、关于“流向中国”的澄清

“未确认”是特定时点的调查边界，不等于“确认没有”。这些通报可以确认事件端发生了个人信息泄露，却没有回答 ARTEX 是否造成了每一家机构的泄露。

CrowdStrike 引用的行业报道提到两类受影响入口：一家银行的贷款进度查询服务，以及另一家银行的员工移动工作支持系统。报告同时写明，受影响机构的准确数量尚未确认。报告引用的韩国行业报道

先把事件事实与原因归因分开，后面的证据才不会发生错位：监管材料回答“受害端发生了什么”，CrowdStrike 报告主要回答“攻击者侧出现了什么环境和活动痕迹”。两条证据流需要高区分度连接，才能落到同一笔行为。

### 起点：一个字符串只能生成调查候选

早期报道只确认疑似攻击服务器的 HTML 中出现 `ARTEX` 字符串，实际使用与否尚未确认。网页标题可以复制、伪造或主动部署，单一字符串只能把服务器列入调查集合，不能证明工具运行，更不能证明它取得了数据。韩联社早期报道

### 第一处隐藏前提：种子 IP 从哪里来

CrowdStrike 将 `38.244.50[.]120` 描述为与这批活动相关，并在 IOC 表中标记为攻击者控制的 IP。博客没有说明这个地址最初来自受害端日志、自有遥测、行业情报共享，还是对公网 ARTEX 特征的搜索。

入口不同，第一跳的强度也不同。受害日志中的源地址与事件距离较近；根据界面特征发现的公网实例则需要额外证据接回受害事件。这个缺口不推翻后续发现，但它是整条关联链依赖的第一个前提。

### 从页面标识进入操作环境

按 CrowdStrike 的公开描述，`38.244.50[.]120` 承载 ARTEX 实例，`18899` 端口的开放目录还暴露了 `.claude/CLAUDE.md`。文档包含中文渗透测试提示，并引用另一台位于香港的服务器。

ARTEX 实例与工作文件同时出现，比页面标题更接近真实操作环境。博客没有发布主机镜像、目录快照、文件哈希、进程日志或登录记录，外部读者仍无法独立排除测试环境、备份镜像、被入侵主机或整体复制的目录。

### 跨主机枢转让活动簇开始成形

CrowdStrike 沿 `CLAUDE.md` 中的香港 IP 继续调查，在第二台服务器的开放目录中发现 Claude Code 会话历史、ARTEX 配置和 Claude memory。报告据此还原出两台服务器的分工：香港节点是主要基础设施，`38.244.50[.]120` 承载 ARTEX 实例。

报告还写明，ARTEX 实例主要使用 DeepSeek v4.1-flash，其他 Claude Code 会话使用 GLM-5.3 和 Grok 4.6；DeepSeek 可能通过 `xcai[.]pro` 这个 API 代理或转售服务接入。会话中的目标机构和活动时间，与行业报道中的受影响机构和事件窗口重合；会话还包含多个代理 IP，以及寻找韩国数据销售渠道的查询。

## 先纠正四处容易读错的细节

**报告列出的代理不是三个，而是九个。**`103.248.148[.]84`、`203.160.133[.]172` 和 `209.209.85[.]38` 只是原列表最后三项。CrowdStrike 共列出九个地址，并统一写作 `proxy IP addresses`。报告没有在这九个地址中标出主次，也没有称任何一个为公共开放代理。

**香港节点不能直接写成“中转节点”。** 原文把未公开地址的香港节点称为主要攻击者控制基础设施，把 `38.244.50[.]120` 称为承载 ARTEX 的节点。香港地址没有出现在 IOC 表里，报告也没有公开两台主机之间的流量、登录或控制关系。用“中转”描述它，会多加一层原文没有给出的网络语义。

**VPS 是框架映射，不是公开的租户证据。**`Virtual Private Server` 只出现在报告末尾的 ATT&CK T1583.003 表格中。正文没有公布云厂商、租户账号、开通时间、购买记录、付款方式或管理面日志，也没有把每个具名 IP 逐一映射到某台已验证的 VPS。

**有网页截图，没有底层取证截图。** 原报告正文没有开放目录、ARTEX 界面、原始 Claude 会话、配置、memory、主机日志或双服务器流量图。页面公开的是调查者的文字摘要、IOC 表和 ATT&CK 表。本文配图是从 CrowdStrike 原始网页截取的文字或表格，用来核对“厂商公开说了什么”，不是开放目录原件。

这四处区别看起来细小，却决定了后面的推理能走多远。把九个地址写成三个，会误判基础设施形态；把 proxy 写成 public proxy，会提前假定共享属性；把香港节点称作中转，会把尚未公开的网络路径画成事实；把网页文字截图当作取证截图，则会把可复核性抬高一层。

## VPS 映射与代理列表并不冲突，但报告没有画出每一跳

一种可能的分层结构，是稳定主机承载工具或会话状态，代理改变对外地址；但报告只公开了双服务器描述、九个 proxy IP 和 ATT&CK 映射，没有公开它们在具体请求中的连接关系。这类分层在一般意义上并不反常，却不能据此认定本案已经验证了“VPS 或 ARTEX 节点连上代理、再由代理打到银行”这条路。没有同类活动基线，也不能反过来把多跳架构当成高水平攻击者的身份证明。

按报告文字，读者最多能推出这么一条到处是断点的链：操作者登录并控制香港那台主要基础设施（用的哪个账号、哪把密钥，没公开）；香港节点上的会话去驱动 `38.244.50[.]120` 上的 ARTEX 实例（两者之间的控制流和网络流，没公开）；实例连上报告列出的九个 proxy IP 之一（什么时候连的哪个，没公开）；最后由那个出口把请求送到韩国金融机构（哪个请求到了哪家银行，没公开）。

上面这几个节点都来自报告，中间那一串问号不是。要强验证，得让三段记录在时间和内容上对上：ARTEX 节点连上某个代理，代理随后向银行发出请求，两侧请求在方法、路径、参数、业务对象或返回内容上出现难以偶然重合的特征。光地址重合，区分度不够。

## 九个代理到底是不是公共代理？公开材料回答不了

CrowdStrike 的措辞是“会话显示使用了以下代理 IP”，不是“发现九个无需认证的公共代理”。两种说法差别很大。代理地址可能属于公共开放代理、商业代理池、按账号认证的共享出口、独享租赁节点、被控制的中继、企业 NAT 网关，或者一台临时配置了转发功能的主机。公开博客没有给出协议、端口、认证方式、供应商、账号、租期、连接记录或同一时段的其他用户。

公开 WHOIS、BGP 和地理定位只能说明地址块由谁登记、由哪个自治系统宣告，以及粗略的托管位置。它们不能回答某一时刻谁租用了地址、一个出口后面有多少客户，或者某个请求属于哪个账号。即使事后在免费代理列表中找到同一地址，也只能说明另一个时点有人观察到代理服务；IP 可能重新分配，代理也可能开关或更换认证模式。

我只针对原列表最后三个地址做了公开侧复核。APNIC 与 ARIN 的注册信息分别指向 Arisk Communications、CloudMedia，以及标注由 Light Cloud 客户使用的地址段。这些登记支持“托管或客户使用型网络”的判断，却没有给出代理产品、租户和认证账号。103.248.148[.]84 注册信息、203.160.133[.]172 注册信息、209.209.85[.]38 注册信息

截至 2026 年 10 月 8 日，这三个地址没有在 TheSpeedX、Proxifly 和 Monosans 的现行免费代理列表中精确命中；ProxyCheck 的当前结果也均为 `proxy=no`。103.248.148[.]84 · 203.160.133[.]172 · 209.209.85[.]38

这个负结果不能推翻 CrowdStrike 从会话材料得出的代理判断。私有认证代理、临时自建中继和事件后已经关闭的服务，本来就可能不进入公共代理目录。它能说明的是：“这三个地址恰好是公开代理”目前没有独立公开证据支持。

所以，问题“那个代理是不是只有一个人用”目前只能回答：**没有证据证明只有一个人使用，也没有证据证明九个都是公共代理。** 在银行日志里命中其中一个地址，只能把请求定位到一个出口。若 VPS 到代理的连接、代理侧账号记录和银行收到的具体请求能够对齐，关联强度最高；代理侧日志缺失时，高区分度的请求、对象或返回内容仍可提供支持，但只有出口 IP 相同远远不够。

## 为什么在同一台工作环境里问“乱七八糟”的问题

报告把两类内容放在同一叙述中：一类是 ARTEX 相关操作、代理和金融目标；另一类是寻找韩国数据销售渠道、生成安全研究员简历、研究 Telegram NFT 礼品市场，以及针对疑似中国支付平台的活动。把这些内容全部称作“攻击链证据”并不准确。

寻找数据销售渠道的问句支持“有人关心如何变现韩国泄露数据”，但不能证明提问者已经持有数据、加入了群组、挂牌出售或成交。生成简历只证明有人向模型输入过一组自述，并要求把 ARTEX 活动写成经历。Telegram NFT 礼品市场的研究会话，以及同一用户名涉及的疑似中国支付平台活动，只能扩展网络人格线索，不能直接证明它们与韩国金融机构泄露具有相同因果关系。

杂项会话确实让目录比一张孤立的“我攻击了韩国银行”文本更像长期工作区。它也可能只是同一台多用户服务器、共享账号或被入侵主机上的不同工作；整目录复制还可以一次搬走所有“人味”、错误、重试和无关话题。判断目录是否实时运行，不能数它有多少种话题，而要查因果残留：上一轮会话写出的路径是否被下一轮实际读取，工具输出能否接回进程和网络记录，同一 API 账号是否在对应时段产生调用和计费。

文本越杂，只能说明内容越丰富；运行依赖越闭合，才越接近真实工作区。

## “会话作者、服务器控制者、银行请求发送者”可能不是同一个主体

CrowdStrike 将这些痕迹归于同一 threat actor，但公开博客没有展开用于合并以下三个主体的底层映射：

* A 是发起或持续使用这些 Claude/ARTEX 会话的账号或操作者；
* B 是在文件生成、保存或暴露期间控制相关服务器环境的主体；
* C 是使请求到达韩国金融机构的主体。

把这三个角色代进四种情形，重合程度各不相同。实时攻击工作区里，A、B、C 可能高度重合；整体复制或备份，目录内容可以来自 A，但当前服务器上的 B 不一定是 A；共享或失陷主机，B 和 C 不一定相同，一台主机也可能对应多个 A 或 C；刻意诱饵或归因投毒，B 可以放进来自真实、盗取或虚构的 A 的材料。

多种文件彼此一致，首先连接的是同一个内容环境，不是某个已识别的 A。开放目录在采集时可访问，只能说明文件当时对外暴露；要识别 B，还需要账号、进程、登录或控制面记录。受害端记录才能把 C 接入。云账号、SSH 密钥、系统用户、代理认证、LLM API 账号和银行请求如果没有跨系统连续对应，A、B、C 不能直接合并成“同一个攻击者”。

A、B、C 都是操作角色；即使三者重合，也仍需单独证明其现实身份。

## 证据变深，不等于证据变得更独立

这组材料同时沿两条轴变化。

第一条是**内容深度**。网页字符串只说明一个名称可见；配置与内部文档开始接近操作环境；完整会话如果包含可验证的目标、工具调用和可信返回，会进一步接近具体行为。CrowdStrike 没有公开原始会话，外部读者无法判断这些层级分别出现了多少。

第二条是**来源独立性**。`CLAUDE.md`、配置、会话和 memory 即使内容不同，也可能来自同一目录、同一用户或同一次摘要流程。memory 可能是既往会话的派生摘要，简历中的活动成果也可能只是操作者重复输入的自述。内容深度明显增加，独立来源的数量却未必同步增加。多了三类文件，不等于多了三票相互独立的证据。

公开报告、行业报道和监管通报也不能简单算成三票。CrowdStrike 明确引用了行业报道，行业报道又可能来自机构披露或监管调查。三个公开页面可能共享上游事实来源。更强的独立交叉，应当来自受害端原始日志与攻击者侧原始材料之间的内容级对应。

### 时间重合必须拆成六个时刻

“发生在同一时间段”只是时间分析的起点。至少要区分六个时刻：目标首次写入会话、调用记录生成、请求实际离开攻击端、受害端收到请求、目录被采集保全、媒体首次公开。

文件修改时间也不是天然可信的时钟。复制、解压、同步和人工修改都可能改变元数据；不同主机还存在时区和时钟偏移。若目标的最早可信时间早于公开报道，并能与受害端请求对齐，它的证据权重会明显提高；即使早于新闻，仍需排除更早的行业共享或其他公开来源。

CrowdStrike 给出了 9 月下旬至 10 月上旬的活动窗口，却没有公开上述六个时刻的逐项对照。这个窗口与攻击期相容，也覆盖了部分信息公开后的时段。公开材料支持时间关联，尚不足以让外部读者独立验证因果方向。
