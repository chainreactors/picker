**BugFind 核心能力**

#### **01｜SOTA 级的长程自主任务链路能力**

BugFind 的任务链路面向仓库级长程审计而设计。在任务开始前Agent 会自主全面了解该项目仓库的语言、框架、入口与权限边界，并据此生成动态任务图，节点类型由基础十类组成：覆盖规划、基线排查、Swarm 蜂群调查、反证查漏、独立挑战、静态验证、动态验证、漏洞回归、归并与报告。该链路支持在后台静默托管，7\*24 小时持续运行，自主完成从测绘到报告的长程任务。

![image.png](https://mmbiz.qpic.cn/sz_mmbiz_png/U8z7Z11Ue0ftNFo5MFzk7TghicbTWQxiclVhTPcp3a9Ql00tiaXuPibhbK54NgoXfJKibOzaYIgGOE7ibe1rh0dyUvtXXwg4MMdjia61DdXqX2X5bY/640?wx_fmt=png&from=appmsg)

图十一：某仓库项目使用 AI 审计 Ultra 模式自主审计 11h 22m、产出111 个风险项

#### **02｜Ultra 级的无限制Swarm-Agent 集群能力**

BugFind 采用自研Agent Swarm 架构算法，由多个 SubAgent 按角色分工协同完成审计任务，角色与数量根据当前仓库的风险面动态确定，并非固定套用模板形式；各 Agent 共享同一套代码图谱与语义事实，并行推进调查、查漏与验证。为降低先看到扫描结果带来的锚定偏差，高危、严重与等级未知的候选以及静态规则来源的候选，会以去重后的复核组为单位各做一次隔离补充复核，复核者不接触候选来源、原始结论与对方意见。BugFind 同时设计 SAST-Blind 盲审通道，盲审 Agent 的工具列表不包含读取 SAST 结果的能力，服务端对其请求予以拒绝，下发的语义事实会去除 role、evidence 等标签并清空 sanitizer 列表。

![image.png](https://mmbiz.qpic.cn/mmbiz_png/U8z7Z11Ue0ffvhuAtJmfxrEoI2oErgaXicZzA7An7G1LyqLTYpricfv8RrA0bZffSaVTeanNvk1yD9xuC4ia7x0MZ99dicaoyEA2vq30auKtf2E/640?wx_fmt=png&from=appmsg)

图十二：BugFind - Agent 集群部分展示

值得注意的是，我们为每一位 SubAgent角色设计了其独特的电子工牌和身份标识 ID（该设计向 Kimi K 系列模型率先推出 Agent 集群 Work 模式 致敬），在为了方便 Ta 们能够互相寻找以主动交流的同时，我们也希望每一位子 Agent 都有其独特的灵魂，更具有特色：（让调用链自己开口，没有引用，先不算数。）（代码不会撒谎，小尾巴藏不住。）

#### **03｜全量代码仓库图谱级取证推理能力**

BugFind 以自研 Argus SAST 3.0 引擎作为底座，该引擎离线运行，不调用任何大模型，覆盖 13 个语言与扩展配置、19 个框架语义模型。同时 Semantic IR v3 引擎将函数、变量、调用、控制流与数据流纳入同一张可查询的图，Agent 在审计过程中对参数来源、传递路径与危险调用的判断均基于该图完成，而不是依赖对代码片段的直接阅读。由于图由确定性计算生成，相关结论可按当前快照回放，每条结论均落回文件、行号与符号，适用于几万至几十万行规模仓库。
