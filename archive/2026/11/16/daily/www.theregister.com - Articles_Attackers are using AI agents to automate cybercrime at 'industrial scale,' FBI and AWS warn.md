Attackers are using open source AI penetration testing framework ARTEX to automate their attacks on banks, governments, energy and healthcare providers, and other critical sectors around the globe, according to security alerts from the FBI and Amazon Threat Intelligence.

Between October 3 and November 5, Amazon’s MadPot honeypot threat sensors detected two ARTEX campaigns: one that allowed thieves to steal AI credentials at “industrial scale” to gain free access to models, and a second that generated deepfake videos to trick live selfie checks.

In the first one, miscreants used AI agents to steal API keys, and then feed these keys into the ARTEX framework’s model gateway to power more agents searching for more AI model access keys.

REG AD

“Agents validated identities through each provider’s token and identity services, enumerated storage, assessed permission scope, and went after managed AI model services, secrets and parameter stores, and application identities,” AWS Chief Information Security Officer CJ Moses [wrote in a blog post](https://aws.amazon.com/blogs/security/amazon-threat-intelligence-observes-threat-actors-running-cybercrime-campaigns-with-artex-ai-agents/) on Friday.

REG AD

Targets included LLM gateways and proxy platforms such as One API, New API, Veloera, Sub2API, and LiteLLM, and AI application builders Dify, FastGPT, Langflow, RAGFlow, Open WebUI, LobeChat, and Ollama.

This campaign also used cloud credentials to gain stolen access to the models.

In a second campaign, attackers used ARTEX to create real-time deepfake videos to trick identity verification (KYC) checks at two cryptocurrency exchanges, and forged ID photos to pass document checks.

“The agents reverse-engineered one vendor’s liveness protocol in detail, documenting the face-detection event stream it sends, how it tracks face position during the check, and the coordinate system it uses to tell the user where to move,” Moses wrote.

The agents did manage to complete the full movement sequence with the face positioned within 7 pixels of the target, but this feat was not enough, as the vendor’s server-side verdict rejected the deepfake in every attempt.

In a separate session, agents built a real-time deepfake video pipeline on a single consumer-grade GPU using an open-source face animation model. This video achieved 11.5 frames per second, which Moses said is “close to what a live video check expects.”
