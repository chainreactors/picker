## Overview

CORRECTED FINDINGS (2026-10-21): Cached-pointer chain DEAD at the addref (session.c:3213 Z\_TRY\_ADDREF keeps array alive - no free, no RCE, CVSS 0.0). The real bug is a serialize-state cross-request UAF (ASAN-confirmed at var.c:756, n+=1 on arrays/references, prefork-only, NOT code execution, CVSS 5.3 Medium). Full proof + receipts preserved; lab details unredacted.

PHP's `session.upload_progress` handler (`php_session_rfc1867_callback` in
ext/session/session.c) runs inside `php_hash_environment`, **BEFORE**
`zend_activate_modules` and therefore BEFORE `PHP_RINIT_FUNCTION(basic)`
zeroes `BG(serialize)` / `BG(unserialize)` (basic\_functions.c:393-395).

Both globals cache `{ level, data }` for the var layer. A memory\_limit bailout inside
the pre-RINIT `update()` decode/encode leaves the context allocated but
`level=1` with a dangling `data` pointer. **Next request on the same
process:** `php_var_serialize_init` / `php_var_unserialize_init` see
`level != 0` and **reuse the freed block as the live context** â UAF
read/write through:

* **Bug S - Cached-pointer path (CVE-2026-109618 class label, DEAD at addref, CVSS 0.0)**:
  `php_add_var_hash` does `data->n += 1` at freed+0x38; fake HashTable
  `pDestructor` fires from `zend_hash_destroy` â `zval_ptr_dtor`
  â forged object â `zend_call_function`.
* **Bug U - Serialize-state UAF (real bug, NOT the cached-pointer path; memory-safety only, CVSS 5.3)** - unserialize context (8208B
  `php_unserialize_data`): `tmp_var()` reads `last_dtor` (+16) /
  `used_slots` â `var_push_dtor` writes arbitrary zval;
  `var_access()` resolves `R:n` markers â arbitrary `zval*`
  injected â next update's `zend_hash_update` replacement â
  `zval_ptr_dtor(attacker_address)`.

`session.upload_progress.enabled=0` closes both (session.c:3239).

**Validated on Apache 2.4.68 prefork + mod\_php 8.2.34 (Debian 12), memory\_limit=8M:**

* **Bug S:** CONFIRMED - context reuse + forged `pDestructor`/`nNextFreeElement`
  reflected in `$_POST['t']`; arbitrary `zval_ptr_dtor` primitive working.
* **Bug U:** ARM/P1 confirmed (pre-RINIT decode OOM, orphaned `BG(unserialize)`,
  session file destroyed by `cancel_decode`); FIRE blocked by session globals
  corruption (`PS(save_path)` dangling pointer to request boundary string) preventing
  clean decode of attacker session data. Requires per-build heap grooming (glibc 2.39 vs 2.36)
  for reliable reclaim - see [Validation](#validation).
