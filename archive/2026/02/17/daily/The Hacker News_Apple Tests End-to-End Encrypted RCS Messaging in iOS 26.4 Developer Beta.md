# [Apple Tests End-to-End Encrypted RCS Messaging in iOS 26.4 Developer Beta](https://thehackernews.com/2026/02/apple-tests-end-to-end-encrypted-rcs.html)

**Ravie Lakshmanan**Feb 17, 2026Encryption / Mobile Security

[![](data:image/png;base64...)](https://blogger.googleusercontent.com/img/b/R29vZ2xl/AVvXsEiPp_YwVMP8UedNu9MRj7UCji7JQ8xfTP29sqz2wXhr5sFnGWNTCM_KOIPJnzD9rNqQjp5O08Oe2LNpns6GYVkQOyjYxQIadGQ4Z5cEclR1Nl40D1_Dr5p8A0sXa4-rFnmmoWkHiVGKCvQ7iXnXZ8O7cdHXLSwBUXvby_SkTuLGj7vqfMP148Wx_5qryIux/s1700-e365/iphone.jpg)

Apple on Monday released a new developer beta of iOS and iPadOS with support for end-to-end encryption (E2EE) in Rich Communications Services ([RCS](https://support.apple.com/en-us/104972)) messages.

The feature is currently available for testing in iOS and iPadOS 26.4 Beta, and is expected to be shipped to customers in a future update for iOS, iPadOS, macOS, and watchOS.

"End-to-end encryption is in beta and is not available for all devices or carriers," Apple [said](https://developer.apple.com/documentation/ios-ipados-release-notes/ios-ipados-26_4-release-notes) in its release notes. "Conversations labeled as encrypted are encrypted end-to-end, so messages can't be read while they're sent between devices."

The iPhone maker also pointed out that the availability of RCS encryption is limited to conversations between Apple devices, and not other platforms like Android.

The secure messaging test arrives nearly a year after the GSM Association (GSMA) formally [announced](https://thehackernews.com/2025/03/gsma-confirms-end-to-end-encryption-for.html) support for E2EE for safeguarding messages sent via the RCS protocol. E2EE for RCS‌ will require Apple to update to ‌RCS‌ Universal Profile 3.0, which is built atop the Messaging Layer Security ([MLS](https://thehackernews.com/2023/07/google-messages-getting-cross-platform.html)) protocol.

[![Cybersecurity](data:image/png;base64...)](https://thehackernews.uk/sse-customer-awards-d)

The latest beta also comes with a new feature that allows applications to opt in to the full safeguards of Memory Integrity Enforcement (MIE) for enhanced memory safety protection. Previously, applications were limited to Soft Mode, Apple said.

MIE was [unveiled](https://thehackernews.com/2025/09/apple-iphone-air-and-iphone-17-feature.html) by the company last September as a way to counter sophisticated mercenary spyware attacks targeting its platform by offering "always-on memory safety protection" across critical attack surfaces such as the kernel and over 70 userland processes without imposing any performance overhead.

According to a [report](https://www.macrumors.com/2026/02/16/ios-26-4-stolen-device-protection/) from MacRumors, iOS 26.4 is also expected to enable [Stolen Device Protection](https://support.apple.com/en-us/120340) by default for all iPhone users. The feature adds an extra layer of security by requiring Face ID or Touch ID biometric authentication when performing sensitive actions like accessing stored passwords and credit cards when the device is away from familiar locations, such as home or work.

Stolen Device Protection also adds a one-hour delay before making Apple Account password changes, on top of the Face ID or Touch ID authentication requirement to give users some time to mark their device as lost in the event it gets stolen.
