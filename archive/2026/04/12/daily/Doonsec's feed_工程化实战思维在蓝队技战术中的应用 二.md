# 第二章红蓝对抗中的蓝队技战术基础

## 2.1 红蓝对抗核心概念与流程

### 2.1.1  红蓝对抗的定义、分类与典型场景

红蓝对抗是一种以红队模拟真实攻击者对蓝队目标进行最大限度的网络攻击，一切围绕实战化模式进行的一种对抗式演练，其核心逻辑是通过红队与蓝队在网络空间中的动态博弈来检验蓝队构建的网络安全防御体系的有效性，最大程度发现是否存在中高风险以上的防御缺陷和安全漏洞，并组织相关业务部门或外部合作厂商进行安全漏洞修复和防御能力升级迭代。

在红蓝对抗的攻击过程中，蓝队一般情况下不会限制红队的攻击手段，完全模拟与真实攻击者一致的战术与技术，无需要按照固定流程，以达到突破网络安全防御或获取目标资产权限；在红蓝对抗的防御过程中，蓝队则在无预设红蓝对抗场景脚本的情况下开展实时安全防御，采取监测分析、威胁阻断、资产隔离、取证分析、追溯溯源等手段，实时获取网络中发生的攻击事件，通过网络对抗、暴露风险、整改优化、修复验证为循环，实现蓝队安全能力的提升和闭环。

根据对抗的核心维度，红蓝对抗可分为多种类型。按对抗范围划分，可分为单点对抗、局部对抗与全域对抗：单点对抗是红队聚焦于蓝队某一特定业务系统或设备，主要目的是通过红队攻击特定资产来检验蓝队特定业务系统的自身安全能力和对应性的安全防御能力；局部对抗是红队覆盖蓝队某一体系化、系统化的业务系统，主要目的是通过红队攻击体系化、系统化业务系统以检测蓝队构建的局部系统的安全性，以较为完整的暴露出局部、全域存在的防御缺陷和安全风险，便于蓝队进行整改和评估业务整体安全性；全域对抗则针对蓝队全部网络资产进行的全范围攻击，允许任意攻击手段，这里主要考验蓝队对全局攻击威胁的感知和防御能力、全局协同处置能力、防御资源调配能力等。按对抗周期划分，可分为短期攻击对抗与长期持续对抗：短期对抗通常是红队在十个工作日内完成攻击任务，允许红队自任务开始时发起高强度的密集攻击，主要要求是高危操作和具备破坏性的攻击程序在使用前必须进行风险评估，不能影响核心业务的正常运行；长期对抗的时间具体根据攻击任务的性质而定，通常是红队在十二个月内对蓝队全域网络资产模拟 高级可持续攻击  的攻击方式进行周期性、阶段性的攻击测试，鼓励红队通过网络测绘、零日漏洞、隐蔽隧道、内网横向、防御绕过、靶标获取的渐进式操作，来检验蓝队对隐蔽式攻击的发现与处置能力。

基于国家法律法规和组织自身网络安全要求，红蓝对抗的典型场景已普遍覆盖于众多行业及领域中。攻击场景一：在金融或银行行业中，红队常构造虚假身份，以社会工程的方式取得目标信任，发生精心编制好的钓鱼附件获取目标终端权限，植入后门代理利用目标终端充当跳板进行内网渗透，获取蓝队指定的靶标系统权限，以模拟达成窃取用户资金的目的，蓝队则需要在保障交易连续性的前提下，实时监测网络中存在的异常攻击流量，对发现的恶意扫描攻击行为进行及时封禁阻断，一旦发现红队在内网中进行横向渗透，应在第一时间联动业务部门进行攻击溯源和应急处置，以确保用户账户的资金安全。攻击场景二：在能源行业中，由于电力调度系统、油气管道监控系统等工控设备的特殊性，红队会要求在测试环境中模拟利用工控协议漏洞注入攻击载荷，来获取工控设备的控制权限，实现系统控制或数据篡改的目的，蓝队需要部署工控安全防护系统对工控环境中存在的异常攻击行为进行实时监控，以快速识别和阻断异常攻击载荷，追踪攻击源头，评估或隔离受攻击的工控设备，从而保障能源系统的正常运转；攻击场景三：在政务行业中，红队多以渗透政务云上系统来获取初始目标权限，然后进行内网信息收集，通过零日漏洞攻击政务云底层系统，从而控制政务云底层系统，以到达控制政务云上所有目标权限，蓝队则需要通过部署的网络安全防御系统进行实时监测，由于政务系统的特殊性，一旦发生网络安全风险，蓝队应及时联动多厂商、多部门进行应急处置和影响评估，保障政务服务不被轻易中断。

### 2.1.2 红蓝对抗全生命周期关键环节

红蓝对抗的全生命周期包含三个阶段，分别是准备阶段、实施阶段、复盘阶段，其中红蓝对抗的每个任务阶段目标都非常明确，主要目的是保障红蓝对抗过程中的公平性、专业性、安全性和有效性。

准备阶段是对抗的基础。目标是明确规则、构建环境、配置资源，避免在红蓝对抗过程中对真实业务造成实际影响。首先，需要开展需求与目标确认，蓝队、红队与组织管理层共同明确红蓝对抗的目标（如检验蓝队构建的安全防御能力、评估业务系统安全性、检验蓝队的应急响应和处置能力）、范围边界（如只允许红队攻击与生产环境代码一致的测试系统）与评判标准（如红队在规定时间内需要完成蓝队设定的验收目标）、注意事项（如禁止红队攻击生产业务系统、禁止增删改查生产服务器文件、攻击过程全部需要录屏等），确保红队和蓝队对红蓝对抗项目事项达成共识。其次，需要进行环境构建与系统部署，搭建一套与真实环境一致的测试系统（如重新部署一套核心业务系统）；如果需要在真实环境中开展红蓝对抗，则需要严格划分生产隔离区域，避免红队在攻击过程中波及正常业务；同时准备脱敏后的测试数据（如模拟的客户信息、业务数据），确保红蓝对抗场景的真实性。最后，完成资源配置与规则制定，为蓝队协调和部署新的安全防御系统（如态势感知系统、终端安全防护系统、SOC 日志分析系统等）与组建人员团队，并明确红蓝对抗的时间节点（如攻击启动时间、每日对抗时长）、沟通机制（如红队发起高风险攻击前需要提前报备、构建蓝队请求暂停红蓝对抗的标准流程），确保红蓝对抗项目有序开展。

实施阶段是对抗的核心。目标是模拟真实攻防、实时记录过程、保障安全可控。在红队层面，红队基于预设靶标与攻击思路，开展扫描探测、漏洞利用、权限提升、横向渗透、获取权限的全流程攻击：通过端口扫描、资产探测获取目标网络资产；挖掘和利用安全漏洞获取目标初始系统权限；通过提权漏洞提升系统账户权限；通过信息收集在内网中进行横向渗透；通过安全漏洞、弱口令等获取更多系统或设备权限；最终实现获取目标系统数据或目标控制系统权限，在这个过程中需要实时记录攻击步骤、工具与结果。在蓝队层面，蓝队通过监测、分析、响应、阻断、溯源等闭环流程开展安全防御工作：通过安全防御系统实时监测内外部网络中存在的攻击行为（如异常登录、端口扫描、漏洞利用、后门下载、后门执行等）；对发现的安全事件，蓝队在第一时间组织人员进行应急响应，研判安全事件的攻击类型、攻击路径与影响范围；基于分析结果采取相应的处置措施（如阻断攻击 IP 地址、隔离被入侵的主机、清除后门程序、开展漏洞修复等）；通过日志关联、流量回溯等手段开展攻击溯源，定位红队的攻击入口、分析红队攻击痕迹与手法，还原红队真实攻击路径、评估红队技战术水平等，以综合评估红队攻击效果。同时，蓝队需要结合在红队攻击过程中安全防御系统采取的实时防御动作，对红队采用的攻击手法进行全程监控，整体把控红蓝对抗进度，如果红队的技战术出现超出预设范围和注意事项和影响重要业务的稳定性等意外情况，需要立即暂停红队攻击任务，提醒红队必须按照红蓝对抗的演练规则进行开展，对因违规而造成的业务崩溃等影响，需要协商红蓝双方找出根本原因以解决对抗过程中发现的问题，保障红蓝对抗稳定运行。

复盘阶段是对抗的延伸。目标是总结经验、定位问题、优化策略，将红蓝对抗成果转化为组织组织内部的长期安全能力。首先，汇总分析红蓝对抗过程中所有的攻击与防御数据，以多维度输出和展示红蓝对抗项目数据（如红队的攻击漏洞、攻击手法、攻击策略、攻击路径等；蓝队发现的攻击事件类型、攻击数量、攻击阻断率、威胁检测率、安全事件应急响应等），基于制定的红蓝对抗规则和验收标准来评估红队的攻击成果。其次，组织红蓝双方进行安全问题和防御缺陷的定位与分析，针对蓝队暴露的防御缺陷或盲点问题（如未检测到红队攻击手法、网络和主机防御盲点、网络和主机隔离策略、老旧系统漏洞修复不及时、零日漏洞等）进行根因分析：如果为防御缺陷，需要分析是否因威胁检测规则未匹配到该攻击特征；如果是响应滞后，需要判断是否因安全管控制度和流程不足，还是人员能力或协作效率低；如果是防御盲点，需要检查是因安全防御系统未部署到对应的网络资产，还是因网络资产是账外资产，且没有纳入统一管理；如果是溯源失效，需要检查是否因日志没有留存或留存不完整，还是因红队采用虚假身份、使用境外攻击资源和伪造攻击 IP 地址等。最后，联合制定后续的改进方案与修复计划，结合红队发现的安全漏洞问题，提出具有针对性、可行性的修复措施（如优化防护规则以完善防御系统的检测能力、部署或下发自动化响应策略缩短非工作时间段的响应时间、提升安全防御系统的检测成功率、覆盖率减少防御盲点、统一收集系统日志进行实时威胁分析等），明确责任部门和负责人、安全问题的整改时间与验收标准；同时，将红蓝对抗过程中形成的经验（如红队的攻击技战术和防御策略绕过、蓝队的有效防御策略和应急处置方法）整理为知识库，提供给蓝队成员进行日常学习培训和能力提升。

### 2.1.3 红蓝对抗中攻防双方的目标与战术差异

红蓝对抗中，红队与蓝队所关注的目标与技战术选择存在本质差异，这种差异源于红蓝双方的角色定位与结果导向，这种在对抗过程中的策略选择与博弈往往是相反的。

从目标来看，红队的目标选择首先要具备基本的攻击条件，即可攻击性与可突破性，主要聚焦于以最小代价和最高隐蔽性突破蓝队构建的安全防御体系。前期技战术目标是绕过或突破蓝队构建的外部防御线（如下一代防火墙系统、入侵检测与防御系统等），获取蓝队重要系统、组织成员终端等初始访问权限；中期目标是通过采取加密隧道等方式在内网进行信息收集，提前获取合法登录凭证，在隐蔽的情况下进行横向渗透扩大权限控制范围，避免被蓝队的安全防御系统发现和处置，持续潜伏和收集高价值目标信息；最终达成蓝队预设的攻击任务与验收标准（如获取靶标权限、窃取底层数据、篡改业务配置、发现的漏洞数等），且尽可能不被蓝队发现，或在被发现前完成攻击任务撤离。红队的目标不局限于是否突破，更注重突破过程的隐蔽性与攻击路径的不可预测性。例如：通过无文件落地攻击在系统中注入内存马，避免在系统或终端中留下可被发现和检测的后门程序，或借助操作系统中自带工具或功能性软件实施网络攻击，以降低被蓝队识别的可能性。

相比之下，蓝队的目标选择一般情况下是具备基本的防御条件，即可防御性与保护性，核心目的是以最小业务影响和最高阻断效率来保护网络资产安全。前期目标是通过部署的安全防御系统快速发现红队的网络攻击行为，第一时间进行阻断和处置，以避免攻击范围扩大；中期目标是精准定位红队攻击路径与受影响网络资产，采取针对性的处置措施（如隔离受感染主机、修复漏洞等）阻断攻击链路，以防止后续的网络攻击影响；最终目标是完成红队攻击过程的整个溯源，明确红队的攻击手段、工具与意图，并将防御经验转化为可复用的防护规则、处置流程和系统，以强化后续安全防御体系。蓝队的目标不仅是要阻断当前网络攻击，更是着眼于提升系统的安全性和提升长期防御的能力。例如：在金融行业的红蓝对抗中，蓝队需要优先保障交易系统的正常运行，在阻断红队网络攻击前，必须进行严格研判和评估影响，避免因误封禁导致客户交易失败；在对抗结束后，需要将红队的新型攻击手法纳入威胁情报平台，更新防护规则以应对未来可能的同类型攻击。

从战术差异来看，红队与蓝队的策略选择围绕攻与守的核心逻辑形成鲜明对比，具体体现在行动策略、资源分配、战术选择三个维度。

在行动策略上，红队以威胁情报收集为基础获取攻击目标的网络资产，以攻击试探为手段探查攻击目标的防御水平，以隐匿渗透为核心保障攻击任务的正常运行的攻击模式。红队在开展作战时要采用灵活多变的技战术策略，攻击过程中要对目标防御状态进行实时探测，为红队的攻击路径动态调整提供决策依据。例如：当红队在尝试通过钓鱼邮件获取目标组织成员终端权限时，如果感知到蓝队的邮件系统存在安全网关，且有严格的反病毒、反垃圾邮件防护策略，立即转向社交软件进行网络钓鱼，通过伪造客户身份，向目标工作人员发送带有后门病毒的附件，诱使目标工作人员打开附件执行后门病毒，以间接获取目标内网权限；在内网横向渗透时，如果某条攻击路径被蓝队发现和阻断，要迅速切换到其他攻击路径或漏洞（如高风险安全漏洞、弱口令），避免红队的攻击路径被彻底阻断。红队的行动策略几乎接近于网络游击战，不盲目追求正面突破蓝队防御，而是伺机寻找安全防御体系中存在的薄弱环节与防护盲区，以最小攻击成本拿下攻击目标。

蓝队则按照流程式和闭环式的防御模式，以全面防御为要求构建和完善安全防御系统、以精准监测为核心获取全部网络资产真实网络攻击事件。蓝队需要构建覆盖边界、内网、终端、业务系统等全链路监测能力，确保无监测盲区；在发现红队的攻击行为后，通过蓝队预设好的安全策略开展网络防御，这里每个环节都需要衔接紧密，以完成攻击流程闭环。例如：蓝队监测到某系统或终端存在异常对外请求，需要立即组织人员登录组织成员终端进行调查取证，调取该终端的登录日志、网络流量日志，判断是否为红队入侵事件；如果确认是入侵，需要同步隔离该终端、检查内网其他设备是否存在同类异常、追溯攻击流量来源，形成完整的防御闭环。蓝队的行动逻辑更接近阵地战，需要守住每一个关键防御节点，通过体系化防御抵消红队的灵活攻击。

在资源分配上，红队应根据自有的作战系统规模和系统建设，切勿聚焦于单点资源突破，将主要资源投入到漏洞探测与攻击路径优化。红队的资源（如攻击系统、威胁情报、人力）多向高价值目标的薄弱点倾斜。例如：针对组织内部的核心数据库，红队会投入更多精力收集该数据库的版本信息、历史漏洞、运维配置习惯，开发或定制专用攻击系统；在攻击过程中，如果发现网站系统账户具有高权限且密码可通过暴力破解获取，集中精爆破多个低权限账户。红队的资源分配原则是以最小资源消耗实现最大攻击效果，避免资源浪费在无价值的试探上。

蓝队则侧重于全域防御和资源均衡，需要将资源分配到监测、分析、响应、溯源全环节，同时，兼顾不同业务场景的防御需求。蓝队需要为边界防御设备（如下一代防火墙）配置足够的防护规则，更新系统资源漏洞、补丁，确保蓝队系统没有那么快被入侵；将所有系统和设备日志接入分析平台，投入算力资源保障海量日志能够实时处理与关联分析。此外，还需要为不同业务区域（如银行交易区、办公域）分配对应的防御资源，为银行交易区配置更高优先级的监测与响应资源，为办公区终端部署安全防护资源等。

在技术选择上，红队偏好隐蔽性、攻击性强的技术，以规避检测、快速突破为目标。红队常采用零日漏洞或使用已公开不久的漏洞实施网络攻击，因为蓝队的防护规则覆盖一般情况下比较滞后；通过采用自定义加密通信协议，在目标内网中部署加密代理隧道，来实现隐藏网络攻击，避免被蓝队的入侵检测与防御系统检测和识别；使用动态混淆技术处理恶意程序，防止被蓝队的杀毒软件或终端威胁检测与响应系统检测和查杀。例如：红队通过某未公开的浏览器安全漏洞，当目标组织成员访问特定网站时，无需要下载后门病毒即可在终端中植入内存后门，全程无明显的攻击痕迹。

蓝队则侧重兼容性和可靠性高的技术，以精准识别和稳定防御为目的。蓝队的技术选择需要兼顾检测准确性与业务兼容性。例如：入侵检测规则的更新需要经过充分测试，避免误判正常业务流量；自动化响应工具的配置需要预留人工干预接口，防止因系统或人员误操作导致业务中断。蓝队常用多源威胁情报融合技术（整合互联网公开威胁情报、行业威胁情报、组织内部历史攻击数据）提升检测能力，通过用户行为画像和分析技术（建立正常用户与系统的行为模型，识别偏离基线的异常行为）发现红队的隐蔽攻击；在响应阶段，采用隔离与恢复（如虚拟机快照恢复、网络分段隔离），在阻断攻击的同时最小化业务影响。例如：蓝队通过建立组织成员正常登录行为基线（如登录时间、登录 IP 地址、常用设备、设备指纹），当红队使用异常 IP 地址 在非工作时间登录高权限账户时，可快速识别并触发账户冻结与告警，帮助蓝队快速检测和处置。

## 2.2  蓝队核心职责与技战术体系

### 2.2.1 蓝队在网络安全防御中的核心职责

蓝队的核心职责主要围绕保护组织网络资产安全展开，目前已经形成监测、分析、响应、溯源的全链条防御闭环，每个环节既独立承担关键任务，又与其他环节紧密联动，共同构成蓝队的防御核心能力。

监测职责是蓝队防御的第一道防线。核心任务是实时感知网络与资产的异常状态，及时发现潜在攻击痕迹。监测范围需要覆盖组织的全网络架构：在边界层，监测进出网络的流量是否存在异常（如大量异常 IP 地址  访问、可疑端口扫描、异常协议通信）；在内网层，监测设备间的横向通信是否合规（如未授权设备接入、跨部门网络访问、异常数据传输）；在终端层，监测终端的运行状态（如异常进程启动、未知软件安装、敏感文件访问）；在业务层，监测业务系统的操作行为（如异常账户登录、高频数据查询、关键配置修改）。监测手段需要结合防御系统与人工巡检：通过入侵检测与防御系统、终端威胁检测与响应系统、日志分析系统等系统实现自动化监测与分析，实时抓取异常攻击行为请求并触发告警；同时安排专人定期巡检安全防御系统、关键设备与系统的运行日志、访问日志、安全配置等，完善安全防御系统的监测盲区（如未覆盖的老旧系统、重要业务逻辑的异常行为、零日漏洞检测规则等），以满足不漏报、少误报的监测目标，既需要确保红队的攻击行为（尤其是隐蔽攻击）能被及时捕捉，又需要通过优化告警规则（如设置告警优先级、关联多维度数据过滤误报），避免大量无效告警占用蓝队资源。

分析职责是蓝队防御的决策中枢。核心任务是对监测到的异常告警数据进行深度研判，明确攻击事件是否为误报还是真实事件、攻击类型与影响范围。在分析工作开始前，首先要对告警数据进行初步筛选。例如：当终端出现敏感文件访问告警事件，蓝队需要结合该终端用户的岗位职责、访问时间、文件用途，判断是终端用户的正常工作行为还是红队的窃取行为；其次对真实事件进行攻击类型识别，这里可以基于威胁情报和知识库，匹配异常访问行为对应的攻击手法（如红队在用户终端中注入内存马，在内网横向渗透时进行端口扫描和漏洞扫描）；最后评估红队攻击的影响范围，通过日志关联分析，判断红队是否已获取其他系统或设备权限、是否已获取核心网络资产（如数据库、业务系统）权限。蓝队在分析过程中需要注重多源数据的交叉验证。例如：某台终端存在少量端口扫描行为时，是无法确认是否为红队攻击；如果同时发现该终端与内网其他终端存在异常通信，且该终端出现异常文件和进程，即可大概率判定为真实红队攻击，表明该终端已经彻底沦陷。蓝队在分析过程中务必在最短时间内明确攻击事件，为后续的处置动作提供决策依据，避免因响应和分析滞后导致网络攻击扩大化。
