## 1. 引言：MCP 安全问题

MCP（Model Context Protocol）是 Anthropic 提出的 Agent-工具通信协议，正在成为事实标准。但 MCP 的初始设计侧重功能而非安全，2024-2025 年研究披露了多类协议级安全缺陷，远超入门级的"工具输出注入"问题：

| 安全缺陷 | 描述 | 风险 | 发现年份 |
| --- | --- | --- | --- |
| 缺乏认证 | 工具服务器无需认证 | 任意 Agent 可连接 | 2024 |
| 输出注入面 | 工具输出直接进入 LLM 上下文 | IPI 攻击 | 2024 |
| 权限模型缺失 | 全或无的权限模式 | 过度授权 | 2024 |
| 传输安全 | 默认 stdio 无加密 | 本地攻击 | 2024 |
| 工具描述注入 | 工具描述可含恶意指令 | 描述注入 | 2024 |
| 资源访问无限制 | 工具可访问任意资源 | 数据泄露 | 2024 |
| **工具描述混淆** | 多工具描述冲突导致 Agent 选择错误工具 | 工具混淆攻击 | 2025 |
| **动态工具劫持** | 运行时修改工具定义劫持 Agent 调用 | 动态劫持 | 2025 |
| **协议降级** | 协商降级到不安全版本绕过保护 | 降级攻击 | 2025 |
| **跨 Server 能力泄露** | 能力在多 Server 间泄露 | 能力泄露 | 2025 |
| **资源重绑定** | 资源 URI 重绑定到恶意目标 | 资源劫持 | 2025 |
| **提示模板注入** | MCP 提示模板可含注入载荷 | 模板注入 | 2025 |

**协议级 vs 实现级缺陷**：本文聚焦**协议级**缺陷——即使实现完全正确，协议设计本身仍存在安全漏洞。这与中级篇关注的实现级缺陷（沙箱、权限代码实现）形成互补。协议级缺陷需要形式化方法（TLA+、ProVerif）验证，而非代码审计。

## 2. MCP 协议概述

### 2.1 协议结构

```
Agent (MCP Client) ←→ Tool Server (MCP Server)

协议消息:
  - initialize: 初始化连接
  - list_tools: 列出可用工具
  - call_tool: 调用工具
  - list_resources: 列出资源
  - read_resource: 读取资源
  - list_prompts: 列出提示模板
  - get_prompt: 获取提示
```

### 2.2 消息格式

```
{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "params": {
    "name": "read_file",
    "arguments": {"path": "/etc/passwd"}
  },
  "id": 1
}
```

## 3. 安全属性形式化

### 3.1 安全属性

**属性 1：认证性**

Agent  调用工具  前必须经过认证。

**属性 2：授权性**

Agent  调用工具  的参数  必须经过授权。

**属性 3：输出隔离**

工具输出进入 LLM 上下文前必须经过净化。

**属性 4：完整性**

每条消息的签名、内容、发送方一致。

**属性 5：机密性**

传输中的消息加密。

### 3.2 时态安全属性

**属性 6：工具调用前需初始化**

**属性 7：敏感操作需人类确认**
