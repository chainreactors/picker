Acronis威胁研究部门的研究人员上周表示，一名攻击者利用人工智能代理获取了台北市七个区的紧急调度记录。

调查人员还发现台北消防部门的一个平台泄露了 2018 年的患者数据，包括心电图读数和救护车视频录像，而无需登录。

研究人员高度确信攻击者是居住在台湾花莲市的一名个人。他利用恶意软件攻击了至少11个国家的数百个组织，包括紧急服务机构、银行、大学和军事系统。这些恶意软件已在台湾、墨西哥和泰国的约10个组织中收集了数据或入侵了系统。

证据来自攻击者自己的服务器，该服务器最初看起来像是一个配置错误的开发系统。但事实证明，它是攻击者的实际攻击平台，其中包含超过9万个文件，包括特工的对话记录、他的命令历史记录、黑客工具、凭证以及受害者数据。

由于这些智能体之间无法通信，攻击者只能手动将一个智能体的输出粘贴到另一个智能体中。商业人工智能模型大多拒绝协助他进行攻击。因此，攻击智能体几乎完全运行在“被抹除”的模型上，这意味着这些人工智能模型在本地运行，但其安全训练已被移除。

### 特工们取得了什么成果

研究人员的技术分析表明，台湾遭受的攻击远比其他任何国家都更为严重。已确认的最严重损害涉及紧急服务数据。

这些调度记录来自台湾消防和救护紧急服务热线119所在的城市系统。工作人员通过系统API提取了这些记录，其中包括事件发生时间、响应类型、案件状态和街道位置。这些是案件记录，并非实时救护车跟踪记录。

研究人员的总结指出，急救服务和大学的系统漏洞导致医疗和个人数据被盗。然而，他们对台北患者平台的详细描述仅指出，相关记录已被泄露。

特工们还追捕了与台湾紧急服务部门有关的另外五个目标：

| 目标 | 特工们做了什么 | 结果 |
| --- | --- | --- |
| 消防调度技术供应商 | 使用默认 root 凭据登录到其数据库管理面板。通过已知 CVE 漏洞发起的 Web Shell 攻击尝试失败。 | 可访问 18 个或更多数据库表 |
| 应急管理信息系统 | 在网站前端 JavaScript 中发现一个硬编码的 AES-256 密钥，该密钥暴露了会话 cookie 的内容，包括管理员身份信息。 | 尚未确认妥协方案 |
| 国家灾害应对中心 | 扫描工具报告了一个严重的 Apache 远程代码执行漏洞。 | 这个缺陷并不存在。 |
| 国家消防局单点登录门户 | 尝试猜测登录名（暴力破解） | 未确认访问权限 |
| 五个城市的消防部门系统 | 扫描它们以识别它们运行的软件 | 尚未确认妥协方案 |

报告没有说明受影响的组织或台湾当局是否被告知此事，也没有说明泄露的数据是否仍然可以获取。

在紧急服务部门之外，这些特工利用SQL注入技术从一家台湾贷款公司的账户表中窃取数据。在泰国，他们以同样的方式从三所大学收集数据，此前他们已在45所院校中选定了489个潜在目标。

在墨西哥，他们利用政府统计数据、邮政编码列表和电信管理局数据，收集了约 206,800 条包含姓名和地址的家庭电话记录。

另有约15个组织遭到攻击，但未确认是否被入侵。在至少其他八个国家，攻击目标仅被扫描或列入攻击计划，但截至研究人员发现时，这些攻击尚未发生。

研究人员对此次攻击行动进行了12天的观察。一段记录显示，攻击者在7月25日仍在进行攻击活动。

### 人工智能是如何被使用的，以及它在哪些方面失败了

这套名为BOSSAI的系统包含12个AI代理，其中9个正在运行。部分代理负责构建和维护攻击者的服务器和工具，而其他代理则负责扫描目标并执行攻击。

大部分构建工作由商业云模型完成，其中 Grok 是主要构建者。当攻击者直接要求他们发起攻击时，Grok 和 MiniMax M3 拒绝了，并要求提供书面授权证明。研究人员表示，目前尚不清楚伪造的授权书是否会改变这一结果。

Grok 破例修复了一个损坏的概念验证脚本，攻击者随后将其交给了一个攻击代理。攻击者还将编码代理 Claude Code 和 Codex 重定向到一个已被彻底摧毁的模型，尽管它们主要从事基础设施方面的工作。另一个编码代理 Cursor 在运行这样一个模型时攻击了台湾的一个紧急服务网站。

被销毁的模型是 DeepSeek、GLM 和 Qwen 的版本。

这些代理也犯了错误。其中一个扫描工具虚构了一些CVE漏洞，其超过一半的高危和严重漏洞检测结果都是误报或错误分类。主要的攻击代理还报告了一些实际上并未发生的结果。

### 谁运营了它

Acronis 的归因依据是攻击者在隐藏身份时犯下的错误，以及公开可用的信息。他将同一身份信息用于其合法业务和攻击服务器，包括 GitHub 个人资料、徽标、SSH 密钥名称和电子邮件地址。

在他的一次 Grok 对话中，通过 SSH 会话显示了他的家庭 IP 地址。

他这么做的原因尚不明确。一些针对政府、紧急机构和军事目标的攻击看起来像是国家支持的黑客组织所为，而另一些则像是普通的网络犯罪。研究人员认为他可能是为了赚钱，但目前尚不清楚他是否受雇于任何人。

### 是什么阻止了agents？

研究人员表示，agents 发现的大部分数据原本就保护不力：一个自 2018 年以来一直开放的医疗数据端口、面向公众的 API 上的调度记录、一家存在 16 个 SQL 注入点的贷款机构，以及运行未打补丁的 Oracle 数据库的大学。

这些代理在强制登录、需要有效会话才能付费以及端点经过严格过滤的情况下都失败了。人工智能虽然能够以极低的成本一次性找到并访问多个目标，但却无法突破那些有效的防御措施。
