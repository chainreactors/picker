上上周，由于我连着一周重度用WorkBuddy处理各种文件。结果没过多久，明显感觉到我的C盘空间掉得飞快

一开始我并没怀疑WorkBuddy，以为就是电脑系统垃圾、写代码时装下的各种依赖包造成的C盘爆满。寻思着抽空清理一下就好，没放在心上

谁知道没几天，C 盘直接飘红

这让我想起之前一次很糟心的经历：当时准备剪视频，剪得都差不多了，结果PR 直接弹出 C 盘空间不足然后闪退，那一刻真的差点想砸键盘。

接连两次的踩坑，我才静下心仔细排查...原来元凶，就是我天天依赖的 WorkBuddy！

下载软件的时候，不少人都有这个意识：安装特意避开 C 盘，手动把 WorkBuddy 装到 D 盘，觉得这下就高枕无忧了

但其实这也是绝大多数人的误区 ——安装路径 ≠ 数据存储路径。你挪走的仅仅是软件本体，模型缓存、项目文件，默认依旧放在 C 盘用户目录里。

所以这次深挖，我发现了一个很少有人留意、比普通缓存更吃空间的底层机制：modify\_backup 修改备份

它这个设计初衷其实挺好理解：当你让 AI 修改、删除文件的时候，会先留存一份完整的原文件副本。万一改错、删错，随时可以撤回还原。关键点在于，它存的是完整副本，不是差异备份。哪怕你只改动视频或者文档里很小一部分内容，备份文件大小几乎和原文件一模一样。反复调整一次，就新增一份备份；改得越频繁，文件堆得越快。

但有个很讽刺的细节：如果你让它帮你清理磁盘，这个清理操作本身，同样会触发备份逻辑，先吃掉一部分空间

这个内置机制我们没办法修改。既然它一定会生成备份副本，那我们唯一能做的，就是不让这些备份、缓存文件继续往 C 盘写入

所以我吸取教训，给大家准备了两套方案，可以按自己WorkBuddy版本选择：

✅ 方案一：新版软件，直接在设置里迁移

1. 托盘右键彻底退出 WorkBuddy，只关窗口不算；
2. 打开软件，点左下角头像，进入设置；
3. 找到【工作空间存储路径】，更换到 D 盘提前建好的文件夹；
4. 确认保存，软件会自动迁移全部数据，后续新项目、备份缓存都会存在 D 盘。

✅ 方案二：老版本，设置里没有路径修改选项，用软链接无损搬家

1. 托盘退出 WorkBuddy，任务管理器确认没有残留进程；
2. 文件管理器打开【查看】，勾选隐藏项目，找到 C 盘用户目录下的 `.workbuddy`、`.workbuddy-key-fallback`、`WorkBuddy` 文件夹；
3. 剪切整套文件夹，移动到 D 盘新建目录，比如 `D:\WorkBuddy_Data`；
4. 以管理员身份打开 CMD，依次执行 mklink 连接命令，做好映射；
5. 全部完成后打开软件，检查历史会话、项目文件能否正常打开。

一个冷门坑顺带提醒：迁移的时候，偶尔会遇到名为 nul 的特殊文件，这是 Windows 保留名称，资源管理器正常删不掉，卡住的话用安全软件的文件粉碎功能处理，再继续迁移。

其实写到这里也挺感慨：现在 AI 生产力工具越来越好用，很多人打开就直接用，很少关心它后台悄悄在生成什么、文件存在哪里。有的人只会被动等着 C 盘爆红、软件闪退；有的人愿意沉下心去摸清它底层的规则，学会约束它。其实能不能看懂工具背后的逻辑，慢慢就拉开了差距

ok，讲了这么多。如果你也经常用 WorkBuddy，C 盘总是莫名其妙变红的话，可以对照看看是不是这个原因
