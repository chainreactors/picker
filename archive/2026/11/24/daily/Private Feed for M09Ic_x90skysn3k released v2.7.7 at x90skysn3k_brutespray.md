## What's New in v2.7.7

> **v2.7.7 finishes the connection-failure skipping work ([#366](https://github.com/x90skysn3k/brutespray/issues/366))**: the failure limit is now enforced *before* dialing, so `-max-conn-fails n` means at most n real connection errors between checks before the skip trips, no matter how many threads you use. This release also stops the post-skip retry storm and demotes accepts-any-password false positives.

### Fixed: Circuit Breaker Overshoot Under Concurrency (`#366`)

* **Root cause** — the breaker counter was checked *after* each dial completed. With `-max-conn-fails 10` and `-t 30`, every in-flight worker was already past the gate, so a dead host logged 30+ connection errors before anyone tripped. On top of that, every queued credential skipped after the trip still printed a `CONN ERR` row even though it never touched the network — hosts showed 130–230 rows in the TUI
* **Fix** — each attempt now reserves one slot in a per-host failure budget (recorded failures + in-flight attempts < threshold) *before* touching the network, and the reservation completes atomically with its outcome: the failure is counted and the breaker trips before any waiting worker can claim the freed slot. A host can therefore never log more than the configured limit in connection errors before the skip trips, regardless of thread count (a valid login clears the counter, as before)
