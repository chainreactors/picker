Paulos Yibelo, the researcher who in early October [claimed](https://www.theregister.com/offbeat/2026/10/06/security-researcher-claims-they-found-kvm-guest-host-escape-flaw/5301267) to have found a guest-host escape flaw in Linux KVM, the hypervisor used by most hyperscale clouds, has [named](https://pwn.ai/blog/pwnescape) the flaw PwnEscape and warned it might represent a new way to attack Linux – on top of being a 9.3-rated critical nasty in its own right.

Yibelo’s work is now [CVE-2026-99999](https://nvd.nist.gov/vuln/detail/cve-2026-99999). It is a scary bug because it makes a guest-host escape possible with a few malformed IPv4 packets.

Such attacks are a nightmare security scenario because the whole point of virtualization is carving up hardware into isolated “guest” virtual machines that share a “host” server’s resources – without ever being able to see what other guests or the host are doing. Public clouds rely on that isolation remaining impervious. So do private clouds, because if guest/host isolation is violated, an attacker could conceivably access all the VMs on a host or pool of virtualized hardware. Attacks on a host could give an evildoer access to thousands of VMs, plus containers because many developers now run those constructs in a micro-VM to keep them isolated.

REG AD

PwnEscape makes it possible for guests to access the host, by sending a guest malformed IPv4 packets.

REG AD

As explained in a [message](https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/commit/?id=0fab003ef4698e0628060a45a48f14b43ba2a40a) from Red Hatter Michael S. Tsirkin in the Linux kernel stable tree, ‘If a packet with bad checksum metadata gets into the ipv4 stack, skb\_checksum\_help can corrupt the network header and cause a bunch of mischief.”

Analysis from threat-finding firm SOC Prime [details](https://socprime.com/blog/cve-2026-99999-analysis/) the mischief.

“Linux allows network packets to carry metadata indicating where a checksum operation should begin and where its result should be written. This optimization is legitimate and widely used for checksum offloading, but the security problem arises when less-trusted guest-controlled metadata can influence a write after the packet header has already passed earlier validation stages.”
