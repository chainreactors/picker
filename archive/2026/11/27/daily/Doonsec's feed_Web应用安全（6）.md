## 一、引言

Web 应用安全并不止于“发现一个漏洞编号”，而是理解缺陷如何串联成完整攻击链：从对外暴露面出发，经信息收集、输入处理缺陷、凭证与配置泄露，逐步获得会话、文件读取与主机 shell，最终完成本地提权。真实攻防中，单点漏洞往往只是入口；真正造成业务灾难的，是多处弱控制叠加后的权限跃迁。

VulnHub 的 DC 系列正是为此设计的教学靶机——系统刻意埋入多种弱点，目标是在合法隔离环境中把整条路径走通。本文选取第九台 **DC-9**，按渗透测试常见阶段复盘：主机可达性与服务发现、搜索框 SQL 注入、管理区目录遍历、Port Knocking 打开 SSH、Hydra 撞库、本地提权，并对照 Burp Suite 自动扫描与 Fuzzing 的能力边界。文中 IP（如 `192.168.198.140`）仅为实验示例，请替换为你本机靶场地址。

靶机以 OVA 形式发布，可导入 VMware Workstation Player 等虚拟化软件；系统通过 DHCP 获取地址，初始 root 口令未知。下文给出的正是**不依赖已知 root 口令**的一条完整接管路径。实验前请确保靶机与攻击机位于隔离虚拟网络，避免误扫生产环境。

从方法论上看，DC-9 适合用来练习“证据导向”的分析习惯：每一步都尽量留下命令输出与截图，把“猜测”变成“可验证假设”。例如先证明注入存在，再决定是否上 sqlmap；先读到 knockd 序列，再解释为何 22 端口从 filtered 变为 open。这种节奏在授权渗透报告中同样重要——客户需要的是可复现的证据链，而不是口号式结论。

## 二、信息收集

靶机启动并确认 IP 后，先做最基础的连通性与端口探测。这一步看似平凡，却决定后续所有工具的目标地址是否正确，也能避免在错误网段浪费时间。若处于多网卡或 NAT 复杂拓扑，建议同时用 `ip a` / `arp -a` 交叉确认，防止把网关或宿主机地址当成靶机。

```
ping192.168.198.140 -c4
nmap -n192.168.198.140 -sV
```

典型结果类似：

| 端口 | 状态 | 服务与版本线索 |
| --- | --- | --- |
| 22/tcp | **filtered** | ssh |
| 80/tcp | **open** | http，Apache httpd 2.4.38（Debian） |

在 Nmap 语境中，`filtered` 通常表示探测未收到正常的 TCP 握手响应，而是收到 ICMP 不可达类错误，或流量被中间设备静默丢弃。结论很明确：**此刻无法直接连接 SSH**，但并不等于 SSH 守护进程未安装——它可能被防火墙规则、Port Knocking 或其他访问控制暂时隐藏。HTTP 则已开放，当前攻击面首先落在 Web 应用。

浏览器打开站点后，可见若干菜单项与搜索功能。建议先做功能熟悉，而不是立刻扔 Payload：

* **Display All Records**：直接展示用户库中全部记录，不接收用户输入，从注入角度看价值有限，但能帮你了解数据模型与字段含义。
* **Search**：按姓名搜索的对话框——这是第一个会把用户输入送到服务端处理的入口，也是 SQL 注入、跨站脚本等输入类缺陷的高发点。

先用正常关键字（例如 `Mary`）确认业务正常返回，再进入恶意输入测试。良好的渗透节奏是“先建立基线，再观察异常”，否则很难判断某次响应差异到底来自注入成功，还是页面本身的错误处理。也建议顺手查看页面源码、响应头中的 `Server`、`X-Powered-By` 与 Cookie 标志位，这些信息虽不直接等于漏洞，却能缩小技术栈判断范围。
