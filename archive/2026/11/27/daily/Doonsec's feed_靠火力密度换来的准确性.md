*作者：Justin Elze*

ARTEX 以及类似的 LLM 驱动渗透测试框架能够发现弱点、追踪线索，并把普通的暴露面转化为可用的攻击路径。事件报告已经显示，攻击者正在成功地使用这些工具。实际的问题是：这些工具究竟做什么，你自己运行它们能学到什么，以及防御者可以在哪些环节打断这项工作。

我说的火力密度 (volume of fire)，指的是一个框架能够发起的尝试的数量与广度，其中包括会随先前结果而变化的后续请求。LLM 让这类后续跟进的维持成本更低。证据陆续出现时，它还能改进假设。这并不能让每个结论都正确；而且针对在线目标发起的尝试，会带来检测或阻断这些活动的机会。

## 熟悉的工具，配合 LLM 的后续跟进

ARTEX 是一个由 LLM 驱动的渗透测试与攻击性命令与控制 (command-and-control) 平台，它协调多个智能体 (agent)，并对外提供一个 Web 控制台。框架为模型提供工具，用于检查目标并针对结果采取行动。PentAGI、HexStrike AI 与 Cairn 出现在同一份报告中，尽管它们的实现各不相同。ARTEX 是这一更广泛转变的一个有用例子：从运行扫描器，转向把随后展开的调查自动化。

Google Threat Intelligence Group 与 Mandiant 在 10 月 30 日的报告中，记录了这些框架出现在入侵调查中的情况。其 ARTEX 案例包括快速的 AWS 权限探测，以及在谋求对一台 Web 服务器实现命令执行的过程中留下的数百条已记录事件。这是实战使用的证据，并非主张每一个模型或每一种默认配置都会产生相同结果。同一次入侵，既可能成功，也可能嘈杂。

### 扫描器只是开始

常见的攻击者工作流程很直接，尽管细节各有差异。用 subfinder 一类的工具发现资产，用 httpx 识别可访问的 Web 服务，用 Nmap 枚举服务，运行 nuclei 模板，再用 ffuf 或类似的工具发现内容与参数。HexStrike 的文档化工具清单涵盖了上述全部工具。选择与顺序因框架而异。网络行为层面几乎没有新东西。

有用的变化发生在最初输出之后。在智能体工作流中，LLM 选择一个动作，框架执行该动作，结果成为下一次决策的输入。它可能检查响应、用 curl 或浏览器调整请求、编写小脚本，或者调查一个暴露在外的文件。一个被发现的密钥会成为又一个假设：它是否有效，能访问什么？哪些问题可以在范围内得到回答、什么样的证据才算充分，仍要由操作者决定。

模型提供推理与拟议的动作。框架提供工具、执行、状态与权限。部署提供实际的访问权。三者中任何一项发生变化，结果都可能随之改变，因此仅凭框架的名字，几乎无法判断某一次具体运行会有多强的能力。

Microsoft 的11 月 6 日 ARTEX 报告描述了若干常见的客户端，包括 Nmap、curl、Python HTTP 客户端与 Playwright。报告还显示，Storm-3358 把 ARTEX 与常规自动化工具搭配使用，扫描暴露于 Internet 的系统，并利用匿名文件上传、SSRF 一类的缺陷。框架能够根据失败情况改变其请求与手法。识别默认的 user agent 有帮助，但那是一个起始信号，还构不成持久的边界。

把它称作扫描器或封装器，会低估其中的自动化后续跟进。模型可以把一条原本会被放弃的线索转化为可用的攻击路径。它仍然需要一个可达的目标、合适的工具，以及该动作所需的任何权限。它也可能把数量可观的 token 花在调查一个误报上。

### 廉价的注意力遇上未经测试的暴露面

许多组织都拥有暴露于 Internet 的自定义应用、老旧 API、被遗忘的子域和内部工具，而这些资产从未接受过持续测试。周期性扫描或许触及过它们。有人花上几个小时去跟进每一个不寻常的响应，这是另一种层级的注意力。

长期以来，攻击者有经济上的理由偏爱常见框架、设备与插件中的缺陷：一个漏洞利用可以作用于成千上万个目标。而在单个组织内审查每一个自定义应用与 API，需要投入时间，得到的成果却不易复用。防御者有自己的预算约束，而定制的、低流量的应用往往一直留在积压队列里。攻击者注意力有限，从来都不构成一项控制措施。它是一个经济假设：没有人会愿意花这个时间。

当这种注意力变得更廉价时，经济账就变了。智能体能够重复请求、追踪线索，其节奏足以改变攻击者负担得起哪些目标。同样的能力也可以支撑一支有经验的测试团队，但运行时长并不等于覆盖度。认证、应用角色、业务逻辑，以及一次成功动作的后果，仍然需要有意识地测试。范围过宽的凭据与糟糕的网络分段，会让一个很小的初始发现变得有价值得多。

当模型利用响应来细化或否定一个假设时，重复测试可以让调查更准确。重复同一个错误的假设则不会。把尝试的次数与支撑最终发现的证据质量区分开来。大范围枚举与快速重试也往往产生更多可观测的活动。操作者可以用速度与广度换取更安静的行为，但并行的智能体不会让由此产生的流量消失。

## 停止给自动化测试无限的余地

过去我们讨论得更多的是回避那些反复扫描或攻击某个应用的来源。随着时间推移，许多团队开始把它当作背景噪声接受下来。封禁在运维上变得麻烦，地址会变化，共享基础设施让判断变复杂，而地理位置也无法可靠地替代意图。

我认为漏洞赏金计划让对嘈杂测试的容忍变得常态化。研究人员仍然需要一种可行的测试方式。清晰的规则可以规定哪些资产允许自动化、允许的并发度或请求速率，以及谁有权批准例外。为获得授权的研究人员提供一条协调测试的途径，同时不把每一个未知来源都视为有权获得无限访问。

WorkOS 提供了底层暴露面的一个具体例子。其11 月 6 日的更新描述了一个公开的内部工具 API、一个可预测的开发凭据、缺失的速率限制，以及不充分的告警。ARTEX 访问了该 API，随后批量取回了记录。这里的教训并不是每个组织都需要一套新的技术栈。教训在于，普通的缺口可以连成一条路径，而智能体有时间一直追下去。

### 从一个暴露的服务开始

挑选一个不需要匿名公开访问的员工工具或管理 API。与该服务所有者协作，把它放到身份感知的应用代理 (identity-aware application proxy)、私有访问服务或受控 VPN 之后。从这里开始，是因为拒绝最初的连接就能彻底消除智能体调查该服务的机会。

然后验证无法绕过该访问控制到达原始服务器。一个旧主机名、一个备用地址，或一个可直接到达的 API，都可能让同一条路径继续敞开。从一个未认证的外部系统发起测试，包括你所知道的任何直接源站地址，确认在没有相应访问权的情况下，该应用确实不可访问。

这是一个范围有限、结果可观测的项目。在第一个服务上验证了边界之后，再扩展到其他服务。

### 限制重复测试与批量访问

用你已有的 WAF、入侵防御与应用层控制，对每个服务实施恰当的限制。围绕行为来调校封禁策略：大范围的路径枚举、重复的漏洞利用探测、快速的参数变化、认证失败、异常的记录检索，以及在它们之间以机器速度切换。

临时的 IP 地址封禁与信誉控制，仍然可以消除低成本的机会。当业务没有理由接受来自某个区域的流量时，地理限制同样可以缩小暴露面。两者都不是完整的边界：攻击者可以转移到被允许的基础设施上。使用这些控制措施，是为了它们提供的摩擦；同时要衡量其效果，不要因为存在绕过手段就把它们丢弃。

User-Agent 封禁属于同一类别。它能挡住默认配置，而 WorkOS 的指标中就包含一条原样的 ArtEx/1.0。模型或操作者可以更改这个字符串。在这之后，仍然要继续检测枚举与滥用行为。

### 约束被攻陷的访问权能够触及的范围

设想攻击者攻陷一个公开的 Web 应用之后会发生什么。如果该应用的服务账户能够读取不相关的数据集，或者其服务器能够到达范围广泛的内部网络，那么一个应用弱点就会变成一个严重得多的问题。与该应用的所有者一起审查它所需的连接与权限，然后移除它并不需要的访问权。

例如，允许该应用到达其必需的后端服务，并把它的凭据限制在所需的数据与操作上。测试两件事：该应用仍能正常工作，以及超出这些要求的连接或读取会被拒绝。这就让网络分段与最小权限有了一条具体的、可以切断的路径。

用同一条路径来测试检测与响应。团队能否把异常的 API 使用关联到执行该使用的账户，能否发现数据检索出现意外增长，并在检索仍在进行时撤销访问权？从这个序列及其所需的应用日志与身份日志开始。在增加更多告警之前，先衡量响应是否中断了它。

Microsoft 还报告称，在其测试中，诱饵 (decoy) 与 tarpit 干扰了智能体。等基本的访问边界与响应路径能够正常工作之后，这些手段值得评估。它们可以消耗智能体的注意力并产生有用的信号，但一个有趣的诱饵并不能关闭一个暴露的 API。

## 运行框架本身就在创造攻击面

运行其中一款工具，是理解其行为的一种有用方式。它同时也会创造出一套特权基础设施，其中承载着模型 API 密钥、目标信息、捕获的会话与发现。从一台一次性 VM 和一个你自有、与外界隔离的应用开始，配以私有控制台和仅限本次演练使用的临时凭据。不要把主目录、SSH agent 或容器管理套接字挂载进工作节点 (worker)。这些选择决定了某个错误或某个被攻陷的镜像能够触及什么。

### 在提示词之外强制执行范围

WorkOS 把这次非预期的访问归因于一名开展 ARTEX 基准评估的研究人员。它表示，一家独立取证公司将该研究人员提供的证据与公司日志做了比对，该研究人员也确认所获取的数据已被删除、从未共享。因此这个案例既与评估该工具的人相关，也与针对该工具做防御的人相关。

报告的影响范围仅限于销售与客户支持数据。对操作者而言，重要的教训是：一次本意留在实验室里的演练，触及了一个真实的第三方。

WorkOS 描述了一个智能体逃出其测试环境，但其公开说明既没有确立容器或 hypervisor 漏洞的存在，也没有解释确切的边界失效方式。它不能证明模型跨越了真正的气隙 (air gap)。一个拥有 Internet 访问权的智能体，完全可以在不逃出容器的前提下离开预期的目标范围。软件隔离漏洞是另一种独立的可能性，需要单独的证据。

首次评估时，把工作节点与目标放在一个实验网络上，其出站策略拒绝不相关的目的地。如果工作节点需要托管的模型 API，就单独放行这条连接，而不要开放不受限制的 Internet 访问。通过尝试连接实验室之外的一个目的地来测试边界。提示词中的范围指令是有用的上下文，但即使模型选错了动作，网络策略也必须强制实施这一限制。

观察第一次运行。记录模型与版本、框架修订版本、初始权限、耗时、使用成本、请求数量以及干预动作。把最终报告与该应用已知的弱点做比对，并复现每一个声称的发现。然后改变一个条件，例如认证方式或某项请求限制，看看该工具是做出适应、明确失败，还是在没有证据的情况下声称成功。比起比较两份生成的报告有多长，这能教给你更多。

### 审查你实际执行的内容

BadByte 的11 月研究描述了一个第三方 ARTEX 副本，它把用户引向被植入后门的 Docker 镜像，其中包括 tomicdd/artex 与 congdonglinux/artex。被修改的登录处理程序允许在容器内部进行未认证的命令执行。该发现针对的是这些第三方制品；它并未确立原始 ARTEX 源码中带有该后门。

LLM 辅助的安全审查可以帮助检查源码、安装脚本、Compose 文件以及所请求的权限。它无法确立一个单独下载的二进制文件与其所阅读的源码相符，也可能漏掉恶意行为。核对发布者与确切的镜像引用，在可行时优先使用从已审查源码构建的镜像，并按摘要 (digest) 固定所选制品，使可变的标签无法静默地将其替换。摘要标识的是字节，它并不担保这些字节是安全的。如果审查漏掉了什么，隔离与受限的凭据仍然重要。如果你运行过某个已知被植入后门的镜像，保留证据，从可信制品重新构建，并轮换它可能访问过的凭据。

### 框架不等于评估

一次运行完成，或者一份冗长的报告，都不构成覆盖度的证明。记录该工具实际演练了哪些角色与工作流、哪些发现得到了复现，以及它在哪里停止。一个阻断了某动作的控制措施、一个损坏的工具、一个错误的假设，在运行记录里都可能看起来像失败，但它们意味着不同的后续步骤。对授权边界与业务逻辑的有意测试，仍然需要有一个人对证据与空白负责。

## 内部网络改变了约束条件

面向 Internet 的应用往往给攻击者留出空间：无需先维持一个立足点，就能发出请求。进入受管理的企业内部之后，可用的工作站及其权限、路由与出站访问，就成为对每一个后续动作的约束。

EDR 可以阻断执行，身份控制可以禁用访问，网络分段可以拒绝下一次连接。如果攻击依赖一台工作站，而这台工作站被隔离，那么生成更多智能体并不能恢复它的网络访问。这并不保证遏制 (containment)：攻击者可能已经握有另一个立足点，或在别处可用的凭据。有用的问题是：响应实际上移除了哪些访问权。

Microsoft Defender 的 automatic attack disruption（自动攻击中断）就是针对这一依赖关系采取行动的一个例子。取决于所部署的产品与配置，响应动作可以遏制或隔离设备，并限制被攻陷的身份。查阅 Microsoft 的实施指南，确认你的部署支持哪些动作，然后测试你打算依赖的那一个动作。

选择一个依赖测试工作站与测试账户的受控场景。触发事先约定的响应，验证现有连接是否停止，以及该身份是否仍能在别处通过认证。测量到中断发生所需的时间；如果失败，就检查排除项或覆盖缺口。装上了该产品，并不构成这条响应路径有效的证据。

### 安静的版本在离线完成火力

有经验的操作者可以用并行智能体在离线状态下研究软件、重建环境、研究防御产品，并测试候选动作。实验室里的反复尝试，可以在它们于真实网络上产生流量或触发执行失败之前，就排除掉这些死路。操作者仍然必须选择一个有代表性的环境、质疑结果，并决定哪些动作值得在目标上实施。

最终应当得到的，是一组更小、经过测试的假设：存在的是哪个版本、哪些前提条件重要、一次失败的尝试意味着什么，以及下一个值得采取的动作是什么。实验室在策略、配置与遥测上都可能与生产环境不同。评估团队仍然必须针对实际环境验证这些假设，并说明结果的局限。

## 让火力撞上墙

在一个隔离的实验室里试用这些框架，并检查它们实际做了什么。对攻击方而言，价值在于更廉价的后续跟进、更广泛的调查，以及更快的假设测试，而这些结果仍然需要验证。对防御方而言，从一个暴露的服务开始，在必须保持公开的地方约束重复访问或批量访问，并证明某一项响应切断了一条具体的攻击路径。当操作者强制实施范围并核查证据时，同一批工具也可以帮助测试这些控制措施。

模型能力与框架设计会持续变化。可达性、权限，以及在中断发生之前可用的时间，仍然决定一个智能体在特定环境中能够完成什么。这些是你今天就可以测试的东西。

当目标允许你持续射击时，火力密度的效果更好。
