## 问题

Lua 5.4 允许表构造里有一个尾随分隔符（`{1, 2, 3,}` / `{1; 2; 3;}`），fakelua 的 `fieldlist` 规则缺少这个 `[fieldsep]` 可选项，导致：

```
$ ./flua t.lua
flua: fakelua error: t.lua:2.25: syntax error, unexpected }
```

## 原因

不是归约冲突导致的。实测加这个产生式**前后 bison 冲突数完全一致**（`5 shift/reduce + 1 reduce/reduce`，均在 state 13/25/40/163，都是仓库既有的）—— `fieldlist` 的 FOLLOW 集只有 `RCURLY`，而 `RCURLY` 不可能开启一个 `field`，LALR(1) 在此无歧义。真正原因只是这条产生式当初没写。

## 改动

新增 `tableconstructor: LCURLY fieldlist fieldsep RCURLY`。

⚠️ 尾随分隔符**刻意放在 `tableconstructor` 上**，而不是写成 `fieldlist: fieldlist fieldsep`。后者会踩 bison **默认归约（default reduction）** 的坑：在 `{ fieldlist fieldsep .` 状态遇到非法 lookahead（第二个 `,`）时仍会归约，使 `{1,,2}`、`{1,,,}`、`{1;,}` 被静默接受（Lua 5.4 均拒绝）。这一点在 PR 里加了回归测试锁住。

`parser.cpp` / `parser.h` 用 bison **3.8.2** 重新生成（与已提交文件的生成版本一致）。注意 `src/CMakeLists.txt` 是 `aux_source_directory(compile/bison ...)`，直接编译已提交的 `parser.cpp`，构建时不会跑 bison，所以这两个文件必须一起提交。
