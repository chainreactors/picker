As the PHP2Shell chaos continues, researchers have found a third PHP vulnerability that could allow attackers to take over websites or remotely run malware on vulnerable systems. But this one won’t receive an emergency fix.

The PHP Foundation on Friday told The Register that it has reserved a CVE identifier (CVE-2026-115560) for a third RCE flaw to go with the first two that comprise PHP2Shell, and it will release a full advisory and fixed software with the next regular PHP release.

CVE-2026-115560 “requires a very unlikely combination of configuration and specific PHP application code, which we do not expect to occur in practical use of PHP,” Elizabeth Barron, executive director of the PHP Foundation, told The Register. “The issue can be mitigated with a configuration setting. So for the moment the PHP Security Team has only published an informational advisory on the PHP website, explaining exactly this situation.”

REG AD

The informational advisory, published on Friday, [suggests that users](https://www.php.net/index.php#2026-10-21-5) “set session.upload\_progress.enabled=0 until the next regular bugfix release, to fully protect from an unlikely RCE vector.”

REG AD

These unlikely RCE attacks require an application to set “session.serialize\_handler to php\_binary or php\_serialize in its configuration and then switch it to php at runtime with ini\_set() before calling session\_start().” Additionally, the session upload progress feature must be enabled.

This setup, according to the PHP Foundation, is unlikely in real-world applications, and as such doesn’t pose the same massive risk as the earlier two CVEs that set the internet on fire earlier this week.

Those, of course, are [CVE-2026-109618 and CVE-2026-109619](https://www.theregister.com/security/2026/10/21/php-devs-publish-critical-bug-fix-as-site-owners-warned-pull-em-offline-if-youre-unpatched/5304519), collectively called [PHP2Shell](https://www.theregister.com/security/2026/10/22/php-blames-supply-chain-security-biz-chainguard-for-putting-huge-chunks-of-the-web-at-risk/5304611). The related vulnerabilities involve memory-safety flaws in PHP, the open source programming language running on about 70 percent of websites with a known server-side programming language. The PHP Foundation officially disclosed and patched both bugs on Wednesday.
