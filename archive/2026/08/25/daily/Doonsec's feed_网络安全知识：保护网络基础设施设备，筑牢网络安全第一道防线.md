# 一、为什么要保护网络基础设施设备？

网络基础设施设备是网络通信和信息系统运行的基础，也是整个网络空间的重要"交通枢纽"。

企业、政府和各类组织每天产生的大量业务数据，都需要通过这些设备进行传输、交换、处理和控制。一旦网络基础设施设备遭到攻击，不仅可能导致业务中断，还可能造成数据泄露、网络瘫痪，甚至危及关键业务连续运行。

网络基础设施设备主要包括：

* 路由器（Router）
* 交换机（Switch）
* 防火墙（Firewall）
* 服务器（Server）
* 负载均衡设备（Load Balancer）
* 入侵检测/入侵防御系统（IDS/IPS）
* 域名解析服务器（DNS）
* 网络存储设备（SAN/NAS）
* VPN网关
* 网络管理平台
* 无线控制器（AC）
* 工业网络交换机及工业网关（OT网络）

这些设备承担着网络数据交换、访问控制、安全防护、业务承载等重要职责，是网络攻击者重点攻击的对象。

# 二、网络基础设施设备面临哪些安全威胁？

网络基础设施设备一旦被攻陷，攻击者便能够控制整个网络的数据流向。

例如：

* 控制边界路由器，可以监听、篡改甚至阻断所有进出网络的数据；
* 控制核心交换机，可以监听内部通信，实现横向移动；
* 控制DNS服务器，可以劫持域名解析，引导用户访问恶意网站；
* 控制防火墙，可以绕过访问控制策略，为攻击者打开"后门"；
* 控制VPN设备，可以获取远程办公人员的访问权限；
* 控制网络管理平台，可以进一步控制整个网络中的大量设备。

攻击者一旦掌握网络基础设施设备，实际上就掌握了整个网络的数据通道和控制能力。

# 三、网络基础设施设备为什么容易成为攻击目标？

与服务器相比，许多网络设备长期存在"重建设、轻维护"的问题，主要表现为：

* 长期运行，升级维护频率较低；
* 默认配置未修改，存在弱口令或默认账号；
* 使用Telnet、FTP、HTTP等不安全协议进行管理；
* 固件长期未升级，存在已知漏洞；
* 未关闭不必要的管理接口和服务；
* 缺少终端防病毒、防篡改等安全防护能力；
* 生命周期较长，部分设备已经停止安全支持（EOL/EOS）；
* 运维人员重点关注服务器，而忽视网络设备的安全检查；
* 网络设备日志未纳入统一安全监测平台，异常行为难以及时发现。

这些问题都会增加设备被攻击和被控制的风险。

# 四、如何提升网络基础设施设备的安全防护能力？

保护网络基础设施设备，应坚持"纵深防御、最小权限、持续监测"原则，从网络架构、安全配置、访问控制、运维管理和供应链安全等方面建立全生命周期安全防护体系。

# （一）实施网络分区分域，构建安全边界

合理的网络分区分域是网络安全的重要基础，也是防止攻击扩散和横向移动的有效措施。

根据业务重要程度、安全等级和访问需求，将网络划分为不同的安全区域，例如：

* 互联网接入区
* DMZ区（隔离区）
* 办公网
* 数据中心
* 数据库区
* 运维管理区
* 安全管理区
* 工业控制区（OT）
* 第三方接入区

不同区域之间通过防火墙、访问控制列表（ACL）等安全设备进行隔离，仅开放必要的通信端口和服务。

**安全建议：**

* 按照"最小权限、按需开放"原则设计网络架构；
* 将重要业务系统与普通办公网络隔离；
* 对不同安全域实施差异化安全策略；
* 定期检查网络边界策略，防止策略冗余和误配置。

# （二）采用虚拟隔离技术，提高网络灵活性

在现有网络基础上，可利用虚拟化技术实现逻辑隔离，提高资源利用率和安全性。

常见技术包括：

* VLAN（虚拟局域网）
* VRF（虚拟路由与转发）
* VXLAN
* MPLS VPN
* IPSec VPN
* SSL VPN

通过逻辑隔离，可以在同一物理网络上划分多个独立网络，实现不同部门、不同业务之间的安全隔离。

**安全建议：**

* 利用VLAN隔离不同业务网络；
* 使用VRF实现不同业务的路由隔离；
* 采用VPN保障远程办公和跨区域通信安全。

# （三）限制横向移动，阻断攻击扩散

网络攻击发生后，攻击者往往会利用已攻陷设备向其他主机横向渗透，扩大攻击范围。

因此，应严格限制网络内部的横向通信。

**安全建议：**

* 启用主机防火墙；
* 实施网络访问控制（NAC）；
* 配置交换机ACL和VLAN ACL（VACL）；
* 对服务器之间的通信实行白名单管理；
* 禁止普通终端之间直接通信；
* 建立微隔离（Micro-Segmentation）机制。

通过限制横向流量，可有效降低攻击扩散风险。

# （四）强化网络设备安全配置

网络设备应按照安全基线进行配置，及时关闭不必要的功能和服务。

**重点措施包括：**

* 禁用Telnet，统一使用SSH进行远程管理；
* 禁止FTP，采用SFTP或SCP传输文件；
* 禁用HTTP管理界面，启用HTTPS；
* 使用SNMPv3替代SNMPv1/v2；
* 关闭不必要的服务和端口；
* 删除默认账户和默认密码；
* 启用强密码策略；
* 定期更新设备固件和补丁；
* 定期备份配置文件，并进行离线保存；
* 定期开展配置核查和安全基线检查。

# （五）加强设备访问控制

网络设备属于高权限管理对象，应严格控制管理权限。

**安全建议：**

### 实施多因素身份认证（MFA）

管理员登录网络设备时，应采用：

* 密码
* USB Key
* 动态令牌
* 手机认证
* 生物识别

等两种及以上认证方式。

### 实施AAA集中认证

采用AAA（Authentication、Authorization、Accounting）统一管理管理员身份，实现：

* 身份认证（Authentication）
* 权限授权（Authorization）
* 操作审计（Accounting）

做到"谁登录、做什么、什么时候做、做了多久"全程可追溯。

### 加强密码管理

应：

* 修改默认密码；
* 使用不少于8位的复杂密码，建议支持更长密码；
* 禁止使用弱密码和已泄露密码；
* 对密码进行加盐哈希存储；
* 将紧急管理密码妥善保管。

# （六）建立带外（OoB）管理网络

带外管理（Out-of-Band，OoB）是将设备管理流量与业务流量分离的一种管理方式。

即使生产网络发生故障或遭受攻击，管理员仍可通过独立管理网络对设备进行管理和恢复。

**安全建议：**

* 建立独立管理网络；
* 管理流量与业务流量彻底分离；
* 所有管理通信采用加密协议；
* 管理终端采用专用运维主机；
* 禁止普通办公终端直接管理核心网络设备；
* 对管理网络实施严格访问控制。

# （七）保障供应链安全，防范"带病设备"进入网络

近年来，供应链攻击事件频发，假冒设备、非法固件和恶意软件可能在采购、运输、安装等环节进入网络。

因此，应加强供应链安全管理。

**安全建议：**

* 从官方或授权渠道采购设备；
* 核验设备型号、序列号和真伪；
* 检查设备包装和外观是否存在拆封、篡改痕迹；
* 从官方网站下载固件、补丁和升级包；
* 对固件进行数字签名或哈希校验；
* 定期检查设备配置是否发生异常变化；
* 建立供应链安全审查机制，加强采购和运维人员培训。

# 五、网络基础设施设备安全管理"十项措施"

为提升网络基础设施设备的整体安全水平，建议重点落实以下措施：

* **网络分区分域**：按照业务重要性划分安全区域，构建纵深防御体系。
* **边界访问控制**：通过防火墙、ACL等技术严格控制跨区域访问。
* **安全配置加固**：关闭不必要的服务和端口，采用安全协议，落实配置基线。
* **漏洞与补丁管理**：建立设备漏洞监测机制，及时升级固件和安全补丁。
* **身份与权限管理**：实施多因素认证、AAA集中认证和最小权限管理。
* **带外管理**：建立独立的运维管理网络，隔离管理流量与业务流量。
* **日志与监测**：开启设备日志，接入日志审计平台或SIEM，实时监测异常行为。
* **配置备份与恢复**：定期备份配置文件，开展恢复演练，确保快速恢复能力。
* **供应链安全**：从正规渠道采购设备，验证固件完整性，防止假冒和被篡改设备进入网络。
* **持续检查与改进**：定期开展安全基线核查、渗透测试和风险评估，持续优化防护措施。

# 安全提示

> **网络基础设施设备是网络运行的核心，也是网络攻击者重点攻击的目标。任何一台路由器、交换机、防火墙或VPN网关被攻陷，都可能导致整个网络受到影响。应按照“分区隔离、安全加固、最小权限、持续监测、供应链可信”的原则，加强网络基础设施设备全生命周期安全管理，不断提升网络整体防护能力，为业务连续运行和数据安全提供坚实保障。**
