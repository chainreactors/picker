## 一、项目概述

### 1.1 项目背景

医疗机构 HIS、电子病历、PACS、LIS、互联网医院、医共体平台集中存储、处理大量**患者个人信息、敏感诊疗数据**，属于重点监管对象。依据《网络安全法》《数据安全法》《个人信息保护法》《医疗卫生机构网络安全管理办法》，定级二级或者三级系统需定期开展等级保护测评：三级系统：**每年至少测评 1 次。**

### 1.2 测评目标

1. 核查系统与 GB/T22239-2019 对应等级要求的符合性；
2. 重点核查**电子病历、患者隐私、诊疗数据**的数据安全、个人信息保护；
3. 输出正式等级测评报告，可提交网安备案；
4. 输出分级风险清单（高 / 中 / 低）+ 落地整改建议；
5. 协助医院完善安全管理制度、应急预案、数据脱敏、备份恢复流程；
6. 形成常态化安全基线，把安全合规作为医疗信息化安全起点。

### 1.3 测评范围（医疗典型系统，按需删减）

表格

| 系统名称 | 建议定级 | 备注 |
| --- | --- | --- |
| HIS 医院信息系统 | 三级 | 核心诊疗、收费、医嘱 |
| 电子病历系统 | 三级 | 敏感患者病历数据 |
| PACS 影像系统 | 三级 | 影像数据量大、隐私强 |
| LIS 检验系统 | 三级 | 检验结果、患者信息 |
| 互联网医院 / 线上问诊 | 三级 | 对外暴露、远程问诊 |
| 120 急救调度平台 | 三级 | 关键业务系统 |
| 医共体集成平台 | 三级 | 多机构数据汇聚 |
| OA、HRP、物资管理 | 二级 | 内部管理 |

> 测评对象包含：机房物理环境、网络架构、防火墙 / 入侵检测、服务器、数据库、应用、终端、运维、制度文档、备份系统、数据脱敏、日志审计等。

### 1.4 测评依据

1. 《中华人民共和国网络安全法》《数据安全法》《个人信息保护法》
2. 《信息安全技术 网络安全等级保护基本要求》GB/T 22239-2019
3. 《信息安全技术 网络安全等级保护测评要求》GB/T 28448-2019
4. 《信息安全技术 网络安全等级保护测评过程指南》GB/T 28449-2018
5. 《医疗卫生机构网络安全管理办法》（国卫网信发〔2022〕19 号）
6. 《网络安全等级保护定级指南》《网络安全等级保护管理办法》

## 二、测评组织与职责

* **甲方（医疗机构）：信息化科、医务科、质控、运维、业务科室；提供文档、账号、机房准入、业务配合、确认整改方案；**
* **测评机构（慧等保）：项目负责人、测评师、渗透测试工程师、文档审核员；方案编制、访谈、核查、工具测试、渗透、报告编制、整改指导；**
* **配合厂商：****HIS 厂商、服务器 / 数据库厂商、安全设备厂商，配合配置核查、漏洞验证。**

> 测评人员具备等保测评资质，工具经过校验，全程不影响核心诊疗业务，测试避开门诊、手术高峰。

## 三、测评内容（等保 2.0 10 大测评域，医疗重点标注）

### （一）技术测评（一个中心、三重防护）

1. **安全物理环境**

   机房门禁、监控、消防、UPS、温湿度、防雷、电磁防护、机房出入登记；重点：服务器机房、存储机房、灾备机房。
2. **安全通信网络**

   网络分区（诊疗网、办公网、互联网医院隔离）、VLAN、专线加密、传输加密、链路冗余；**医疗重点：内外网隔离、远程访问、医共体横向互联安全**。
3. **安全区域边界**

   防火墙策略、ACL、IPS/IDS、边界审计、恶意代码检测、网闸（跨域交换）；重点防止互联网医院、远程运维入口被入侵。
4. **安全计算环境（医疗核心）**

* 身份鉴别：双因素认证、弱口令核查、HIS / 病历系统账号权限；
* 访问控制：最小权限、角色权限、医嘱 / 病历越权访问；
* 安全审计：日志留存≥6 个月，操作审计（调阅、修改病历）；
* 入侵防范、恶意代码；
* **数据安全（医疗重中之重）**

患者数据保密性、完整性、备份恢复、脱敏、剩余信息保护、个人信息采集 / 存储 / 共享合规；电子病历防篡改。

1. **安全管理中心**

集中审计、运维管控、设备集中监控、态势感知、告警处置。

### （二）管理测评

1. 安全管理制度：安全策略、数据安全制度、病历数据管理、外包运维管理；
2. 安全管理机构：岗位、授权审批、信息安全领导小组；
3. 人员安全管理：岗前培训、离岗回收权限、外包人员管控；
4. 系统建设管理：定级备案、厂商选型、开发安全、上线测试；
5. 系统运维管理：变更管理、漏洞管理、应急演练、定期备份、介质管理、远程运维管控。

### （三）医疗专项增强测评（慧等保特色）

* 电子病历防篡改、日志溯源；
* 患者隐私脱敏、导出管控、数据共享审批；
* 远程会诊、互联网医院用户鉴权；
* 勒索病毒防护（医疗高发风险）；
* 灾备与恢复演练（RTO/RPO 核查）；
* 第三方服务商（HIS 厂商运维）安全管控。

## 四、测评方法

采用**访谈 + 文档核查 + 配置核查 + 工具扫描 + 人工渗透测试 + 现场核查**组合方式：

1. 访谈：信息科负责人、运维、业务负责人、安全管理员；
2. 文档检查：制度、应急预案、备案回执、培训记录、备份记录、变更记录；
3. 工具测评：漏洞扫描、弱口令扫描、配置基线核查；
4. 人工测试：登录验证、权限测试、越权测试、渗透（**非破坏性，严禁删改业务数据**）；
5. 现场核查：机房、机柜、消防、门禁、UPS、安全设备。

> 测试原则：**不影响诊疗业务，不篡改、不删除患者数据；高危测试提前预约，安排在夜间 / 周末**。

## 五、实施流程（总周期建议 30 个工作日）

### 阶段 1：测评准备（3 天）

* 收集系统清单、拓扑图、备案材料、制度文档；
* 确认测评范围、账号、机房准入、测试窗口；
* 编制《现场测评实施方案》，双方确认。

### 阶段 2：现场测评（5–7 天，避开门诊高峰）

* 文档审查、人员访谈；
* 机房、网络、安全设备、服务器、数据库配置核查；
* 应用、HIS / 电子病历专项测试、漏洞扫描、渗透测试；
* 现场记录、证据采集，形成初步问题清单。

### 阶段 3：风险分析与差距研判（5 天）

* 对照标准判定：符合 / 部分符合 / 不符合；
* 风险分级：高风险（必须整改）、中风险、低风险；
* 输出《差距分析报告》《问题整改清单》，附整改建议。

### 阶段 4：整改实施（10 天，按需延长）

慧等保提供整改辅导：制度补全、策略优化、配置加固、日志审计开启、备份策略优化、脱敏、权限梳理；如需新增安全设备，输出建设建议。

> 整改完成后，开展**复测**，验证整改有效性。

### 阶段 5：报告编制、交付备案材料（5 天）

* 出具正式《网络安全等级保护测评报告》；
* 风险汇总、测评结论、整改回执；
* 协助提交公安网安备案、卫健迎检材料。

## 六、交付物清单

1. 《医疗信息系统等级保护测评实施方案》（本文档）
2. 《现场测评记录、证据包》
3. 《差距分析及风险清单（高 / 中 / 低风险）》
4. 《安全整改建议书（含医疗数据专项）》
5. 渗透测试专项报告
6. 正式盖章版《网络安全等级保护测评报告》
7. 备案辅助材料、制度模板、应急预案模板

## 七、项目成果价值

1. 满足公安网安等级测评备案要求，规避处罚风险；
2. 满足卫健行业网络安全检查、电子病历评级、互联网医院准入核查；
3. 梳理患者敏感数据全链路，降低隐私泄露、勒索病毒风险；
4. 形成持续运维基线，把安全合规做成医院信息化安全的起点；
5. 为后续数据安全、隐私合规、信创改造提供安全底座。
