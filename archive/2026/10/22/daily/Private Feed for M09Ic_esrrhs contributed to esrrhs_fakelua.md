## Summary

Fixes the 10 items in `deliverables/fakelua-issues-from-doudizhu-server-2026-10-21.md` (the doudizhu server port report).

* **Runtime errors now carry `file:line` on all three backends.** `FakeluaException` keeps message / Lua location / C++ stack as separate parts, and each engine fills the location at the boundary nearest the failure: the interpreter reads its own `ip` against the (previously always-zero, now populated) `FuncProto::lineinfo` in a same-frame `catch`, so the hot path pays nothing; JIT code writes the current statement into a slot on `State` that native-function errors fall back to. `pcall` surfaces the same message.
* **`#line` per statement in generated C** so tcc/gcc warnings point at the Lua source instead of `<string>:2503` (verified on both compilers). This also makes the report's unresolved "assignment of read-only location" warnings attributable.
* **Strict arity holds for the interpreter too**: the check existed only in CGen, so an interpreter-only build (`disable_jit` on both C backends) silently padded nil.
