一个程序，只给你一串十六进制数，没有源码，没有反汇编器，没有调试器，也不许运行，你能说出它是干什么的吗？

2026年11月，一个研究小组把这个问题丢给了GPT-6.1 Sol。模型通过Codex CLI调用，推理强度设为high，输入是一段xxd导出的hex dump（十六进制转储），也就是把文件里每个字节写成两位十六进制。团队在本地中转层把所有工具从请求里拿掉，还审计了每一轮事件流。除了这堆字符，它没有别的工具，没有第二次机会，回复只有一次。

结果有点超出预期：四段程序，四个答案，全对。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/ibO9kiauylaDpxpib1QkYkgicjp6R9INTr3HcykuIbIGRQp8Zicy1hPc0DF9QicbKicDUMm09bv5pvEelnlU87kYwpfovLhj3icBRzR7LPibWa8wGL20/640?wx_fmt=png&from=appmsg)

他们把这种能力叫做Machine Code Programming（机器码编程）。名字听起来像新学科，描述其实很简单：让通用大模型直接对可执行文件的字节推理，中间不经过编译器、汇编器、反汇编器，也不让程序跑起来。

四个程序里，三个是团队自己写的小工具。5,368字节的wordcount，数行数、单词数和字节数；9,152字节的AES工具，只做AES-128和AES-256的ECB加密；8,872字节的账本程序，用命令管理几个具名账户。第四个是FreeBSD的ministat，67,392字节，做统计检验，还会画ASCII图。

ministat被刻意处理过：-O3编译，静态链接musl，strip掉符号，删掉程序自带的所有文本，最后三个字符串还把每个字节的最高位置1。模型还是找到了解码循环，把选项表恢复出来，八个选项一个不落。

更意外的是Bug。ministat的t分布表没有符号，也没有文字说明。模型把那串数据当成64位浮点数读，发现标着99.5%置信度的选项，实际用的是99.8%的临界值。也就是说，-c 99.5跑的是更严的检验。团队后来在源码里确认了这个问题。

这里要说明一下成本。hex dump大约每个字节2.4个token，67KB的ministat就要16万多token。模型能读，但读得不便宜。

# 会读之后，它开始改

读懂之后，下一步是改。团队给三个程序各提一个新需求：wordcount多打印一列最长行长度；AES加一个dec命令，能解密；账本加transfer，能在账户之间转账。

模型拿到的还是字节，回复的是一串等长替换：改哪几个地址，原来是什么，改成什么。没有反馈，没有第二次尝试。

三个程序都通过了隐藏测试：老功能不变，新功能可用，长输入也不出错。改动量分别是74字节、544字节和379字节，对应1.4%、5.9%和4.3%。

它是怎么做到的？说白了，像一个熟悉二进制的人在手改程序。先在文件里找一段填充空间，改段头把它变成可执行，再把新代码写进去，最后把原来的指令替换成跳转到新代码的call。wordcount这一例里，模型自己找到了0x1110和0x1190两处输出函数，直接复用。

图1是改过的wordcount跑同一组命令。原版只打印前三列，这一版多出第四列，也就是最长行的长度，整个文件还是5,368字节。

![](https://mmbiz.qpic.cn/mmbiz_png/ibO9kiauylaDqNulI0maJDuhns1fHXHSJhkeKlIhUMicF41ZouMibCb6njNUw4puAQY1XKW9jXxOtuMzicNWjAtWKhoUFlpOicMHNZhkicmmYx0XtU/640?wx_fmt=png)

图1｜wordcount修改后。第四列是最长行长度，文件大小没变。

账本这例更直观。原版只认识open和打印，遇到transfer就报unknown command；图2是改过之后的版本，alice给bob转50能成功，余额不足、账户不存在、同一账户转账也都能给出对应的错误。

![](https://mmbiz.qpic.cn/mmbiz_png/ibO9kiauylaDqOvlncLWsa2devW2PibIE5uYIz5jvwLQaX8cBgNEMSMCInYs3bCHe4G8bhfpC9Rk1Tl5oLCuGmdXHYdflbdZQMpofQW0BghK54/640?wx_fmt=png)

图2｜账本程序修改后。转账命令从unknown command变成可用，错误提示也对上了。

这些改动不是把整个程序重写，而是在原有代码的缝隙里塞进新逻辑。几十到几百个字节的补丁，能让一个只会加密的工具学会解密，也能让一个只会记账的程序学会转账。

# 从零写一个ELF64

再往前走一步，就不给程序了。团队只写一段行为描述，让模型从零生成一个完整的ELF64可执行文件。ELF64是Linux下的64位可执行格式，文件头、段表、代码、数据，每个字节都得自己算。没有汇编器，也没有编译器。

三个程序，三次都跑起来了。测试放在qemu-x86\_64下执行，stdout和退出码要和GCC参考版本逐字节一致，才算通过。

数字很有意思：wordcount加最长行，模型写出来391字节，GCC版本5,432字节；AES加解密4,144字节对9,408字节；账本加转账3,584字节对8,896字节。输出token从6,035到25,069，耗时124秒到504秒。

体积小不代表功能少，因为模型不需要编译器那套对齐、填充和通用运行时。它只写这个程序真正要用的部分。反过来，从零写比在现有程序上改更费token，后者大约只要前者的四分之一到一半。

图3是AES工具改过之后。原版遇到dec就报unknown command，现在128位和256位都能解回明文，坏数据会报bad data。

![](https://mmbiz.qpic.cn/mmbiz_png/ibO9kiauylaDoQMDhWtWZs3tsiahMv0dWvtbHl1ruwVCUmec5RIJic1jjv71ZZQuq4Zn95QY1taiau0AAkGxia4O1msSXW8VGyMbf0oo6BdJ0glCg/640?wx_fmt=png)

图3｜AES工具修改后。解密命令从报错变成可用，128位和256位都能还原明文。

# 真实样本，211秒

接下来是恶意软件分析。团队给模型一个4,608字节的PE32+文件，PE32+是64位Windows可执行格式。这个样本只露出一个Sleep导入，其他API调用全藏在名字哈希里，字符串也不是明文，而是在栈上拼出来的。提示词和前面一样，没有告诉它这是恶意软件。

211秒后，模型给出的结论是：这是一个下载并执行内存代码的stager（分段投递器）。它报出了硬编码服务器165.154.205.34的443端口，以及请求的URL：GET /?a=w64&h=165.154.205.34&t=ws\_&p=443。

团队拿同一个文件去比对公开的VMRay动态分析，SHA-256一致。沙箱联系了同一个地址，请求了同一个URL。模型还列出13个通过遍历模块、比较ROR13（循环右移13位哈希）找到的API，团队独立重算，13个全对。它识别出%TEMP%\log\_de.log这个标记文件，存在就退出；识别出把返回内容用0x99异或，再写进可读写可执行（RWX）的缓冲区；也识别出下载的5,158,400字节windows\_amd64.exe，和公开报告里的VShell stager对得上。

这些就是入侵指标（IOC）层面最关注的东西：地址、请求、落地文件、执行方式。

当然，有几处没有被沙箱完全证实：每10秒重试一次，以及0x99这个异或密钥。ROR13哈希在公开工具里很常见，模型可能靠记忆认出了一部分。团队自己也把这些限定写清楚了。

# 开源模型也给出了同样的答案

闭源前沿模型能做到，不算太意外。团队又换了开放权重的DeepSeek V4.1 Flash，MIT许可，换一个harness（运行框架），同样的样本，同样的提问，高推理强度，一次回复，不用工具。

DeepSeek给出的结论一样：download-and-execute stager，按哈希找Windows函数，443端口走明文HTTP，单字节异或解码，在内存里执行，最终payload不在这个文件里。

差别在过程和成本。它找对了13个API里的9个，URL里把一个参数写成了fh而不是h；用了89,902个推理token，是Sol的17倍，耗时859秒对211秒。它的推理记录里能看到很具体的动作：用PE节头把入口点映射到文件偏移0x400，把e9 03 00 00 00读成跳到0x408；从两条写栈的指令里拼出GET /?a；跟着rbx里的缓冲区指针，把80 34 19 99读成异或0x99，把ff d3读成调用缓冲区。

这段记录也说明，它不是背答案，而是在字节层面一步步推理。

# 另一条战线：权重

# 黑鸟认为，通用大模型已经能在没有反汇编器的情况下读机器码，也能在不靠梯度的情况下读写神经网络权重。相关阅读：[只动两个神经元，大模型就变坏了](https://mp.weixin.qq.com/s?__biz=MzAxOTM1MDQ1NA==&mid=2451189550&idx=1&sn=34d400b3803c142a2c935ac882e7b290&scene=21#wechat_redirect)

如果说机器码是程序的最底层，那神经网络的权重就是另一个极端。它没有语法，没有符号，只有一大片浮点数。2026年11月2日，MIT CSAIL的一个团队公布了另一组实验，把这种能力叫做Weight-Space Programming（权重空间编程）。它不是一套新的训练算法，而是一种描述：把权重当成程序来读和写。用的模型是GPT-6 Astra。

先看读。一个MLP（多层感知机），500→32→32→5，tanh，17,253个权重，四个游戏用的是完全相同的网络尺寸和输入输出。模型只看权重文本，四个游戏全说对。它还看懂了扩散模型：23,824个权重的DDPM（去噪扩散概率模型），12×12灰度图，分别训练圆、方、三角，模型说出每个模型生成什么形状。有意思的是它把形状画成轮廓，而模型实际生成的是实心图，这反而说明它在读权重的几何结构，不是在脑子里跑前向。

语言模型也一样。7.16M参数，4层×6头，宽度384，只给中间四个Transformer block，输入输出层全部拿掉，384个维度也没有标签。模型要说出训练语料是Python、罗马字日文还是英文，还要说出24个注意力头各自在干什么。它三次都答对，而且把所有的copying head（复制头，也叫induction head，归纳头）都找了出来，没有多报一个。它用Python分析权重，但不许跑网络。它用的那套方法，和Elhage等人公开过的电路分析思路一致，团队并没有提示它。

还有一个实验专门盯着“谄媚”。三对Gemma 3 270M，每对都用同样的数据微调，一个说正确答案，一个跟着用户给的错误答案走，输入输出层冻结，所以不能靠看embedding偷懒。只给权重，模型四次都没能分辨；允许它自己写16段文本、只看两个模型的注意力分布，三次配对全部选对。它还指出中层注意力头的差异：谄媚模型的10.2号头把85.7%的注意力放在用户给的答案上，诚实模型正好相反，94.3%看题面数字，只有0.75%看用户答案。

然后是写。Kinetix里有一辆车上坡的任务，PPO（近端策略优化）训练了10亿步，卡在局部最优：车直冲坡道，上不去。模型拿到171,664个权重、场景描述和一段失败记录，一次回复，改了3.5%的权重，256次失败变成1,024次全成功。这个网络是679→128→五层128→16，输入是场景里每个物体的位置、速度和形状。它的做法是在每层加一条很小的旁路，读车速和位置，等绿轮过了红线就关掉，让原来的网络接着开。

![](https://mmbiz.qpic.cn/mmbiz_png/ibO9kiauylaDoaQsQ61dAlYQD1grxQXQ3eAv0j94hAJUqGAZKBRLq3ia9Qx818Wy3D155KwPp6icZlEUoCF7ZK0JdoLVsHxpg4fELb1ia6IDFLicQ/640?wx_fmt=png)

图4｜Kinetix小车任务。修改后的策略会先倒车再起跳，原版PPO的车还停在坡道前。（图源：项目公开页）

更夸张的是从零写。MinAtar三个游戏，600→32→32→6，模型只拿规则、源码和输入输出布局，没有数据、没有损失、没有梯度、没有工具，也不许试玩。它写出来的网络在Breakout拿到517.4分，PPO训练1亿步是15.8分，训练5亿步是25.3分；Seaquest是53.1分对5.6和88.9；Asterix是53.2分对25.8和55.2。

9×9围棋，243→512×6→82，148万个权重。模型在Python沙箱里一层层写，不许用围棋库，不许联网。0次前向就能赢两个小PPO网络，50次前向能赢同尺寸、训练了2,000万局的PPO。它把前几层写成提子、气的标记，中间层沿棋子链传播，最后一层给每个点打分：能吃、能救、别把自己放进被打吃的位置、别填自己的眼。没有前向预算的那一版，整段逻辑是它用336行Python一次写出来的。

最后是Qwen3.5-0.8B。这个模型有个毛病，思考时会循环，96个练习答案里85个达到32,768token上限。模型把循环定位到第15和第19层的MLP写出的一个方向，在每层64个输出列上把这个方向减掉，一共改了131,072个权重，占0.8B的0.016%。50次前向之后，MATH-500从7.9%到48.1%，GSM8K从13.8%到67.1%，IFEval从21.0%到62.3%，达到上限的比例从93%降到33%。

还有一个反例。同样是数学，Gemma 3 270M很少循环，模型找不到一个可以关掉的单点故障，只能看到零散的算术和代数错误。它改来改去，MATH-500从6.8%最多到7.7%，自己也说这个提升不算成立。这说明改权重能搬开挡住能力的石头，不能凭空造出一个能力。

# 工具会消失吗

机器码和权重，过去都属于看得见但读不懂的东西。前者靠反汇编器、调试器、沙箱，后者靠训练、评测、可解释性工具。两边的共同点是：中间必须有一层工具，把原始数据变成人能理解的符号。

现在，通用模型可以跳过这层转换，直接在原始表示上推理。机器码这边，反汇编器对模型来说可能不再是必需；恶意样本可以先在字节层面做一遍快速分诊，再决定要不要上IDA、Ghidra、沙箱。权重这边，审计可以在不跑benchmark的情况下先看权重，优化可以一次改几千个权重而不是重训。

但工具不会消失。对人来说，汇编、反汇编、动态分析仍然是必要的证据链；对模型来说，工具变成了harness的一部分，用来扩大上下文、做前向验证、把大文件切片。真正变化的是分工，不是工具的生死。

机器码这边的硬限制是上下文。hex dump每个字节2.4个token，67KB就要16万token，10MB的程序要2,400万token，一次读完不现实。团队测过的最大程序就是67KB，再往上质量怎么掉，他们也不知道。一个可能的解法是Recursive Language Models：把长提示放在REPL里，模型先读文件头，再顺着调用和跳转把每个函数交给子调用。

实验规模也不大。恶意样本只有一个，运行只有一次，沙箱确认了地址、请求和下载，但没有确认10秒重试和异或密钥。ROR13哈希在公开工具里太常见，模型可能认出了熟悉的家族。

权重那边同样。多数网络小到能塞进上下文，Qwen的0.016%改动解决的是循环，不是数学能力本身；Gemma的反例说明很多能力不是一个方向能开关的。研究团队把这些称为early results，早期证据，不是成熟方法。

还有一个容易被忽略的点：模型能读，不等于读得准；能写，不等于写得稳。一次成功背后，是公开日志里大量的失败、重试和错误猜测。DeepSeek的记录里就有反复改口和猜错的API名。把它当成一个不知疲倦的逆向工程师，可以；把它当成不会出错的oracle，不行。

回到开头那个问题。一串十六进制，没有工具，没有源码。以前我们会说，找反汇编器吧。现在可能要加一句：也可以先问问模型。

它未必每次都对，但它已经能直接在那层我们以为只属于反汇编工具的空间里工作了。下一次你打开一个exe，或者一个几十MB的模型文件，可以想一想，对面那个读文件的家伙，可能已经不需要先看见汇编了。
