The review found ways a Lua plugin could do more than it declared. This closes them.

### What changes

* **User-only commands.** `Command.UserOnly` marks what changes who may do what. `oriel.run` refuses it to every plugin, whatever capabilities it holds. Your own keys, clicks and `init.lua` still run it.
  + User-only: `plugins.install`, `uninstall`, `accept`, `update`, `sync`, `enable`, `disable`, `consent`, `consent.accept`; `settings.set`, `reset`, `reset_section`, `reset_all`, `undo`, `trust`; `secrets.set`, `delete`, `dialog.save`; `update.install`, `restart`; `jobs.form.save`.
  + Before this, a plugin that declared nothing could install another plugin and accept its consent.
* **Missing Grants.** `permissions.tool` and `permissions.net` need `gate`, like `rules.add` and `rules.remove`. `jobs.run`, `jobs.save` and `jobs.delete` need `session.control`.
* **Options.** Through `oriel.option` (and `oriel.session_option`), a plugin can set:
  + its own `plugin.<name>.*` options freely;
  + other options only with the new `settings` capability, which is high risk and listed at install;
  + `sandbox.*` never. Before this, a plugin could set `sandbox.default = "host"`, or `sandbox.servers`, which holds host command lines.
  + A buffer's options (an ftplugin's `tabstop`) stay free. Your `init.lua` is unrestricted.
