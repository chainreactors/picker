### 1. 背景介绍

本文介绍的 Trident 发表于 Computers & Security 2026（CCF-B 类期刊），代码仓库见 https://github.com/123wzj/trident 。

APT自动化归因需要整合源源不断发布的CTI中的三类证据：

* IoC（IP、域名、文件哈希等）
* MITRE ATT&CK框架定义的TTPs
* 串联上述证据的关联上下文

但APT自动化归因面临着下文所述的3个挑战

### 2. 动态威胁环境下归因面临的三大挑战

面向动态威胁环境的自动化归因仍存在以下3个挑战：

#### C1：非结构化情报解析存在事实偏差，长文本出现语义碎片化

实际场景中，**威胁线索**往往最早出现在厂商报告、技术博客、事件分析文档中，而非结构化情报共享平台，想要及时摄入这些情报，就需要系统从长篇的非结构化CTI中自动提取IoC实体、关系、TTPs等信息

尽管基于大模型的提取方法具有一定的泛化性，但是事实偏差、角色混淆、跨段落信息丢失等问题依然存在

#### C2：缺少能同时处理结构化证据和行为证据的统一归因模型

APT归因既依赖IoC实体及其关联关系所提供的结构线索，也依赖TTPs序列反映的威胁行为体的行为线索

现有模型大多只能有效利用其中一类证据：

* 面向结构的模型能够捕捉实体关联和局部拓扑模式，但容易受基础设施复用、共享中继资源的干扰
* 面向行为的模型可以刻画攻击流程，但当不同组织使用相似技术时，判别能力会明显下降，易受假旗行动干扰

#### C3：针对持续更新的CTI开展归因模型更新

归因所依赖的CTI并非静态数据集，而是不断新增的事件流、基础设施指标和技术组合。

每次更新若执行完全重训练，计算开销会高到难以接受，也会阻碍及时响应威胁。反之，如果仅在新数据上直接微调模型，会有灾难性遗忘的问题

### 3. Trident 的主要贡献

针对动态威胁场景下自动化归因面临的3个挑战，本文提出了Trident，解决3个挑战的概况如下：

* **针对C1（长篇非结构CTI带来的语义偏移、角色混淆等问题）**：本文设计一套基于状态维护和多阶段校验的提取流水线。**通过重叠分块、跨窗口记忆、一致性过滤、基于规则的校验**，把长篇报告转换为可以并入异构威胁知识图谱(HTKG)的结构化增量子图
* **针对C2（归因系统鲁棒性不够）**：为克服单一视图证据带来的不稳定性，本文设计双路(Dual-Stream)归因模型：一个分支使用关系图卷积网络（R-GCN）对威胁知识图中的多关系结构模式建模；另一分支采用 Transformer 对每个攻击事件对应的、经过阶段归一化的 TTP 序列和辅助行为特征进行编码，两个分支在决策层协同融合
* **针对C3（无法很好地适应CTI随时间的增量）**：采用基于回放的增量训练机制，在吸收新观测样本的同时，尽可能保留模型对历史 APT 组织的判别能力

图2 非结构化 CTI 报告的结构化抽取流程

可以分为这几步：

* **数据预处理**：

+ 将不同格式的CTI报告统一转换为Markdown
+ 使用重叠分块策略(即前一个Chunk的结尾内容会同时出现在下一个Chunk的开头)进行分块，避免一次性将长文档输入大模型造成语义偏移、上下文溢出等问题
+ 使用正则表达式预识别IOC（防止大模型幻觉，以及避免大模型在长文档中寻找分散的IoC实体的性能和效率问题）
+ 同时通过实体寄存器以及滚动摘要维护分块状态记忆

> 实体寄存器（Entity Register）跨分块**累积已识别实体及其局部上下文**；滚动摘要 (Rolling Summary) 是一段由 3–5 句话构成的事实摘要，**不新增任何原文没有的信息**，它会被注入每个文本分块的提示词中，在被切分的报告上维持共指消解与叙事连贯性

* **基于大模型的提取**(实体寄存器以及滚动摘要维护分块状态记忆)

+ 双分支提取：系统为 IOC 与 TTP 两条路径分别构建**思维链提示词（CoT Prompt）**，引导大语言模型执行抽取：IOC 路径识别 IP、域名、URL、哈希、CVE 等候选实体并校验其安全角色；TTP 路径提取有明确依据的攻击技术，并映射到 MITRE ATT&CK 体系

* **对抗性校验**：校验提取出的候选实体以及TTPs，这里是**独立于上一步的大模型调用**，作用就是抬杠，想尽办法挑候选实体的毛病，最后输出接受ACCEPT/拒绝REJECT，以下情况会被拒绝：

+ 防御者、研究人员的行为，而非攻击者行为
+ 只是通用漏洞概念、定义描述，不是本次攻击真实发生的行为
+ 受害者资产被错误标记成攻击者 C2
+ 报告本身的素材、CDN 域名、参考文献 URL 等文档内容，不是攻击 IOC
+ 校验器无法证伪为攻击者证据的候选会被剔除，剩余实体与 TTP 序列输出为统一的 JSON 记录

* **外部知识丰富节点与属性**：通过公开情报丰富实体属性，比如对于 CVE 实体，从 NVD 记录中获取漏洞编号与年份信息，并按年份做归一化。除了属性增强，还起到了验证大模型是否幻觉出不存在的IoC，不存在的IoC在这一步无法在外部知识源中得到验证

通过第2、3步，保证了抽取出的实体的正确性，避免了大模型编造不存在的IoC和TTPs实体

这步的产出：多源的CTI最终被归一化为**事件级结构化表示**

#### 双路APT归因框架(Dual-Stream APT Attribution Framework)

Motivation：APT 攻击活动通常暴露出两类互补的证据：一类是以基础设施与实体关联为核心的**结构证据**，例如共享 IP、域名、恶意软件家族、利用的漏洞；另一类是 TTP 在攻击各阶段的组合与战术阶段组织所反映的**行为证据**。仅建模其中单一视图，都容易受基础设施复用、公共中继资源、局部行为不全的干扰

##### 图结构编码器

使用关系图卷积R-GCN

图结构分支对每个攻击事件关联的结构证据建模。对于给定事件，我们构建连接事件节点与其关联实体（包括 IP 地址、域名、URL、ASN、文件、CVE 编号）的异构局部图。该分支聚焦于事件关联实体之间的关系，旨在捕捉与归因相关的结构信号，例如 IP 与 ASN 的归属关系、攻击事件与文件的关联、局部连通模式等。

为建模这些多关系依赖，我们采用**关系图卷积网络（R-GCN）**。它通过为不同关系类型学习独立的变换参数，在异构图上实现感知关系的消息传递，因此特别适合捕捉攻击事件与其关联威胁实体之间的细粒度结构交互；这也与此前基于图的 APT 归因研究结论一致，即关系传播对于挖掘潜在结构证据有效。

我们选择 R-GCN 而非单关系编码器（GCN/GAT/GraphSAGE）或注意力密集的 HGT，原因在于：其面向关系的传播机制匹配我们 14 种关系的异构模式，同时**基分解**可以控制参数量；该选择也得到了消融实验的实证支持。

##### TTPs行为序列编码器

使用Transformer

对于每个攻击事件v，其关联的 TTP 序列记为，其中每个代表从 CTI 中提取并映射到 ATT&CK 的技术项。我们将事件提取出的 ATT&CK 技术集合，**按照 14 个 ATT&CK 企业战术阶段（从侦察到影响）的顺序序列化**，同一战术下的技术按技术 ID 固定确定性排序。这种序列化方式得到稳定的事件级表示，不受 CTI 报告中提及顺序的影响（报告通常按主题组织），同时注入了粗粒度的战术阶段先验。

不同 APT 组织可能使用相似技术，但侧重的战术阶段、技术组合方式存在差异；区分信号主要来自技术组合与战术阶段覆盖度。随后每个技术被映射为可学习的技术嵌入，并在序列化序列中加入位置编码。

为编码这类行为模式，我们采用基于 Transformer 的序列编码器。与 LSTM 这类循环编码器（逐步处理技术、偏向严格局部顺序）相比，Transformer 通过自注意力建模整个序列中技术间的依赖关系，因此更适合捕捉攻击行为的阶段结构、长程交互与复杂技术组合模式；消融实验也验证 Transformer 表现优于 LSTM。经过多层自注意力与前馈变换后，最终隐状态聚合为事件级行为表示。该分支旨在捕捉技术选择、战术阶段覆盖、技术组合模式中反映的行为规律，从而提供与图结构信号互补的归因证据

#### 基于回放的双路增量自适应
