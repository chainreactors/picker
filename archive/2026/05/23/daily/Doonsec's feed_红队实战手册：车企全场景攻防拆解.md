### 1.1 思维认知升级：资产收集三大核心准则

**为什么常规思路必死？2026 防御底层逻辑**

1.**流量不再按“端口/协议”判断，而是按“行为”判断**

2.**被动探测全覆盖，主动探测=自投罗网**

3.**正常业务从不“批量扫描”，异常=攻击**

4.**一次暴露 → 全链封锁 → 渗透失败**

切勿将资产收集简单等同于端口探测与域名爬取，专业的测绘工作需要遵循三套核心原则，建立正确作战思维。

* **被动优先，主动探测保持隐蔽** 主动发包探测极易暴露自身行踪，实战场景下，前期二十四小时仅开展无源信息搜集，依托公开搜索引擎、证书档案、代码仓库、历史DNS记录挖掘情报，全程不向目标主机发送数据包。主动扫描作业压缩至十五分钟内完成，同时模拟正常运维、搜索引擎爬虫流量特征，做到低速、精简、精准探测。
* **聚焦网络拓扑，摒弃单纯IP清单记录** 收集信息不能只罗列IP地址，重点梳理资产用途、业务权限、设备互联关系，搭建三维网络拓扑结构。单一开放端口没有实际参考意义，判断设备所属服务、运行环境、系统层级，才能合理规划攻击先后顺序与突破路径。
* **检索语法等同于实战武器** 熟练掌握谷歌检索语法、Shodan筛选语句、Censys查询规则以及GitHub检索指令，能够从海量公开数据里快速定位配置漏洞、开发遗留接口、游离影子资产。精准的检索语句，探测效率远超大范围端口扫描。

### 1.2 实战三式秘技：无源被动信息搜集

**第一式：证书日志检索挖掘 · 捕获隐藏后台与内网资产**

实际场景中，企业往往刻意隐藏管理后台、VPN登录入口、测试环境等涉密站点。

技术原理：所有HTTPS域名证书都会同步留存至公开透明度日志，无法彻底隐匿。

适用场景：批量发掘未对外公示的子域名资产。

```
curl -s "https://crt.sh/?q=%.auto.htb&output=json" | jq '.[] | select(.name_value | contains("cloudflare") | not) | select(.name_value | contains("mail") | not) | .name_value' | sort -u
```

**命令参数解析：**

* %.auto.htb 模糊匹配该域名下所有子站点
* jq工具过滤云代理、邮件类无关域名，精简有效信息
* sort -u 自动剔除重复数据，输出规整资产列表

**新手实操提醒：** 直接访问证书查询网站会留存本机访问IP，存在溯源风险。 正式测试务必借助匿名网络、代理节点或者境外服务器执行查询操作。

**车企实战应用案例：** 运用该指令检索目标域名，除公开业务站点app.auto.htb外，额外发现隐匿资产client.auto.htb，该设备为C/S架构运维服务端，以此为突破口顺利打通内网渗透通道。

---

**第二式：代码仓库情报挖掘 · 抓取泄露账号与核心配置**

行业普遍现状：开发人员时常误将账号密码、密钥凭证、内网地址推送至代码托管平台。

技术原理：Git版本库会完整留存提交记录，即便文件删除，历史数据依旧可以回溯查询。

适用场景：获取账号密钥、云服务凭证、数据库地址、域服务配置等核心资料。

```
"DB_PASSWORD" extension:env OR extension:yml OR extension:config org:auto-htb -example -test

  path:config extension:properties "jdbc.password"

  "AKIA" AND "auto.htb" language:yaml
```

**检索语句使用技巧：**

* 搭配密码关键词与配置文件后缀，精准定位敏感文件
* 绑定企业组织名称检索，大幅提升情报命中率
* 剔除示例、测试类无效文件，减少冗余干扰信息

**专属实战技巧：定制敏感信息正则匹配库**

* `[a-zA-Z0-9]{20}` 匹配各类云平台密钥凭证
* `10\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}` 筛选内网网段地址
* `password\s*=\s*\S+` 通用匹配明文账号密码

**车企实战应用案例：** 在开发人员个人仓库的注释内容中，检索到内网域服务配置语句： `#LDAP_SERVER=ldap://192.168.10.1:389/CN=Users,DC=auto,DC=htb` 直接锁定域控制器IP与完整服务路径，拿下域渗透关键线索。

**第三式：ASN网段定位 · 摸排云端资产与分支站点**

搜集难点：企业业务分散部署在多家云平台，常规子域名爆破无法全覆盖资产。

技术原理：每家企业对应独立ASN编号，统一管辖名下所有公网IP网段。

适用场景：汇总企业全部公网联网设备，排查游离的影子业务系统。

```
whois -h whois.radb.net " -- -i origin AS13335"

  ipinfo asn AS13335
```

**标准查询流程：**

1. 通过主域名查询企业工商全称
2. 依托企业名称反向检索对应的ASN编号
3. 导出名下所有IP网段，划定精准探测范围

**车企实战应用案例：** 借助ASN归属信息排查，发现车企创新业务板块部署在公有云的独立网关innovation.auto.htb，站点对外开放接口文档页面，存在未授权访问漏洞，可直接调取业务接口数据。

### 1.3 2026 原创技巧 · 红队一线绝密技巧（全网独家）

**✅ 原创声明：以下技巧全部来自真实车企对抗总结**

核心思路：**不发包、不扫描、不爆破、不触发任何AI风控**，纯靠情报狩猎突破。

#### 第四式：DNS 历史记录隐形挖掘（0 发包 · 100% 被动）

**2026 实战原理**：企业测试机、旧服务器、废弃代理、内网穿透节点都会留在 DNS 历史记录中，且**不会被安全设备监控**

```
curl -s "https://dns.bufferover.run/dns?q=auto.htb" | jq -r '.RDNS[] | .[0]' | sort -u

```

**2026 实战价值**：90% 企业会遗漏清理历史解析记录，其中大量存在**测试后台、旧运维入口、未补丁机器、VPN节点**，是真实红队最高命中率入口之一。

#### 第五式：企业工商/备案暗链挖掘（车企 100% 有效）

**2026 车企专属技巧**：车企、重工、制造类企业官网、供应商系统、车联网平台都会在工商/备案信息中留下**未公开运维域名**


**真实战果**：2026 实战中，80% 车企边界突破点来自**供应商、分公司、备案遗留域名**，而非主站。

#### 第六式：AI 风控专用 · 超低熵目录探测（不会被拉黑）

**2026 原创核心**：传统目录爆破 404 过多 = 直接拉黑超低熵探测 =**只访问人类可能点击的路径**，AI 判定为正常用户行为。

```
curl -s -o /dev/null -w "%{http_code}" "https://app.auto.htb/actuator/health"
  curl -s -o /dev/null -w "%{http_code}" "https://app.auto.htb/api/docs"
  curl -s -o /dev/null -w "%{http_code}" "https://app.auto.htb/.well-known/openid-configuration"
```

**原创规则**：每次只访问 3–5 个路径，间隔 3–5 秒，UA 伪装成手机浏览器，完全模拟人工点击，**2026 所有 AI 风控都无法识别**。

#### 第七式：车企影子资产定位法（2026 独家）

**实战逻辑**：车企一定存在：车联网平台、TSP 平台、充电桩管理、供应商系统、测试车后台、OTA 升级服务器这些资产

**不会出现在主域名，却一定能被情报检索到**

```
site:auto.htb "tsp" OR "ota" OR "vehicle" OR "charge" OR "v2x"
  intitle:"车联网" site:auto.htb
  intitle:"供应商" site:auto.htb
```

**2026 实战结论**：车企主站几乎无漏洞，**车联网/OTA/充电桩类影子资产漏洞命中率 > 70%**。

### 1.4 可控主动扫描：低速低噪，精准核验资产

**🚨 为什么 2026 年不能用“常规主动扫描”？深度论证**

1.**发包频率异常**：AI 已学习正常业务流量，批量扫描的发包密度直接判定为攻击

2.**无业务语义**：正常访问是有序的，扫描是无序的，行为模型一眼识别

3.**特征指纹入库**：Nmap、Masscan、FFUF 等工具指纹被全网拉黑

4.**全域联动封禁**：边界 → 内网 → 终端 → 云端一键拉黑，一次扫描终身拉黑

**唯一出路：极小范围、极低速、极精简、模拟正常业务的可控探测。** 完成无源情报搜集后，即可整理出初步资产清单。主动扫描不以大范围探测为目的，仅针对目标设备做服务版本与端口状态核验。

```
sudo nmap -D RND:10,ME -T2 --max-retries 0 --min-rate 10 -p 80,443,8080,8443 -Pn -sS -iL target_ips.txt -oA stealth_scan

  sudo nmap -sI zombie_host:80 target_host

  masscan 192.168.0.0/16 -p443 --rate=10000 -oJ - | jq -r '. | select(.ports[].port==443) | .ip'
```

**扫描参数设计思路解读：**

* -T2 调低扫描速率，规避流量异常告警
* --max-retries 0 关闭数据包重传，弱化扫描特征
* -D RND:10 伪造随机源地址，隐藏本机真实IP
* -sS 采用半开放扫描模式，不建立完整网络连接
* 仅筛选业务高频端口，舍弃无价值端口探测

**车企实战应用案例：** 对app.auto.htb:8080端口探测，识别出服务器为Tomcat服务。通过目录爆破工具扫描，发现未授权访问接口/api/user/list，页面返回Base64编码字符串YXBwQDEyMw==，解码后获取登录账号appuser与对应密码app@123，拿到调试预留的系统后门权限。

#### 阶段二：Web服务权限控制

**原有理想打法**：上传专用WebShell工具，直接调用命令行执行系统指令

**重构真实打法**：无文件内存反射注入，寄生Web容器进程运行
