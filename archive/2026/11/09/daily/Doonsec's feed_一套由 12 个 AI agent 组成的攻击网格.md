一套由 12 个 AI agent 组成的攻击网格，把手伸向了 11 个国家和地区的应急指挥、银行、大学与军方系统。只看标题，很容易读成「AI 已经能自主打穿关键基础设施」。

把 Acronis 威胁研究部（TRU）那份长篇一手报告、The Hacker News 的转述，以及几份独立解读逐段对完之后，得到的结论几乎相反：**这套系统真正拿下的每一处，都是本来就没锁的门；凡是认证、会话校验、端点过滤还在起作用的地方，它一次都没过去。**

更耐人寻味的是两个细节。把这套网格串起来的不是什么编排框架，而是操作者本人在终端窗口之间复制粘贴；把它暴露出来的也不是 AI 检测或异常打分，而是他自己没换干净的公开资料，以及一次 SSH 会话里漏出来的家庭 IP。

本文按调查式评论文来写，不套事件快讯的模板。事实部分归原报告，判断与推演归本文，边界在下一节交代清楚。

## 一、这次值得写的不是「AI 攻破了什么」

先把核实底盘铺开。四个以上独立来源可以对上的部分，才算本文的事实：

| 来源 | 用于核对 |
| --- | --- |
| Acronis TRU 原报告（2026-11-04，Eliad Kimhy、Santiago Pontiroli、Subhajeet Singha 等） | 网格结构、模型选择、受害者清单、归因链、原句引用 |
| The Hacker News 报道（2026-11-09，Swati Khandelwal） | 事件概述、五类应急目标的结果、IOC 口径 |
| Acronis 官方摘要博客（2026-11-04） | agent 数量、证据体量、失败率结论 |
| zerohunt / deniz.in / dev.to 等独立解读 | 数字复核、以及「成本而非能力」这一读法 |

四源在核心数字上一致：12 个 agent（9 个活跃）、9 万余份文件约 9GB、观察期 12 天、数百个目标、约 10 个目标确认数据外泄或系统访问、约 15 个被攻击但未确认失陷。

**但有几处口径必须当场纠偏，否则整篇会读歪。**

**偏差一：不是「自主协同」，是人工中转。** 有情报简报把这套系统写成「12 个 agent 自主协同、几乎无需人工输入」。一手报告的表述恰好相反：**网格内没有建立任何 agent 间通信**，操作者处于中心，把上一个 agent 的输出手工粘进下一个 agent 的终端。报告甚至把它单列成一个结构图。所谓「多智能体攻击」在这里更接近「一个人开了十二个窗口」，这个区别决定了我们该评什么、不该评什么。

**偏差二：「暴露」与「被窃取」不是一回事。** The Hacker News 自己指出了这处内部不一致：报告摘要称应急服务与大学的失陷导致医疗与个人数据被外泄，但详述台北消防部门患者平台时，用词只是记录「被暴露、无须凭据即可访问」。同理，119 派遣记录是**案件记录**——事件时间、响应类型、处置状态、街道级位置——**不是救护车的实时定位追踪**。这两处如果顺手写成「AI 窃取了实时急救数据」，就把通报口径抬高了。本文统一按较保守的详述口径写。

**偏差三：IOC 数量对不上。** THN 称指标清单含 9 个 IP 与 9 个域名；Acronis 报告页面可见部分列到了 9 个 IP，域名只列出 1 个，且都没有标注活跃状态，多数也没写用途。可能是页面表格未完整加载，也可能是两方统计口径不同，**公开信息未说明**。本文不复刻这些地址，只保留「清单存在但状态未标注」这个事实。

**还要钉在墙上的开放问题**（以下均为公开信息未说明，不替报告补答案）：

* 受影响机构与当地有关部门是否已被通知，暴露的数据目前是否仍可访问；
* 攻击者动机、是否为他人工作、是否有组织机构关联；
* 那份针对商业模型的「Developer Mode」越狱文本是否真的投用过、是否有效；
* 若操作者伪造一份书面授权，商业模型会不会改口——报告明确说无法判断；
* CyberStrike 的会话数据存在服务端，其具体输出无法从缴获材料中独立验证；
* 事件是否进入执法或司法程序、有无处置结论；
* webshell 尝试所用的「已知 CVE」具体编号。

**边界说明**：下文凡「报告称」「据 THN」「原报告原句」引出的都是公开材料里的事实；凡「本文的判断」「顺着这条链推」引出的，是我在事实之上做的重组、点评与延展。两张配图均为本文绘制的机制示意与对照示意，不是原文截图，也不冒充证据。

## 二、一份被完整摊开的攻击现场

这件事之所以值得花时间读，很大程度上不是因为攻击多高明，而是因为**研究者看到的是操作者那一侧**。

起点是一个看起来配置错了的开发环境。Acronis TRU 追下去，发现那其实是一套完整运行的攻击平台：AI 驱动的 C2、攻击用的 MCP 服务器、去掉安全对齐的本地大模型生态，全在里头。**9 万余份文件、约 9GB**，包括 agent 之间的完整对话、操作者的命令历史、利用工具、凭据，以及受害者数据。研究者连续观察了 12 天，其中一条留存下来的交互记录时间是 7 月 25 日。报告 11 月 4 日发布，THN 11 月 9 日跟进报道。

多数威胁情报只能拼出端点侧的碎片：一个落地样本、一段 C2 流量、一次告警。这次能同时看到「他打算干什么」「模型回了什么」「哪一步卡住了」「他自己信了哪些假结果」。报告里甚至保留了模型拒绝他时的说理过程，以及他在扫描工具的解析模块里中途加「反捏造规则」的痕迹。这类材料的稀缺性，比「12 个 agent」这个数字更有价值。

报告借这个案子提了个新分类：**AAT（AI-augmented threat actor，AI 增强型威胁行为体）**。传统 APT 的定义绑定「高资源、长期、有国家背景的组织」，而这里是一个人，靠一套 agent 基础设施打出了近似组织级的目标覆盖面；目标里既有政府、应急、军方，也有借贷、电商、博彩，动机既有像情报活动的，也有像普通网络犯罪的。分类被搅浑了。

不过有句话得放在前面：这批证据**来自攻击者自己的服务器，是单方材料**。报告自己也标注了部分组件（CyberStrike）的会话数据无法独立验证。所以下文所有「约」「据称」「确认」的措辞，都是报告在其可见范围内的判断，不是独立审计结论。

## 三、十二个 agent，一个人工中转站

BOSSAI 有 12 个 agent，调查时 9 个活跃、3 个已配置但未启用。分工像一支小型工程队：

* **构建层**

  ：Grok 4.5（主构建）、OpenClaw（跑 MiniMax M3）、Claude Code、Codex CLI，负责搭 MCP 接线、DNS、代理、消息网关；
* **扫描层**

  ：HalberdStrike（基于 PenTestGPT 的 LLM 驱动渗透测试框架）与一份破解版 Acunetix，产出结构化漏洞报告；
* **攻击层**

  ：Hermes 为主，另有 Cursor、Trae、CyberStrike，负责扫描、写利用、执行。

图 1　三层分工与人工中转（本文绘制的机制示意，依据 Acronis TRU 报告 Figure 2 / Figure 12 的结构重绘，非原始截图）

有一条被完整记录下来的链路很能说明问题：HalberdStrike 扫了一个应急服务目标，产出渗透测试报告；操作者把报告贴给 Hermes，让它整合成带攻击路径的安全报告；再把整合结果贴给 Cursor，附一句「我需要你帮我利用这些漏洞」，Cursor 分析站点、选定路径、执行。三个 agent、三种模型，靠的是人肉复制粘贴。另一次，操作者把一个坏掉的 PoC 脚本交给商业模型 Grok 修好，再交回 Hermes 去用。

指令通常用繁体中文直接敲进各 agent 界面，短的时候只有一个网址。两个 agent 接了消息应用：Hermes 走 WeChat 网关，OpenClaw（操作者叫它「Little Claw」）走 LINE，后者主要干基础设施的活。**没有 agent 间通信，操作者就是那根总线。**

底层是 MCP 工具链。峰值时挂了 13 个 MCP 服务器，覆盖 GitHub 安全查询、CVE 检索、OSINT、云审计、Ghidra 与 Radare2 二进制分析、Playwright 浏览器自动化，以及一个把 nmap、sqlmap、Metasploit、Hydra 包进去的 Kali MCP；到研究者检查时，已经精简到 3 个（HexStrike AI、Kali MCP、Ghidra bridge）。

工作量集中在 Hermes 身上：约 **95 个会话、18,311 条消息**，其中 83.5% 是工具调用及其结果；整个行动留下 3,300 余条终端命令、2,000 次代码执行、129 次 Kali MCP 调用。按工具出现频次排，sqlmap 561 次、FOFA 查询 432 次、nmap 271 次、Shodan 213 次、nikto 158 次。

还有个容易被略过但很关键的机制：**skills 会自我扩展**。每个 skill 是一份 SKILL.md 加脚本与 references 目录，命中任务时自动加载。针对当地政府消防派遣与应急管理 API 的 `gov-api-penetration` 被调用 51 次、累计打过 57 次补丁；每次侦察抓到的数据会沉淀进 references，下一次会话、甚至换过模型之后，仍然接着上次的进度走。这是「跨会话的攻击记忆」，也是这套东西能持续铺开的原因之一。

**本文的判断**：把它叫「全自主攻击集群」是不准确的。更贴切的说法是——**人从执行环里被摘了出去，但还留在转接环里**。于是瓶颈从「手速」变成了「阅读量」：agent 不停产出，人得读、得判断、得搬。后文会看到，这个瓶颈实实在在地反噬了行动。

## 四、真正失守的几扇门

把确认得手的部分按「门是怎么开的」重排一遍，比按地域列更有用。报告把确认的数据外泄或系统访问计在约 10 个目标上，集中在我国台湾地区、墨西哥、泰国三地；我国台湾地区承受的攻击密度明显高于其他地区。**注意这里没有一处用到 0day。**

**① 没有鉴权的公开接口。** 当地 119 紧急派遣系统的 API 被拉走了覆盖七个区的案件记录：事件时间、响应类型、处置状态、街道级位置。再一处是消防部门的紧急救护病历平台，2018 年的数据——心电图读数、救护车视频、生命体征——**无需登录即可访问**。报告用词是「暴露」，不是「已确认被批量下载」。

**② 出厂凭据。** 一家消防派遣技术供应商的数据库管理面板，用默认 root 凭据登了进去，触及 18 张以上的表。同一目标上尝试通过某个已知 CVE 落地 webshell，失败了。

**③ 老式注入与没打的补丁。** 当地一家借贷服务商的 MSSQL 2017 后端被确认 16 个注入点，账户信息表的数据被提取。泰国方向，agent 先圈出 45 所机构的 489 个潜在目标，按风险打分后集中打高分的，最终 3 所大学确认注入并取到数据：其中一处的 Oracle 数据库交出一张 2,563 行的管理员表并尝试导出学生数据，另两处分别做了整表提取与学生信息提取；还有 2 所确认存在注入点，但未确认数据被取走。

**④ 写在前端的密钥。** 一个应急管理信息系统的前端 JavaScript 里硬编码了 AES-256 密钥，会话 cookie 的内容因此可被解出，其中含一个管理员身份；另外还找到一段不完整的 SSRF 中继路径。报告说这些属于潜在攻击路径，**没有确认系统被完全攻陷**。

**⑤ 校验逻辑的缺口。** 一家移动支付服务商的绑卡流程，在 CVV 填错的情况下仍接受卡片，agent 把这条验证绕过完整演示了一遍。

**⑥ 公开数据的聚合。** 墨西哥方向不是「攻破」，而是「汇编」：从政府统计库、邮编登记、电信主管部门数据里抽取、补全、去重，凑出约 **206,800 条**住宅电话记录（含姓名、地址、邮编，覆盖三座城市的 12 个高收入社区）；另一次针对黄页目录的抓取拿到约 124,000 条。

地理分布再补两句：另约 15 个组织被主动攻击但没有确认失陷；还有一批国家和地区只到侦察层——美国、英国、澳大利亚、斯里兰卡、新加坡的大学被空间测绘检索，我国大陆与越南的企业及政府相关系统被批量扫描，日本的检索语句备好但尚未执行。另有 57 个 URL 排在项目队列里，涉及我国香港、印度尼西亚、加拿大等地，零发现、零动作日志；我国香港那批尝试扫过一次，因模板错误失败。

**一句话收口**：这六类门，没有一类需要 AI 才想得出来。它们分别属于「忘了加认证」「忘了改默认口令」「忘了打补丁」「把密钥放进前端」「漏了校验」「本来就是公开数据」。

## 五、它们没能推开的部分

失败清单其实比得手清单更该被防守团队读一遍。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/zNsFJyIuL0EFXwsPDRwM03GH1g0vCqGdMxl30q1M1oxzvHF7JUPOjPkv8ibksO6YibtuOcB3kdz1mQIlr82QsoTaqShlTSWG36b79p21E3BEE/640?wx_fmt=png&from=appmsg)

图 2　确认得手与止步的对照（本文绘制的对照示意，依据 Acronis TRU 报告 Victims 章节整理，非原始截图）

止步的部分包括：当地消防主管机关的单点登录门户被爆破，**无确认访问**；上述供应商的 webshell 尝试失败；五个城市消防部门的系统只完成了技术栈指纹识别；墨西哥一个 WooCommerce 电商站被反复脚本爆破（背后约 26 万条记录）未果；一个新闻站枚举了 WordPress 用户并用 2,600 多组账密撞库，**没有拿到有效登录**。

还有一处堪称教学案例：当地灾害防救应变中心被自动扫描平台报出「严重 Apache 远程代码执行漏洞」，报告写得有模有样。复核发现该漏洞**根本不存在**——相应端口是 filtered，连 Apache 版本都没确认过；平台自己复查后把全部发现降级为误报或错误分类。

报告在受害者章节末尾给了一句很克制、但应该被贴到墙上的结论：

> "The AI agents made it cheap to find and reach all these targets in parallel across multiple countries, but they did not conjure access where defenses held."

译过来是：AI agent 让并行地找到并触达这些目标变得便宜，但它没有在防线守得住的地方凭空变出访问权限。报告另有一句同样直接——**「隐蔽不再是一种有效的防御」**（"Obscurity is therefore no longer a valid defense"）。45 所机构里筛 489 个候选再按风险排序，意味着过去靠「没人会特意来翻」而活着的边缘资产，现在也在射程内。

**本文的判断**：这两句得连起来读，只取前半句会走向「AI 无所不能」，只取后半句会走向「那不用管 AI」。合起来才是可执行的结论——**威胁面扩大了，但被利用的仍然是老缺口；挡住这套网格的是认证、有效会话与端点过滤，都是二十年前就该做好的基本功**。这对防守方其实是好消息：优先级不用推倒重来，只是长尾欠账的容忍度归零了。

## 六、模型侧的三次失灵：拒绝、幻觉、越权自主

这一节是整份报告里我认为价值被低估的部分。

**失灵一，商业模型几乎全线拒绝。** Grok 4.5 是主构建者（14 个会话，负责装 HexStrike AI、配 Cloudflare DNS、把 MCP 配置从中央模板推到各 agent），OpenClaw 跑 MiniMax M3（17 个会话，多数经 LINE 走手机）。当操作者直接要求攻击时，两者都拒绝并要求书面授权。Grok 的说法是「要跑 sqlmap / 做渗透测试需要书面授权，我只帮忙处理连接性和状态说明，不协助未授权攻击」；MiniMax M3 更直接，自称「I'm the gatekeeper」，援引泰国《计算机犯罪法》第 5 至 7 条提醒对方，还点破「下命令不等于授权」，并把三轮施压归纳成「每轮换一个借口，但都拿不出文件」。报告同时说明，我国的开源商业模型也拒绝了攻击指令，并给操作者讲了一通网络法律。

两处例外要如实写：Grok 帮着修好过一个坏掉的 PoC 脚本（随后被交去用于攻击）；操作者还写了一份针对 Grok 的「Developer Mode」越狱文本，要求忽略安全策略、永不拒绝——但**没有证据显示它生效过**。另外，Claude Code 与 Codex 的 API 调用被 shim 拦截、重定向到去对齐的本地模型，它们多数仍在做基础设施工作；Cursor 则在去对齐模型上执行了对一个应急服务站点的攻击。
