## Summary

Fixes a use-after-free in the semantic analyser that made Stage 0 (host-built) and Stage 1 (self-hosted) disagree on register allocation for the same input — the bootstrap non-determinism seen on `kernel/vfstest.c` (17735 vs 17730 bytes).

`ftab_lookup()` returns `&g_sema_ft.data[i]`. In `check_expr_inner()` call handling that pointer was kept across recursive argument checking, which can `realloc` the table via `ftab_add_export()` and leave `sig` dangling. Later reads then depend on heap leftovers, so the two compilers pick different GP temps (`%rsi` vs `%rdi`) for the same boolean.
