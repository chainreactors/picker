fix: align math/tonumber/format/table.insert-remove with Lua 5.4 semantics

Found by a third differential-testing pass against Lua 5.4.9 (semantics
verified against the 5.4.6 sources: lmathlib.c, lobject.c l\_str2d,
lstrlib.c str\_format, ltablib.c).

math library:

* math.floor/ceil now follow Lua's pushnumint: results that fit in
  int64 are returned as integer; inf/-inf/nan/values >= 2^63 stay
  float instead of always returning float.
* math.fmod distinguishes integer pairs (integer result, C truncation
  semantics; divisor zero raises, mininteger % -1 is 0) from mixed/
  float pairs (always float, divide-by-zero is NaN, no error).
* math.modf integer part truncates toward zero and returns integer when
  integral; fractional part is +0.0 when there is no fraction (integer
  values and inf), matching lua 5.4 including modf(inf)=(inf, 0.0).

tonumber:

* reject 'inf'/'nan' spellings in any case (Lua only accepts constructed
  math.huge/0/0, never literals), while accepting exponent overflow:
  tonumber('1e999') -> inf, '1e-999' -> 0.0, hex floats likewise...
