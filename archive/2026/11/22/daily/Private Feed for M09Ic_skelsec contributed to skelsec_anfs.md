## What is in it

**Protocol**

* NFSv4 client: 4.0, 4.1 and 4.2 (`version=4.0` / `4` / `4.2` in the URL), SECINFO, ACLs (`get_acl` / `set_acl`)
* RPCSEC\_GSS: `krb5`, `krb5i`, `krb5p` on top of asyauth, for NFSv3 and NFSv4, TCP and UDP
* UDP transport, configurable ports (`nfsport`, `mountport`, `portmapport`), AUTH\_SYS parameters (`uid`, `gid`, `gids`, `machinename`) in the URL
* `write_file`, `upload_file`, `download_file` and `set_credential` on both clients

**Tools**

* `anfsanalyze` / `anfsscan`: security checks of an NFS server (exports, export escape, root squash, uid spoofing, write access, NFSv4 namespace, exports with different rules over v3 and v4). Only `--check-no-root-squash` writes to the server.
* `anfsclient`: `put`, `putdir`, `cat`, `mv`, `chmod`, `chown`, `stat`, `whoami`, `su`, `getacl`, `setacl`

**Fixes**

* NFSv3 `readdir` returned the first page only
* `download_file` (`get`, `getdir`) stopped after the first chunk
* NFSv3 `setattr` reset the timestamps
* NFSv3 `write`, `setattr`, `mknod`, `link`, `commit` did not report NFS errors
* `touch` over NFSv3 created files with mode 0000

**Testing**

* `lab/`: docker lab with the Linux kernel NFS server, NFS-Ganesha and an MIT KDC, see `lab/README.md`
* `python3 -m pytest tests -p no:randomly` against the lab: 428 passed, 6 skipped, 3 xfailed
