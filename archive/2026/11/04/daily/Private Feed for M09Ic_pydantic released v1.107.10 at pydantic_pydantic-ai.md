## What's Changed

### 🛡️ Security

* [GHSA-m5vj-8mcw-82qx](https://github.com/pydantic/pydantic-ai/security/advisories/GHSA-m5vj-8mcw-82qx) (high): `web_fetch_tool` and the `WebFetch` capability's local fallback re-indented a JSON response on the event loop before applying the returned-content limit, so a deeply nested document within the download size limit could expand to hundreds of times its size, using large amounts of memory and delaying other work in the same process. You are affected if an attacker can choose or influence the URLs the tool fetches. Provider-native web fetching is not affected. Fixed in v1.107.10 and v2.66.0 (`pydantic-ai`, `pydantic-ai-slim`).
* [GHSA-5fj9-5pjw-vpwc](https://github.com/pydantic/pydantic-ai/security/advisories/GHSA-5fj9-5pjw-vpwc) (medium): The cloud-metadata blocklist that URL downloads check did not include Tencent Cloud's instance metadata address `169.254.0.23`, so someone who can supply a URL the application downloads could have it fetch the instance's temporary role credentials. You are affected if you run on Tencent Cloud and allow local URLs, through `force_download='allow-local'` on a `FileUrl` or `web_fetch_tool(allow_local_urls=True)`. Fixed in v1.107.10 and v2.66.0 (`pydantic-ai`, `pydantic-ai-slim`).
