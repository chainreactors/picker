## What's Changed

### ⚠️ Compatibility Notes

* Keep workspace files below `'operator'` authority out of the instructions in `RepoContext`, `Skills` and `Memory`, and add `lowest_authority_under` by [@adtyavrdhn](https://github.com/adtyavrdhn) in [#11837](https://github.com/pydantic/pydantic-ai/pull/11837)
  + Text from a workspace file below `'operator'` authority no longer reaches the instructions: `RepoContext` names the working directory's file for the model to read with its file tools and sends an ancestor's file as framed data, `Skills` offers such skills through `list_skills` and `load_skill` tools instead of `load_capability`, and `Memory` attributes such a snapshot to its `MEMORY.md`. Files at `'operator'`, the default, are unchanged. Durable runs now record extra `realpath` workspace calls at run start, so let in-flight runs finish, or use Temporal worker versioning or a new DBOS app version, before upgrading. `RepoContext(autoload_instructions=False)` with nested instruction files misses the prompt cache once on the first request after upgrading.
* Raise empty and unreadable model responses as `ModelEmptyResponseError` and `ModelInvalidResponseError`, so `FallbackModel` and `ModelFallback` fall back on them by [@DouweM](https://github.com/DouweM) in [#12108](https://github.com/pydantic/pydantic-ai/pull/12108)
