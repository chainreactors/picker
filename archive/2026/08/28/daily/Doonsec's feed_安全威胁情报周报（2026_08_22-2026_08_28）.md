微软8月补丁星期二修复400+漏洞 含Lazarus组织在野利用零日

**微软于2026年8月15日发布了月度补丁星期二安全更新，修复了其产品组合中超过400个安全漏洞，其中包含至少42个严重级别漏洞。此次更新覆盖了Windows操作系统、Azure云服务、Exchange服务器、SharePoint协作平台等广泛产品线，影响范围极为广泛，安全团队需优先安排紧急修补工作。**

![](https://mmbiz.qpic.cn/mmbiz_png/IFwQhmKAhyLgoTCKJdZbyqc6fXkoarrTrMCBWH8gW9lxCN1iaCbAe9u2FpZgFBQzmE7gMn6lB5PtiaWeSysn8qR8Y60OvHM3ibWNPdYDlcKvkQ/640?wx_fmt=png&from=appmsg)

*图：示意图*

最紧迫的问题是零日漏洞CVE-2026-68820的修复，该漏洞是Windows Ancillary Function Driver for WinSock（afd.sys）中的一个use-after-free漏洞，CVSS评分为7.0。Check Point安全研究人员已将此零日漏洞的在野利用归因于朝鲜国家支持的威胁组织"Lazarus Group"。Lazarus Group在"Operation Dream Job"活动中使用此漏洞部署了FudModule内核级rootkit，以获得SYSTEM级权限、维持持久化访问，并禁用EDR安全解决方案。这意味着攻击者可以在目标系统上实现最高权限控制，同时绕过所有端点检测响应工具的监控。

此外，微软还修复了其他值得关注的漏洞，包括Windows DNS Server中可能导致远程代码执行的可蠕虫化栈溢出漏洞CVE-2026-62878，以及Windows用户配置文件服务中的权限提升漏洞CVE-2026-62832。CVE-2026-62878作为可蠕虫化漏洞，意味着攻击者可以无需任何交互即实现远程传播，在大型企业内部网络中具有极高的横向移动风险。安全团队应优先修复此被在野利用的零日漏洞和其他未认证的关键漏洞，加速终端部署并监控权限提升活动。

CVE-2026-68820被Lazarus Group在野利用的事件具有重要的战略安全意义。朝鲜关联的Lazarus Group长期以来专注于金融盗窃和加密货币攻击，此次将其攻击焦点转向政府和企业系统，可能反映了朝鲜在制裁压力下对高价值网络资产的新型战略需求。

安全分析人士指出，FudModule内核级rootkit的部署表明Lazarus Group在Windows内核安全领域的技术能力已达到相当高的水平，能够对抗主流EDR产品。对于仍在使用Windows系统的组织而言，这不仅是紧急修补问题，更应审视整个端点安全架构是否具备检测和清除内核级威胁的能力。

Oracle发布943个安全修复 含WebLogic严重远程利用漏

**Oracle于2026年8月下旬发布了大规模安全更新，修复了其产品组合中多达943个安全漏洞，这是Oracle历史上规模最大的单次安全修复之一。其中Fusion Middleware组件单独获得了262个修复，包括182个可在无需身份认证的情况下远程利用的漏洞，影响范围极为广泛，这些未认证可远程利用的漏洞意味着攻击者可以直接从互联网发起攻击，无需任何凭证。**

![](https://mmbiz.qpic.cn/mmbiz_png/IFwQhmKAhyJgJticvnyqArm1t5O8uW2x6ictx5AGtbnibMibqdqHkGJxPtypLGnEjDtgNG56Xknhkc6rQL1ibcssunlOiapWuobibMVhKaEOZF6YH0/640?wx_fmt=png&from=appmsg)

*图：示意图*

在已披露的漏洞中，影响Windows虚拟机的严重漏洞CVE-2026-21962被美国CISA列入已知被利用漏洞目录（KEV），CISA下达了最紧迫的三天修复期限。该漏洞允许攻击者创建、删除或修改关键数据访问权限，甚至完全访问受影响系统上的所有数据，已被证实遭到活跃利用。CISA对KEV漏洞设定如此短的修复期限，表明该漏洞已被大规模武器化并正在被积极利用。

Oracle建议管理员优先对面向互联网的系统进行排查和修复，尽快测试并应用相关补丁。对于大型企业而言，Oracle Fusion Middleware和WebLogic广泛应用于企业核心业务系统，承载电子商务、客户关系管理、供应链管理等关键业务应用。如此大规模的漏洞批量修复凸显了企业级中间件在安全治理中的重要性，企业需要建立自动化漏洞管理和补丁分发机制，以应对供应商大规模漏洞发布的挑战。

Oracle此次943个漏洞的集中修复给全球企业IT运维团队带来了巨大压力。大型企业通常需要数周甚至数月来测试和部署Oracle补丁，尤其是在金融、电信等对系统稳定性要求极高的行业。

CISA对CVE-2026-21962设定的三天修复期限在实操层面几乎不可能完成，这意味着许多受影响的系统将在修复期限内持续暴露在攻击风险之中。

安全专家建议，在正式补丁部署前，应立即对面向互联网的Oracle系统进行网络隔离，部署基于行为分析的入侵检测系统，并加强审计日志监控以识别可疑的访问尝试。 从漏洞管理和企业安全的角度来看，Oracle大规模补丁的发布对企业IT运维构成了持续性的挑战。

大型企业在测试和部署补丁时需要平衡系统安全性和业务连续性，特别是在金融交易系统、电信核心网等不能轻易中断的场景下，补丁部署往往需要数周的变更管理周期。安全专家建议企业建立分层补丁管理策略：对面向互联网的关键系统优先部署紧急补丁，对内部系统按风险等级分批部署，同时对无法及时修补的系统部署网络隔离和入侵检测作为临时补偿措施。

GitLab严重GraphQL漏洞遭在野利用 PoC已公开

**GitLab修复了一个被评定为CVSS 9.4分的关键GraphQL漏洞（CVE-2026-19478），该漏洞允许未认证的攻击者在自托管的GitLab Community Edition和Enterprise Edition实例上修改或删除公开项目以及用户数据。安全公司已经观察到针对此漏洞的在野利用尝试，表明攻击者已将该漏洞武器化，PoC代码也已公开在安全社区，进一步降低了攻击门槛。**

![](https://mmbiz.qpic.cn/sz_mmbiz_png/IFwQhmKAhyKRSak3wLibKNU7icBmg6HOBkoPyl4tuMj4eokxqj2om0qYjXdkYCXosyVpbCVjibbEst2AdDgOnickBeS1ictR5gG7eOGptfY9GEvQ/640?wx_fmt=png&from=appmsg)

*图：示意图*

受影响的管理员应立即升级GitLab实例，审计公开项目的变更日志，审查受影响用户的数据完整性，并调查异常的GraphQL请求。此外，此漏洞可能与其他GraphQL相关安全缺陷形成组合攻击链，进一步放大对代码托管平台和企业DevOps基础设施的威胁。GraphQL接口的灵活性在提供强大查询能力的同时，也为复杂的访问控制逻辑带来了额外的挑战，使得该类漏洞的检测和防护难度高于传统REST API。

GitLab作为全球广泛使用的代码托管和DevOps平台，被数千家企业和组织用于管理源代码、CI/CD流水线、项目管理等核心开发流程。其漏洞的利用可能影响企业源代码管理、CI/CD管道和存储在其中的敏感数据资产，包括API密钥、数据库连接字符串、访问令牌等。安全团队应将其视为高优先级紧急修复对象，同时对所有GitLab实例进行暴露面审计。

GitLab的GraphQL漏洞是DevOps工具链安全风险的又一个典型案例。GitLab实例通常承载着企业的源代码、CI/CD构建配置、容器镜像注册表、以及大量的API密钥和访问令牌等敏感资产。一旦实例被攻破，攻击者不仅可以窃取现有数据，还可以利用CI/CD管道在构建过程中植入后门，实现对企业软件供应链的长期渗透。GraphQL接口的灵活查询能力使得攻击者可以通过精心构造的查询请求遍历大量数据，而传统的API安全测试工具往往无法覆盖此类复杂的GraphQL查询模式。

**应急处置建议**

1. 优先升级：自托管实例立即升级至对应安全补丁版本；

2. 临时缓解（暂时不能升级时）：WAF 拦截`/api/graphql`接口中包含`@gl\_introduced`的请求；限制外网直接访问 GraphQL 接口，仅内网可信地址放行；

3. 审计检查：

   - 查看 GitLab 日志：`gitlab-rails/production.log`，重点排查未认证来源调用 GraphQL 发生项目删除、用户 ban 操作记录；

   - 核查公开项目、用户账号是否存在异常删除、禁用；

4. 备份加固：做好仓库完整备份，开启项目操作审计日志；

5. 收敛暴露面：非必要不将 GitLab 直接暴露互联网。

NetScaler CVE-2026-19490身份认证绕过漏洞 CVSS 9.3

**Citrix NetScaler ADC和Gateway系统曝出一个CVSS评分为9.3的严重身份认证绕过漏洞（CVE-2026-19490），远程攻击者可利用此漏洞绕过身份验证，获取对受影响设备的未授权访问权限。NetScaler同时还发布了针对CVE-2026-19489拒绝服务漏洞的补丁，该漏洞允许攻击者通过构造特制请求使NetScaler设备无法正常服务，造成拒绝服务影响。**

![](https://mmbiz.qpic.cn/mmbiz_png/IFwQhmKAhyJ3DQegTxHbOPBrcUiapLWA3R8dmhAD741k5v0cG5yhp9AvM98wYzAr3l7ictUqIOKZBOIibRvoC21mYb2L0wGbAcVOw8PHjf8a2o/640?wx_fmt=png&from=appmsg)

*图：示意图*

NetScaler产品作为企业VPN和远程访问网关，被全球众多组织用于保护内部网络资源和远程办公访问。认证绕过漏洞一旦被利用，攻击者即可绕过正常访问控制，直接获取对内部系统的访问权，可能进一步横向移动至企业核心资产，包括文件服务器、数据库和应用系统。该漏洞的严重性在于，它不需要任何初始认证信息即可利用，攻击者可以从互联网直接发起攻击。

安全团队应立即对暴露在外的NetScaler设备进行清查，安装相关修复，限制不必要的外部访问，并审查认证和网络日志中的可疑活动。NetScaler产品线历史上曾多次曝出严重安全漏洞，企业应对该类产品保持高度警惕，建立完善的产品生命周期管理和漏洞跟踪机制，确保安全补丁及时部署。

NetScaler身份认证绕过漏洞的危险性在于其影响的广泛性。NetScaler作为Citrix企业级虚拟桌面和远程访问的基础组件，被全球无数企业用于构建VPN网关和远程办公入口。该漏洞一旦被利用，攻击者可以绕过所有身份验证控制，直接获取对企业内网的访问权限，包括文件共享、数据库、邮件系统和内部应用。

**应急处置建议**

1. 优先升级，将 NetScaler ADC/Gateway 升级至官方安全补丁版本。

2. 临时缓解（无法立刻升级）

   - 收敛外网暴露面，非必要不把 Gateway/AAA 直接暴露互联网；

   - WAF 拦截异常路径特征请求；收紧源 IP 访问策略，仅可信 IP 段访问 VPN 网关；

   - 核查 SAML 配置，新版本若业务允许可临时移除未使用 SAML Action 配置，消除利用条件。

3. 安全审计排查

   - 查看`/var/log/ns.log`，审计异常未认证会话、陌生源 IP 直接访问 VPN 资源日志；

   - 检查是否存在未知会话、异常登录、新增账号；

   - 核查内网是否出现陌生主机访问痕迹。

4. 加固基线：开启网关操作审计日志；定期备份配置文件。

NetScaler的安全漏洞问题并非孤立事件。过去几年中，NetScaler产品线曾多次曝出严重安全漏洞，包括2023年的多个高危远程代码执行漏洞。这种反复出现的安全问题反映了虚拟网关类产品在安全设计上的系统性挑战：这些产品需要同时处理来自互联网和内部网络的流量，必须具备复杂的多认证协议支持，其代码复杂度和攻击面远大于普通应用服务器。

安全行业专家呼吁NetScaler用户不仅要安装每一次安全补丁，还应从架构层面考虑是否需要保留面向互联网直接暴露的部署模式，能否通过前置反向代理、Web应用防火墙和零信任网关等替代架构来降低NetScaler的直接暴露风险。

CISA将Zimbra ZCS OS命令注入漏洞列入KEV目录

CISA将漏洞列入KEV意味着该漏洞已被确认在现实攻击中被利用，联邦民用机构必须在限定时间内完成修复，否则将面临合规问责。此外，同期被CISA列入KEV的还包括TrueConf Server的身份认证缺失漏洞（CVE-2026-72529），该漏洞允许远程攻击者通过TCP端口4307执行任意脚本，攻击者可以利用该漏洞完全控制受影响设备。

Zimbra作为一个开源协作平台的商业发行版，其用户群体分布广泛，包括学校、非营利组织、中小型企业和政府机构，其中许多组织缺乏专门的IT安全团队，是本次漏洞攻击中最脆弱的群体。

安全社区呼吁所有Zimbra实例的管理员通过Shadowserver等平台的扫描工具主动检查自身服务器的补丁状态。

**应急处置建议**

1. 优先升级至 10.1.20 及以上版本。

2. 临时缓解（暂时无法升级）

   - 关闭 SNMP 通知告警功能：`zmprov mcf zimbraSnmpTrapNotificationEnabled FALSE`

   - 收紧 SMTP 源 IP 访问策略，非可信源限制访问 25 端口；

3. 入侵痕迹自查

   - 检查 `/tmp`、`/opt/zimbra/jetty/webapps/`、`/opt/zimbra/jetty\_base/webapps/` 是否存在陌生可疑文件，zimbra 属主异常文件；

   - 审计邮件日志、系统 bash 历史，查看异常系统命令执行记录；

   - 核查是否存在未知账号、定时任务后门；

4. 备份邮件数据，定期校验备份完整性；收敛邮件服务器公网暴露面。

**Microsoft SharePoint RCE漏洞链遭野外利用 PoC已公开**

**微软SharePoint Enterprise Server 2016被曝存在一个由两个漏洞组成的远程代码执行（RCE）攻击链。其中认证绕过漏洞CVE-2026-55040与RCE漏洞CVE-2026-63520组合，可让未认证的攻击者在SharePoint服务器上执行任意代码。安全公司已经观察到该漏洞链在野外被积极探测，且概念验证（PoC）代码已公开，这意味着任何人都可以利用该攻击链对未修补...
