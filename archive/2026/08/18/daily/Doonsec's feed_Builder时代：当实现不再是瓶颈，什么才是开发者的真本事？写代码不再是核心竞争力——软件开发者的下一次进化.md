**软件开发者的下一次进化**

从"写代码"到"定意图、做编排、担责任"

过去几个月，我读了无数讨论 AI 是否会取代软件开发者的文章。有人预言编程将走向终结，也有人认为不会有太大变化。但我认为，这两种观点都偏离了重点。

真正的变革不在于 AI 能写代码——这一点早已不是新闻。真正值得思考的是：当写代码不再是软件开发中最困难的部分时，我们的职业将走向何方？

回顾软件工程的历史，你会发现一个反复出现的规律：每一次重大创新，都在提升抽象的层级。

从汇编语言到高级语言，从手动内存管理到自动回收，从重复模板代码到框架抽象，从自建运维团队到云平台托管——每一步都让开发者更高效，让他们从实现细节中解放出来，专注于解决真正的问题。

AI，不过是这条进化路径上的下一个台阶。它不是在取代开发者，而是把我们推向抽象栈的更高层。

变革的方向不是"从开发者到 AI"，而是"从写代码到定义意图、编排系统、为结果负责"。

**AI 不是颠覆者，抽象才是**

我刚入行时，软件开发的一切都围绕着 IDE 打转。典型的一天就是创建类、实现函数、修 Bug，然后一次提交一个 commit 地缓慢推进代码库。代码，是我们向计算机表达意图的方式。

随着系统规模增长，一件有意思的事发生了：理解已有代码，变得和编写新代码一样重要。 整个咨询项目的核心工作，就是接手遗留系统、搞懂它的运行逻辑、在不引入回归的前提下修 Bug 并安全地添加新功能。阅读代码成了一项高价值技能，因为理解系统远比多产出几百行 PHP 或 Java 来得重要。

而今天，我认为我们正在经历又一次过渡——抽象层再次上移。

**开发者正在沿抽象栈向上移动**

我越来越多的时间花在"理解问题"上，而不是"思考实现"上。

我定义需求、明确约束、评估取舍、设计架构、连接现有平台、审查 AI 生成的代码，还要判断哪些地方用确定性逻辑就够了，哪些地方 AI 推理能真正创造价值。写代码仍然是我工作的一部分，但它已经不再是最能创造价值的那部分了。

这就是为什么我不认为软件开发者会消失。我们只是在向栈的更高层移动。多年积累的技术知识不会突然变得无关紧要——恰恰相反，正是因为我们理解抽象层之下到底发生了什么，才能在更高的层级上自如运作。

这个角色的变化在于：不再是把每个决策手动翻译成代码，而是首先做出这些决策。

**IDE 不再是工作的中心**

几十年来，IDE 一直是我们创建软件的主要界面。但这个界面正在改变。

我们可以描述想要构建的东西、提供上下文、定义需求和约束，然后让系统帮我们生成部分实现。至于用的是 Codex、Claude Code、Gemini CLI 还是尚未出现的工具，几乎是次要的。真正值得关注的是我们与软件开发之间交互方式的转变。

IDE 不会消失——我仍然会打开文件、检查代码、调试问题、审查实现，偶尔也会直接写几行。但它的角色变了。它不再是每一行软件代码诞生的起点，而是越来越多地变成一个检查、理解、验证和改进生成代码的场所。

我们的主要交互界面，正逐渐从"实现"转向"意图"。

**软件开发的经济学正在改变**

这次转变也改变了软件开发的经济学。

是的，AI 有成本——Token 不是免费的。但如果你把"生成、审查、迭代代码"的成本，和"完全手动完成同样工作"的成本做个对比，行业的走向就一目了然了。实现代码的成本正在以前所未有的速度下降。

但这并不意味着软件变得不那么值钱。恰恰相反——我们会构建多得多的软件。以前因成本太高而不值得实现的想法，突然变得可行了。小企业可以自动化那些以前根本配不上定制开发的流程；自由职业者可以独立打造过去需要整个工程团队才能完成的产品；创业公司可以更快地试验，因为实现的门槛持续降低。

而所有这些新软件，仍然需要有地方运行。它们需要可靠的基础设施、部署平台、可观测性、身份认证、内容管理、支付、监控、存储、数据库、集成和安全。Laravel Cloud、Vercel、Netlify、Storyblok、Supabase、Stripe 这类平台不会因为 AI 能生成代码就变得不重要——它们提供的正是让越来越多想法变成现实产品的基础构件。

软件创建变便宜了，但运营、演进和为软件负责这件事不会凭空消失。

**"所有权"是新的分水岭**

想象一个未来：AI 生成了一个项目里的每一行代码。那谁拥有这个软件？

不是 AI。

总有人拥有架构。总有人决定服务之间如何通信。总有人对安全、可扩展性、可靠性、合规性、性能、成本和长期可维护性负责。总有人判断哪些技术权衡可以接受、哪些技术债可以等等、哪些已经变得危险。总有人需要理解半年前某个架构决策的来龙去脉，以及它现在是否依然合理。总有人在凌晨两点生产环境出故障时被追责。

而在重要的软件产品中，这个"总有人"很少是某一个人——而是不同团队和个人分别对系统的不同部分承担责任。

生成代码不等于拥有产品。这是两种截然不同的责任。

事实上，我越想越确信：实现越便宜，所有权就越值钱。当 AI 消除了生产软件的摩擦，架构决策、功能决策和非功能决策的质量就成了更强的差异化因素。做软件从来不仅仅是产出代码，而是做出决策并承担其后果。

**软件正在从"确定性"走向"概率性"**

应用内部也在发生一个有趣的变化。

几十年来，大多数业务逻辑是确定性的——相同的输入和相同的状态，每次都产生相同的输出。AI 引入了不同的东西：应用可以在运行时推理、理解自然语言、分类信息、总结文档、生成内容、选择工具、根据上下文做决策。我们的系统，部分正在从确定性走向概率性。

这创造了一类全新的工程决策：哪里该用大模型，哪里传统函数更好？如何测试一个输出可以合理变化的东西？如何评估它的质量？如何在生产环境中监控它？多大的变异性是可以接受的？当模型产生意外结果时会怎样？

我们在运行时引入的智能越多，这些问题就越重要。AI 并没有通过提供智能组件来消除工程决策——它创造了新的工程决策。

**开发者最大的机遇**

这正是让我对这次进化感到乐观的部分。

多年来，很多自由职业者和顾问本质上是在"卖实现"——客户需要一个功能，我们估算工作量、实现它，然后按工时收费。当实现变便宜时，这个模式显然会改变。但我不觉得这是个问题——我看到的是机遇。

一个有经验的开发者，可以越来越多地将 AI 能力、云基础设施、认证服务、支付平台、无头 CMS、部署服务、数据库和专业 API 组合在一起，构建出几年前需要一整个团队才能完成的产品。

差异化优势不再仅仅是"能不能实现每个组件"，而在于知道该用哪些组件、如何组合、什么该定制、什么根本不该建，以及最重要的——哪个问题真正值得解决。

这让开发者前所未有地接近产品本身。我们不再只是卖实现，而是可以卖解决方案；不再只是接收规格说明然后翻译成代码，而是可以参与定义"该建什么"并为结果负责。

这就是为什么我喜欢 Builder（建造者） 这个词。建造者不是由他亲手写了多少代码来定义的。建造者理解问题、设计方案、选择工具、编排组件、评估结果，并为接下来发生的一切负责。

从这个角度看，我不认为未来的软件开发者创造的价值会更少——我们只是换了一种方式创造价值。

更少的实现，更多的意图。

更少的敲代码，更多的决策。

更多的编排。

更多的担当。

行业的每一次重大变革都提升了抽象层级，却从未消除对优秀工程师的需求。AI 正在做同样的事，只是规模和速度前所未有。它不是要我们变得不那么技术化，而是给了我们机会，在更高的层级上运用技术知识——在那里，理解系统、做好决策和承担责任，比以往任何时候都重要。

这不是软件开发的终结。

这是软件开发者的下一次进化。
