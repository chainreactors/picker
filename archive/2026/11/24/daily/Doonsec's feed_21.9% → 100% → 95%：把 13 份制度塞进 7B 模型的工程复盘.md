栏目 · 工程复盘

把 13 份制度塞进 7B 模型
一次垂域问答系统的工程复盘

32 万字制度、614 个条款单元、四轮数据迭代。基座模型准确率 21.9%，微调后 100%，随机条款召回却只有 50.5%；接入 Agentic RAG 才到 95%。

· 数据已脱敏　· 2026-11　· 全文约 5000 字

把 13 份制度文件喂给大模型，让它替员工答题——听起来像「接个 API 就完事」的活。真正做起来，第一周就会被两件事打脸：模型记不住文号，而且它会一本正经地编。

这篇复盘按真实交付顺序讲四段：数据怎么配、训练为什么炸、行为怎么修、检索什么时候该开。指标放前面，翻车现场放中间，能直接抄的结论放最后。

微调后的模型在 73 道制度题上拿了满分。同一周，问它「1+3 等于几」，它回答「材料中没有规定」。**专业满分，不等于模型可用。**

01三种死法：记不住、爱编造、答不准

一家省级通信服务企业的网信安全制度，散在 13 份文件里：一份 466 页的白皮书、若干管理办法与规范、一整套应急预案，外加一份主管名册，合计 32.4 万字。员工查一条规定，要打开几百页 PDF 翻目录。

把这件事交给通用大模型，会连着遇到三个问题。

1**记不住**——文号、时限、部门职责，预训练语料里根本没有，模型只能猜。

2**爱编造**——被问到某个部门的职责，它会生成一套看起来很像、但原文没有的答案。

3**答不准**——同一个问题换种问法答案就漂移；条款号一多，还会把两条串在一起。

所以目标不是「做个能聊天的机器人」，而是三个硬指标：**答得准、给得出条款依据、能离线单机部署**。

02数据工程：17.8 个百分点是数据给的

把 PDF 抽成文本只是第一步，噪声比想象中多。

|  |  |
| --- | --- |
| 噪声 | 处理办法 |
| **页眉页脚** | 466 页重复出现，保留页分隔符后统一去重 |
| **版式符号** | 「— 1 —」「□— 2 —」这类页码装饰，正则清洗 |
| **网址水印** | 正文里夹带的官网地址，正则删除 |
| **Excel 整表压成一行** | 按行分句、按列分隔，重建记录边界 |

最后一条最容易被忽略：第一版把整张主管名册拼成了一行，相邻两条记录的行边界直接消失。**表格抽取一定要检查换行。**

去重后训练集 2,475 条，按来源分成九类，每类解决一个具体问题。

|  |  |
| --- | --- |
| 样本类型 | 作用 |
| **名册问答** | 人名、电话、职务，以及各种简称问法 |
| **文件身份** | 文号、发布日期、版本号 |
| **条文问答** | 「第 X 条」的原文覆盖 |
| **生成问答** | 把长段落改写成人话问答 |
| **人工关键事实** | 高频硬事实，逐条对照原文核对 |
| **同义问法** | 「多久内反馈」与「多长时间反馈」 |
| **超纲拒答** | 教它不知道就说不知道 |
| **通用对话** | 保住基座能力，正常闲聊 |
| **公司概况** | 公开资料整理，回答企业基本情况 |

生成数据要过滤。让基座模型从 258 个语料片段生成问答对，共 768 对，再用 **4-gram 重合率**卡一道：答案里的四字片段落在原文中的比例低于 0.55 就丢掉。最终丢掉 119 对，占 15.5%。

同义问法是另一个坑。第一版模型对「《数据安全管理办法（2025 版）》是几号文」答得对，对「数据安全管理办法是几号文」却拒答。于是把 52 条关键问题各改写成 3 个口语问法，硬性要求数字、文件名、部门名不许改。73 题准确率从 **94.5% 升到 98.6%**。

还有一类结构性歧义：白皮书是制度汇编，好几个章节里都有「第十四条」。训练题只写「白皮书第十四条」，同一个问题就对应多个答案，模型必然串条。处理办法是把章节写进问题——「白皮书第六章第八条」。**条号不是全局唯一的，必须带作用域。**

这轮迭代说明一件事：把「40 条人工关键事实」「278 条同义问法」「几组易混事实对比」补进去，比调学习率有用得多。

03训练：bf16 反传为什么会炸

环境是一台 128 GB 统一内存的 Mac Studio，MLX 框架，基座 Qwen2.5-7B-Instruct，LoRA 挂满 28 层、rank 16。按最常见的教程设 lr=1e-4，训练在 20–40 步内从 loss 3.4 冲到 11——接近随机猜测（ln 152064 ≈ 11.9）——随后 NaN。

固定同一批数据、只改精度，量梯度总范数，答案立刻清楚。

|  |  |  |  |
| --- | --- | --- | --- |
| 模型精度 | loss | 梯度总范数 | 结果 |
| **bfloat16** | 2.645 | 1.58 × 10¹¹ | 必然发散 |
| **float16** | 2.649 | 44.4 | 能撑一段，长序列溢出 |
| **float32** | 2.649 | 45.3 | 稳定 |

bf16 只有 8 位尾数，7B 模型 28 层反传把误差放大成了天文数字。fp16 的 44.4 看着正常，但最大表示值只有 65504，长条款的激活一溢出就是 NaN。学习率扫描得到的是同一个结论。

|  |  |  |
| --- | --- | --- |
| 精度 | 学习率 | 现象 |
| **bf16** | 1e-4 | 第 40 步 loss 11.3 |
| **bf16** | 2e-5 | 稳定但欠拟合 |
| **fp16** | 1e-4 | 前 100 步正常，约 400 步 NaN |
| **fp32** | 1e-4 | 第 70 步 loss 14，方向被离群梯度带偏 |
| **fp32 + 裁剪 1.0** | 3.5e-5 | 稳定下降，验证 loss 3.46 → 0.40 |

最终配置：**fp32 权重 + 梯度裁剪 1.0 + warmup + 余弦退火**，lr 3.5e-5。这是整个项目最有复用价值的一条结论——不要照搬「LoRA lr 1e-4」的教程。

还有一条更贵的经验：**epoch 比学习率危险**。1,594 条样本跑 7.5 个 epoch，训练 loss 0.09、验证 loss 2.0，模型看起来完美，实际「只会背题」。3–4 个 epoch 才是安全区，而且必须用「验证 loss + 独立评测集」双指标看，训练 loss 没有任何参考价值。

04行为对齐：SFT 会把人训傻

SFT 之后出现了新的行为问题——不是不知道，是该不该答。

|  |  |  |
| --- | --- | --- |
| 提问 | SFT 的回答 | 问题 |
| **1+3 等于几** | 材料中没有规定 | 该答不答 |
| **你知道乔布斯吗** | 把名册里的人搬出来 | 答非所问 |
| **你是谁** | 自称某平台管理员 | 身份错乱 |
| **帮我写代码** | 我不是代码助手 | 过度推辞 |

这些问题靠调数据配比修不干净，DPO 更直接。构造 **79 对偏好数据**，rejected 全部来自实际观察到的错误输出，不是随手编的：β=0.1，lr 5e-6，100–250 步，再加 0.1 倍 NLL(chosen) 防止语言能力漂移。

100 题能力验收从 94 提到 100，「某分公司主管是谁」「应急预案联络人」「某人是院长吗」这类回退点全部修复。

但 DPO 也会过拟合。第二轮用 120 步、全量偏好对，总分从 99 掉到 97，把「水是无色的」「春节是正月初一」这种常识训错了。偏好对少的时候，**小步（40–100 步）、低学习率、只针对新 badcase 补**，才是对的。

05RAG：条款背不下来，就别硬背

同一套 200 条随机条款（带章节号），纯 SFT 只答对 101 条，**50.5%**。原因不复杂：614 个条款单元、32 万字，rank 16 的 LoRA 记不下；条款问题高度同构，容易串条；条号跨章节重复，天然歧义。

结论是别硬背。SFT 管高频事实和口吻，长尾条款交给检索。

1**路由**——名册、公司概况、常识类问题直接作答，不检索。

2**定位**——问题里带「《文件》第 X 条」，就按文件 + 章节 + 条号精确命中。

3**检索**——文件内 BM25（top 6），再用连续 5 字片段重合度加权。

4**组装**——相邻条款扩展，上下文不超过 7 条，每条都带文件名与条号。

5**校验**——回答必须标注【《文件》条款】，并反查条号是否真的出现在检索结果里。

三路信号融合：精确条款定位、BM25、连续片段加分。另有一张文件别名表，把「113 号」「数据办法」「白皮书」「勒索病毒」这类口语映射到正式文件。

路由这一步最容易省，也最容易出事。曾经问「某学院简介」，Agent 仍然去检索制度，检索不到相关条款，模型就用记忆补，把省公司主管的名字套到了学院头上。修复很粗暴：学院、公司概况、常识类问题直接作答，不含领域关键词的问题不检索。**RAG 不能对所有问题都开，路由本身是准确性的一部分。**

图2 | 五个系统、两条曲线——**专业问答靠 SFT 就能刷满，条款召回只能靠检索**。

同一个 200 条评测集，加上 Agentic RAG 后从 50.5% 到 **95.0%**。差距不是模型变聪明了，是它终于「查得到」了。

06还有四个坑，和模型能力无关

十二个坑里，下面四条不涉及算法，但每一条都真实伤过人。

6.1 拒答要精确打击，不能全面戒严

24 条拒答样本加上过多 epoch，模型学到的是「没见过的就拒答」。问「谢谢」也回「材料中没有规定」。拒答只该覆盖「制度相关的未知事实」，同时要补「该答必须答」的正样本。

6.2 身份和知识要分开训练

问「你是谁」，模型开始背名册里的手机号。根因是身份样本和名册样本混在一起，模型把「我是谁」当成了「名册检索」。身份单独成组，明确一句固定自我介绍。

6.3 名称近似会编造

问「培训分公司的网信安主管」，答出来的是另一家名字相近的机构和人名。「培训」两个字触发了邻近概念，而名册训练只有全称、没有简称问法。补简称、补「一个组织两块牌子」的事实，再用这次真实错误做 DPO 的 rejected。

6.4 部署侧的 system prompt 是分布的一部分

同一个 GGUF，不带 system prompt 时，「重保期间多久反馈」答 24 小时，「今年营收」编出一串日期；带上之后分别答 8 分钟和「材料中没有规定」。因为 SFT 每条样本都带同一段 system prompt，模型已经把「严谨 / 拒答」和它绑定了。解法是把 system prompt 写进 GGUF 的 chat template，并在模板里丢弃客户端传入的通用 system。

07结论：三句话

🎯 一、数据配比比参数调优更重要

82.2 → 94.5 → 98.6 → 100 的提升，来自 40 条人工关键事实、278 条同义问法、几组易混事实对比。参数扫描没有带来这种量级的变化。

⚠️ 二、专业满分不等于模型可用

73 题 100% 的同一周，模型连「1+3 等于几」都拒答。必须同时评测通用能力、拒答行为和部署链路，不然满分只是过拟合的证据。

🔍 三、SFT 与 RAG 是互补，不是替代

SFT 让模型会说话、记得住高频事实；RAG 让冷门条款查得到、可溯源。200 条随机条款上 50.5% → 95.0% 的差距，就是这句话的证据。

给同类项目的四条建议：

1**先建评测集**——再谈训练。训完再挑指标，等于没指标。

2**先保数值稳定**——精度、裁剪、epoch，这三件没搞定，效果讨论都是空的。

3**先做路由**——再做检索。检索错配会把幻觉放大，而不是消除。

4**先想部署**——system prompt、chat template 必须原样带到线上，否则行为会漂。
