红队实战：一次护网演练里的社工钓鱼链路复盘（脱敏）

攻击者最省力的入口从来不是 0day，而是人。这篇复盘一次授权护网演练里的社工钓鱼链路，全程脱敏、只讲方法。

重点不在「怎么骗到人」，而在「防守侧每一层本来可以拦在哪」。

本文为授权红蓝对抗演练的方法论复盘，所有社工动作在书面授权与受控范围内进行；不提供可用于真实钓鱼的模板或话术。

0101 信息收集：先搞清楚「钓谁、用什么名义」

授权演练里，先确认目标人群与可使用的「名义」（如内部系统升级通知）。这一步严格限定在授权书范围内，不得使用授权外的个人信息。

公开信息（官网团队页、公开演讲、已授权提供的通讯录）只能用于授权内的演练设计，且不得触碰法律边界。

0202 投递：走「看起来正常」的通道

演练里投递走内部可控通道，模拟一封「系统升级提醒」。关键技术点不是文案多像，而是它落在了用户习以为常的通知流里——这正是防守要识别的异常。

1发件人显示名伪装成内部系统，但域名需经邮件网关核验。

2链接指向演练专用隔离域名，绝不指向真实业务。

3全程记录，演练结束即销毁所有凭据与数据。

0303 凭据获取：克制比「拿到」更重要

演练目标是验证「能否诱导到一步动作」，不是收集真实凭据。所以一旦用户点击并抵达隔离页，即记为命中，立即停止，不记录任何输入内容。

红队演练的价值不在「骗成了」，而在「哪一层没拦住」——邮件网关、员工识别、异常登录检测，缺一个都该写进报告。

0404 防守侧：四道该拦的缝

|  |  |
| --- | --- |
| 薄弱点 | 加固 |
| 邮件伪造 | SPF/DKIM/DMARC 全开 + 外部邮件显式标记 |
| 员工识别 | 常态化钓鱼演练 + 一键举报 |
| 凭据保护 | MFA + 异常登录风控 |
| 可见性 | 登录日志集中 + 告警 |

0505 演练的价值在报告不在过程

产出不是「钓到 N 人」，而是「这条链上每一步薄弱点在哪、怎么补」。报告写清触发条件、影响、修复建议、复测方法。
