# 1 引言：为什么现在必须重视AI智能体权限管控

## 1.1 从“聊天工具”到“自主智能体”的范式转变

短短数年间，大语言模型的应用形态已经发生了根本性变化。在发展早期，我们仅将模型当作“会聊天、会写作、会翻译”的工具：输入提示词即可得到一段回答，且回答本身不会对现实世界产生任何持续性影响。如今，大语言模型正越来越多地被封装为“智能体”（Agent）：它能够理解用户意图，将目标拆解为多个步骤，主动调用外部工具，在真实系统中完成数据的读取与写入，还可以在多轮任务中积累并复用记忆。

这种范式转变意味着，大语言模型已经从“仅生成内容”演进为“能够执行行动”。当智能体被授权连接数据库、办公系统、消息平台、代码执行环境、云服务乃至支付通道后，一次看似无害的工具调用，就可能引发数据泄露、业务误操作或合规性事件。因此，权限——也就是“这个智能体可在什么条件下、以多大范围、代表谁开展行动”——就此成为智能体安全的核心议题。

## 1.2 权限失控的典型事故与教训

我们无需列举具体企业的实际事件，仅从风险作用机理就能看清权限失控的后果。目前业界反复出现的风险场景主要分为以下几类：

1. 过度授权：为图省事，给智能体授予了与管理员等同的权限。当智能体遭遇外部内容诱导发起工具调用时，可能会删改生产数据或批量外发敏感信息，且事后难以追责。
2. 工具误调用：用户原本仅意图完成“查询”操作，但因意图理解偏差或参数错误，最终触发了写操作、删除操作或对外发送操作。
3. 身份与权限混淆：系统无法区分“用户本人操作”与“智能体代为操作”，导致智能体越权访问了本不该获取的数据。
4. 提示词注入引发越权：智能体读取的网页、邮件、文档等不可信内容中携带恶意指令，会劫持智能体的后续行为，诱导它在既有权限范围内执行破坏性动作。
5. 供应链投毒：从第三方来源加载的技能、插件或依赖项中暗藏恶意代码，可在智能体的权限范围内运行。

这些风险场景的共同点是：破坏力并非来自模型“不够智能”，而是来自模型被赋予的权限边界过大、授权边界模糊，且缺乏人机确认与审计机制。安全界已形成共识：智能体的自主性越高，对权限管控的严格程度要求就越高。

## 1.3 本次培训的目标与读者

1. 统一共识：理解智能体与传统应用的差异，领会“权限即边界”这一核心理念。
2. 掌握方法：吃透最小权限、动态授权、人在环、可审计等核心原则与落地机制。
3. 明确职责：理清开发、使用、运维、安全各相关方在权限管控中的责任分工。
4. 推动落地：获取可执行的自检清单与实施路径，回到岗位即可直接应用。

本讲义适用于公司内所有开发、使用、部署和管理AI智能体的员工，无论你是业务用户、研发工程师、运维人员，还是安全与合规岗位的工作人员。

# 2 AI智能体的能力模型与安全边界

## 2.1 智能体的定义与工作闭环

一个典型的智能体围绕“感知—规划—决策—执行—记忆”的闭环运转：

1. 感知：接收任务、用户指令与上下文信息，既包括网页、邮件、文档、消息这类外部输入，也涵盖系统的历史记忆。
2. 规划：将模糊的整体目标拆解为可逐步推进执行的步骤序列。
3. 决策：判断每一步应当调用哪个工具、访问哪些数据，以及明确行动的范围边界。
4. 执行：在真实系统中完成操作，包括写入数据库、发送消息、部署服务、调用API、变更配置等。
5. 记忆：跨会话留存上下文信息，让后续任务执行更为连贯，但也可能因此留存沉淀下敏感信息。

风险在于：这个闭环的每一步都有可能偏离预先设定的预期边界。模型决定智能体“要做什么”，权限决定它“被允许做什么”；只有二者同时处于受控状态，才能保障安全。

## 2.2 智能体与传统应用/服务的本质差异

传统应用的安全边界相对清晰：功能固定、输入受控、身份明确。智能体则存在若干本质差异，详见下表。

表1 智能体与传统应用的差异

|  |  |  |
| --- | --- | --- |
| 维度 | 传统应用/服务 | AI智能体 |
| 行为确定性 | 逻辑确定、输入可控、结果可枚举 | 行为随输入与上下文变化，难以穷举 |
| 输入可信度 | 多为结构化、受控输入 | 常混入网页、邮件、文档等不可信内容，存在提示词注入面 |
| 授权方式 | 静态角色＋固定功能菜单 | 需要动态、会话级、意图相关的细粒度授权 |
| 动作空间 | 有限且预定义 | 可调用所有已暴露的工具与资源，动作空间大且动态 |
| 身份归属 | 用户操作与系统行为边界清晰 | “用户本人”与“智能体代操作”边界模糊 |
| 失败模式 | 逻辑或异常错误，影响局部 | 自主多步、级联、难以回滚的失效 |
| 审计重点 | 业务日志即可覆盖 | 需覆盖决策、工具调用、参数、结果的全程审计 |

## 2.3 为什么权限管控是智能体安全的“命门”

大语言模型“输出可信”并不等于“行为可信”。模型既可能生成逻辑严谨但超出权限范围的动作指令，也可能被输入中的恶意指令劫持。既然我们无法保证模型每一次决策都“完全正确”，就必须确保它“哪怕决策出错，也没有能力实施破坏性动作”——这正是权限管控的核心作用。

OWASP在《大语言模型应用Top 10》v1.1中，将“过度授权（Excessive Agency）”列为大语言模型应用的关键风险：赋予模型不受约束的自主行动能力，会危害应用的可靠性、用户隐私与公众信任。我们可以这样理解智能体的实际风险：

智能体实际风险≈ 模型弱点 × 授权边界 × 工具执行后果

其中每一项都可以通过工程手段压缩风险：模型弱点依靠防护与测试管控，授权边界依靠最小权限与动态授权收缩，工具执行后果依靠沙箱与审计约束。权限管控可同时作用于后两项，因此是投入产出比最高的安全防线。

## 2.4 智能体典型安全风险分类

参照国际主流框架，可将智能体权限相关的主要风险归纳如下：

1. 过度授权（Excessive Agency）：智能体的自主度或权限超出任务实际需求，是智能体权限安全的首要风险。
2. 工具误用与命令注入：智能体在授权范围内调用工具时，被诱导执行非预期动作，例如命令注入、路径穿越等。
3. 身份与权限混淆：人与智能体、主客体归属不清晰，引发越权访问问题。
4. 提示词注入引发的越权：不可信外部内容劫持模型指令，在权限边界内实施破坏。
5. 供应链风险：第三方模型、技能、插件与依赖被恶意投毒。
6. 级联失效（Cascading Failures）：多智能体协作场景下，单个节点的失控会被逐级放大。
7. 记忆与上下文污染：跨会话复用的记忆被污染，导致权限判断出现错误。

# 3 AI智能体权限管控的核心原则

## 3.1 最小权限原则

最小权限（Least Privilege）要求仅授予智能体完成当前任务所必需的最小权限。NIST《安全与隐私控制》（SP 800-53）将其列为访问控制的核心控制项（AC-6）。针对智能体，需要落实“双重最小化”要求：第一是运行身份最小化——智能体以专用服务身份、低权限账号运行，绝不使用管理员或超级管理员身份；第二是单次动作最小化——每一次工具调用都仅拥有该动作所需的最小作用域、最小资源范围与最短时效。

有一个实用的判断标准：如果移除某一权限后，智能体依旧可以正常完成任务，就应当去掉该权限。宁可因权限不足发起额外授权请求，也不要因权限过大承担不可逆的安全后果。

## 3.2 动态授权与会话级作用域

静态常驻权限不适应智能体的动态行为特点，因此需要采用动态授权机制：权限随任务、上下文与会话动态授予，使用后立即回收，作用域、时效、资源范围都应当控制在最小范围。例如，仅负责“查询本周排班”的智能体，不应当持有写入或修改日程的权限，更不应当拥有全库访问权限。

## 3.3 人在环与自主度分级

人在环（Human-in-the-Loop）是智能体安全的关键防线。OWASP《AI智能体安全速查表》明确提出相关要求：针对高影响或不可逆动作，必须获得用户的明确批准；执行动作前需要提供动作预览；需要根据动作风险划定自主度边界；保留清晰的决策与动作审计轨迹；同时允许用户中断并回滚智能体的操作。

落地实施时通常按照动作风险划分为三级：低风险只读动作可自动执行；中风险写操作需要经过人机确认；高风险、破坏性或不可逆动作必须强制审批，并提前预留回滚预案，具体内容详见第5章表2。

## 3.4 零信任思想

零信任（Zero Trust）的核心是，不会因访问主体的位置、来源或归属给予隐式信任，而是会对每一次访问的身份、设备、上下文与合规性逐一验证。NIST SP 800-207已经对零信任架构作出了权威定义。将这一理念应用到智能体权限管控中，即便智能体持有合法令牌，也不意味着它可以任意调用工具——每一次工具调用都应当在策略执行点重新评估本次动作是否符合允许执行的条件。

## 3.5 可观测、可审计、可回滚

权限管控必须形成完整运营闭环：需要记录智能体的决策依据、工具调用、参数与执行结果，保障可观测性；确保审计日志不可篡改、全程可追溯，满足可审计要求；在出现异常时能够中断执行并回滚操作影响，实现可回滚目标。缺失运营闭环的“权限管控”只是静态配置，无法发挥安全防线的作用。

# 4 智能体授权模型与技术机制

## 4.1 授权模型：从静态角色到动态委托

传统授权以“静态角色+功能权限”模式为主，在智能体场景中需要引入“委托授权”模型：由用户（即资源所有者）授权智能体以自身身份，在限定的作用域与时效内代表本人执行操作。这一思想与OAuth 2.0/OpenID Connect等业界标准的委托授权模型一致——不将整个账号权限交付给智能体，仅颁发带作用域限制、有时效约束、支持随时撤销的授权。

推荐采用多层授权结构：用户→ 智能体 → 工具 → 资源，每一层都独立作出授权决策，且任一层次的授权范围都应当以“完成当前任务必需”为限。

## 4.2 凭据与令牌管理

1. 细粒度作用域：令牌仅携带完成任务所需的最小权限声明，避免生成“全功能令牌”。
2. 短期时效：令牌有效期尽量缩短，同时支持刷新和随时撤销。
3. 最小留存：不在日志、代码、提示词、记忆或配置文件中明文存放密钥。
4. 集中保管：凭据统一存放于专用密钥保险库，运行时按需注入，执行完成后及时清除。
5. 禁止万能密钥：不使用管理员凭据或长期有效的服务账号直连。

## 4.3 工具/技能层的权限清单

智能体的“能力”最终由它可调用的工具、技能与API决定，因此工具层是权限管控的核心落点。

1. 技能级白名单：明确智能体可调用的工具范围，未纳入范围的调用一律禁止。
2. 参数级约束：对工具参数设置边界限制，包括金额上限、时间范围、目标对象白名单、调用条数上限等。
3. 动作分类：区分只读、有限写、高影响写、破坏性/不可逆动作，为不同类型分别配置对应的授权策略。
4. 参照OWASP《Agentic Skills Top 10》的梳理，恶意技能、供应链滥用、过度特权执行、弱隔离等都是技能生态的高发风险，必须对技能来源与执行权限做严格审查。

## 4.4 沙箱与运行隔离

对于不可信或高风险动作，需将其执行过程放入沙箱环境：通过容器或虚拟机实现运行隔离、进行网络分段（禁止横向访问）、配置最小运行身份、设置资源配额与调用限流。即便智能体被诱导执行越权代码，沙箱也能将影响范围限制在最小区间。

## 4.5 权限对抗防护

1. 提示词注入防护：将不可信内容与系统指令隔离；对外部输入进行过滤和标记；在执行敏感动作前，对操作意图做独立校验。
2. 工具调用参数校验：在策略执行点对参数做白名单、类型和边界校验，防范命令注入、路径穿越与非法目标访问。
3. 双重校验：将智能体的“自主决策”与策略执行点的“独立校验”分离，动作合法性以策略执行点的校验结果为准，不依赖模型自身的判断。

## 4.6 记忆与上下文跨会话的权限边界

智能体的记忆模块可以提升运行效率，同时也可能放大安全风险。针对记忆需要遵循最小化与隔离原则：敏感数据（凭据、个人信息、商业机密）不得写入长期记忆；跨会话复用的上下文，在每次调用时都需要重新校验权限；对不同数据域的记忆做隔离，避免单次授权污染全部上下文。

# 5 权限管控的落地架构与实施路径

## 5.1 参考架构：分层授权与策略执行

权限管控的落地需要一套分层参考架构，各层职责如下：

表3 权限管控参考架构层级

|  |  |  |
| --- | --- | --- |
| 层级 | 承载内容 | 主要职责 |
| 身份层 | 用户身份、智能体服务身份 | 认证、身份源、单点登录 |
| 授权层 | 角色、作用域、授权策略 | 定义“能做什么” |
| 策略执行点 | 动作校验、参数校验 | 在动作执行前独立裁决 |
| 工具/资源层/ | 工具、技能、数据资源 | 白名单、沙箱、最小权限 |
| 审计层 | 日志、监控、告警 | 全链路可观测与响应 |

## 5.2 动作风险分级与人工确认策略

将智能体动作按照影响范围分级，并针对性配置不同的确认策略：

表2 动作风险分级与人工确认策略

|  |  |  |  |
| --- | --- | --- | --- |
| 动作类别 | 风险等级 | 授权与确认策略 | 典型示例 |
| 只读查询 | 低 | 自动执行，受限白名单 | 查询天气、读取已授权文档 |
| 有限写操作 | 中 | 人机确认或业务审批 | 修改个人日程、发送内部消息 |
| 高影响写操作 | 高 | 强制审批，必要时双人 | 对外发布、变更生产配置、支付 |
| 破坏性/不可逆动作 | 极高 | 禁止，或专项审批＋回滚预案 | 批量删除、覆盖关键数据 |

智能体自主度应与风险反向匹配：风险越高，自主度越低，人的参与越充分。

| 运营 | 持续 | 监控、权限复核、回收、改进 | 安全运营闭环 |

## 5.4 与既有IAM/身份体系的融合

复用企业现有身份源与单点登录体系，智能体以专用服务身份运行，不借用个人账号。角色与作用域和现有角色权限体系对齐，减少重复建设。权限变更沿用既有流程（申请、审批、审计），审计日志接入现有安全运营平台，实现统一告警与响应。

## 5.5 安全运营：监控、告警、审计与应急响应

关键监控指标包括：工具调用量、越权尝试、异常动作、高权限使用频率、敏感数据访问。针对不同风险设置分级告警机制：低风险仅记录留痕，中风险发送提醒，高风险立即触发阻断。提前预设“中断+回滚”应急响应预案，明确处置升级路径与对应责任人。此外，定期对智能体权限开展周期性复核，及时回收不再需要的授权。

## 6.2 制度与流程建设

建立权限申请、评审、授权、回收全流程规范，定期开展权限复核与最小权限审计，明确异常上报与处置机制（含越权、误操作、注入类安全事件），落实第三方智能体、模型与技能供应商的准入评估要求。

## 6.3 对标国际与国内框架

智能体权限管控可参照以下权威框架，构建体系化的自检与改进基线：

1. OWASP《大语言模型应用Top 10》v1.1：重点关注LLM08过度授权风险，提示需做好权限边界设计。
2. OWASP《智能体应用Top 10》（2025）：覆盖不安全智能体间通信（ASI07）、级联失效（ASI08）、人机信任利用（ASI09）等智能体特有的风险场景。
3. OWASP《智能体技能Top 10》（2026）：聚焦技能层恶意代码、供应链滥用、过度特权执行与弱隔离问题。
4. NIST《人工智能风险管理框架》（AI RMF 1.0，NIST AI 100-1）：以Govern、Map、Measure、Manage四大功能搭建AI风险治理体系。
5. ISO/IEC 42001:2023《信息技术 人工智能 管理体系》：提供可认证的AI管理体系框架。
6. 《人工智能安全治理框架》（全国网络安全标准化技术委员会）：1.0版于2024年9月发布，2.0版将于2025年9月发布，框架强调分类分级治理与安全指引。
7. 《生成式人工智能服务管理暂行办法》：2023年8月15日起施行，确立了“包容审慎、分类分级”的监管理念。
8. 《网络安全法》、《数据安全法》、《个人信息保护法》及《网络数据安全管理条例》（国务院令第790号）：共同构成数据安全与个人信息保护的基础合规底座。

注：以上框架与法规信息在本文编制时经核实为现行有效；实际部署应用时，请以最新发布版本为准。

## 6.4 员工安全意识与个人最佳实践

只授予智能体完成任务所需的最小权限，勿因图省事授予过大权限。绝不将管理员账号、密钥或敏感凭据交由智能体保管，也不得将其写入提示词。授权前需完成对拟授权工具、数据范围以及有效期的审查。针对高影响动作保持人在环确认机制，不得盲目自动执行。发现异常（包括越权、误操作、可疑调用）后，要第一时间上报安全团队。

# 7 总结与行动建议

## 7.1 关键结论

1. 权限即边界：智能体安全的核心，在于将其“可执行操作”严格约束在完成任务所需的范围之内。
2. 四大支柱：最小权限、动态授权、人在环、可审计，四项原则缺一不可。
3. 体系工程：技术机制、制度流程、组织分工，必须协同推进落地。
4. 持续运营：权限管控不是一次性配置完成即可，而是需要持续复核、持续改进的长期过程。
