Desloppify naming-and-api-shape step 4: the Lua API's shape. Nothing that works today stops working. One commit per finding.

1. **Options go last.** `oriel.on` and `oriel.exec_async` still take opts before the function too, now through one helper (`optsAndFn`) in place of two copies. Options that are neither a table nor the function raise, instead of being ignored. Before this change, opts given after the function were dropped. docs/api.md's preamble states the rule. Test: `TestLuaOptionsGoLastOrBeforeTheFunction`.
2. **A contribution's spec table is canonical.** `decorations.provider`, `session.chips`, `session.done`, `session.unsaved`, `status.rule` and `view.override` take `{ name (id for a view), run = fn }` as well as `(name, fn)`, and raise without a name or a function. The rule is in the preamble. Test: `TestLuaPositionalContributionsTakeASpecTable`.
3. **A plugin's diagnostics are its own.**

   * `diagnostics.set` and `coverage.set` scope the owner under the plugin's id, e.g. `init.lua:lint`, so a plugin can't overwrite or clear a built-in's (lua, tests, an LSP server's).
   * Setting a file again keeps one undoing instead of one per call.
   * Coverage that isn't a table raises.

   Tests: `TestAPluginsDiagnosticsAreItsOwn`, `TestSettingDiagnosticsAgainDoesntGrowWhatsOwned`, `TestCoverageOfTheWrongTypeRaises`.

docs/api.md and the Lua types are regenerated. The full suite, ratchets and a chaos pass on the new tests pass.
