On Thursday,  PHP [version 8.6](https://www.php.net/releases/8.6/en.php) was released on its usual yearly schedule, popping up as if the web scripting language hadn’t been under intense scrutiny this past month.

For those who missed it: a [swarm](https://www.theregister.com/security/2026/10/22/php2shell-exploit-bypasses-protections-designed-to-stop-remote-code-execution/5304883) of [unearthed vulnerabilities](https://www.theregister.com/security/2026/10/23/theres-a-third-php2shell-bug-but-it-wont-get-an-emergency-fix/5305208) has [plagued](https://www.theregister.com/patches/2026/11/18/another-critical-php-security-release-has-dropped/5310911) PHP since October, allowing unauthenticated attackers to crash PHP workers or execute arbitrary code on the server. Users of every PHP-based application, including WordPress, Laravel, and Symfony, had to scramble to update their PHP instances.

The PHP core development community, along with the [PHP Foundation](https://thephp.foundation/), responded with a coordinated release of patched versions of PHP ([8.5.13, 8.4.28, 8.3.37, 8.2.36](https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security/) and the new 8.6) that [closed](https://cybersecuritynews.com/php-8-released/) seven critical remote code execution (RCE) flaws in one sweep.

REG AD

In addition to patching specific exploitable holes in the PHP engine, the new version of PHP also tamps down some of PHP’s historically liberal configuration settings.

REG AD

Lucky for PHP, and for the rest of us, core developer Jörg Sowa called out these lax settings in June, when he posted a [proposal](https://wiki.php.net/rfc/session_security_defaults) to set more security-friendly defaults.

Sowa saw that three configuration settings of PHP’s session extension – Strict Mode, HttpOnly, and SameSite – were designed to boost security but shipped “with defaults that leave applications unnecessarily exposed.”
