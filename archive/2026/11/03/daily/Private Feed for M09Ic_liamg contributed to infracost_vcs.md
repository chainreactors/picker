Pins new FinOps, security and tagging policy failures to their lines in the PR diff.

* `comment.BuildAnnotations(data)`: one annotation per new failure with an in-repo file and line. It uses the same "new on head" and `IncludeInPullRequestComment` rules as the comment. Blocking failures sort first.
* `Annotation.Markdown()` renders the design template from TRK-1287:
  + ❌/⚠️ heading with the policy type, plus "(blocking)" if it blocks the PR
  + ℹ️ policy name
  + 💡 one line per suggested fix
  + 💰 yearly savings, shown when it is $100 or more
  + policy description under "View details"
* New `VCS.PostAnnotations` method. All three providers post the same markdown:
  + GitHub: PR review comments on `Options.HeadSHA`, one per call. It resolves threads whose failure is gone. It reposts threads that GitHub marked outdated.
  + GitLab: diff discussions. Resolves stale threads.
  + Azure: file threads with an iteration context. Stale threads are set to `fixed`.
  + Bitbucket: no-op.
* A 400/422 on one annotation counts as rejected, and the rest still post.
* Annotation threads use their own hidden tag (`<tag>-annotation, key=…`), so the main comment lookup never matches them.

Needs a release (minor) before the runner PR merges.
