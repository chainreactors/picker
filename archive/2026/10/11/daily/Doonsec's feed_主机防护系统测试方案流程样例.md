在终端安全产品的选型实践中，我们观察到一个普遍存在的认知偏差：许多用户仍将 "病毒库查杀率" 作为衡量终端防护能力的核心甚至唯一标准。静态扫描能够验证产品对已知威胁的基础覆盖，但在当前的威胁环境下，这一标准已远远不够。

近年来，勒索软件、APT 攻击和无文件攻击的产业化趋势日益明显。攻击者普遍采用免杀技术绕过特征码检测，利用合法工具（LOLBins）执行恶意操作，通过漏洞利用获得初始访问后进行横向移动，并在加密数据前完成凭证窃取与持久化。国庆假期末期出现的RedPipe组织，对国内多家企业进行渗透勒索，提权过程中利用了某安国内终端安全产品驱动，进行BYOVD的攻击操作。在MITRE ATT&CK 框架所描述的完整攻击链中，静态特征匹配只能覆盖 "执行" 阶段的一小部分，而对于初始访问、权限提升、防御规避、凭证访问、横向移动、影响等绝大多数阶段，传统病毒库扫描几乎无能为力。

基于这一现实，我们设计了一套以真实攻击链为蓝本的终端安全能力简单的验证方案。所有测试项目均围绕勒索组织和高级威胁的典型攻击路径展开 —— 从免杀恶意代码的行为检测，到漏洞利用的虚拟补丁防御；从合法软件滥用的上下文关联分析，到勒索加密的实时阻断与数据回滚；从威胁传播路径的可视化溯源，到失陷主机的应急隔离与全网威胁狩猎。相关测试内容的技术门槛较低，我们欢迎大家在评论区留言，补充更多专业的测试项目内容。我们的目标不是对特定产品进行排名或背书，而是回答一个更本质的问题：一款真正有效的 EDR/EPP 产品，应当具备哪些能力？

本文力求中立、客观、可复现。每一项测试都明确了测试方法、环境配置和判定标准，读者可以依据相同的方法论在自身环境中进行验证。我们希望通过这套测试框架，帮助安全团队跳出 "比查杀率" 的选型误区，建立基于攻击链防护能力的评估体系，从而在面对日益复杂的威胁时，做出更符合实际安全需求的决策。

# 主机防护系统测试方案流程

# 一、测试目的

本次测试旨在对我集团公司拟采购的终端安全防护方案进行客观、全面的技术评估，验证产品在实际真实业务场景下的防护能力、管理便捷性、资源占用情况及安全检测与防护效果，为后续采购决策提供依据。

# 二、测试基本原则

1. 测试内容应覆盖集团公司主流终端类型（办公环境工作站等）及典型业务场景。
2. 测试方法应具备可重复性，结果可量化、可对比。测试项目应从集团真实需求场景出发，有效应对银狐钓鱼，勒索攻击，内网横向，应急响应排查等场景。
3. 测试过程中应尽量减少对集团公司现有业务系统的影响。选择封闭的局域网环境进行测试。
4. 所有测试结果如实记录，作为评估依据。

# 三、具体测试方法流程

## （一）基础防护能力

## 1、授权与统一管理能力

测试目标：验证产品对不同操作系统终端的支持情况及授权管理方式。

|  |  |  |
| --- | --- | --- |
| 类别 | 管理中心 | 终端保护 |
| Windows Server环境 | 支持 | 支持 |
| Linux Server环境 | 支持 | 支持 |
| Windows 工作站（7/10/11等） | 支持。建议部署在服务器端。 | 支持 |
| Linux 工作站 | 支持。建议部署在服务器端。 | 支持。 |
| 安卓移动设备 | 不支持。建议部署在服务器端。 | 支持 |
| 是否区分Server和工作站、不同操作系统的授权？ | 不区分/区分 | |

## 2、功能模块覆盖

测试目标：确认产品在服务端与工作站端所支持的安全功能是否满足集团公司防护需求。

|  |  |  |
| --- | --- | --- |
| 功能类别 | 情况说明 | 备注 |
| 文件反病毒 |  |  |
| Web威胁防护 |  |  |
| 网络威胁防护 |  |  |
| 防火墙 |  |  |
| 行为检测 |  |  |
| 漏洞利于防御虚拟补丁技术 |  |  |
| 应对勒索技术（注明类型：实时监测回滚、诱捕备份等） |  |  |
| 外设管理 |  |  |

## 3、安装资源占用

测试目标：评估产品在不同场景下对终端性能的影响，避免影响集团公司日常业务运行。

1. 静态系统资源占用（内存、CPU）
2. 首次扫描系统资源占用（内存、CPU）
3. 二次扫描的系统资源占用（内存、CPU）

## 4、病毒包测试扫描静态查杀能力

测试目标：使用标准病毒样本包，评估产品的静态文件检测能力。

测试方法：使用已知病毒样本集，在断网/联网两种环境下分别进行扫描，记录检出率。

## （二）内网安全进阶防护能力

## 1. 行为检测能力

测试目标：验证产品能否有效识别并阻止病毒库未覆盖的恶意程序行为，阻止攻击者获取Windows操作系统凭证。

测试方法：使用经免杀处理的黑客工具（如mimikatz）运行，观察产品是否能够发现、阻止其读取系统NTLM等敏感行为。若出现静态查杀该文件，应将黑客工具加白，或者关闭文件防护，确保避免出现查杀、拉黑文件的前提下进行测试，依靠行为检测验证动态防护能力。

## 2. 内网横向渗透防护能力

测试目标：模拟攻击者利用失陷主机进行内网横向移动，验证产品防护能力。目前勒索攻击内网渗透攻击行为，往往采取PTH哈希传递方式批量渗透。

测试方法：在测试环境中模拟主机失陷后，通过Metasploit等工具进行PTH哈希传递攻击，评估产品是否能阻断攻击行为。其阻断应自动阻断，不依赖人工选择阻断。

## 3. 未知勒索病毒应对能力

测试目标：验证产品在不依赖病毒库特征的情况下，对未知勒索病毒的防御能力。

测试方法（1）：使用免杀处理后的勒索病毒样本执行，观察产品是否能够拦截加密行为、保护文件完整性。

为保证验证未知勒索病毒防护能力，测试必须关闭防病毒等静态防护功能，将勒索样本添加到白名单后测试。

需记录产品所采用的勒索防御技术原理（如行为分析的内存快照分析、诱捕等）。若出现加密成功行为，须验证能否恢复被加密的文件，详细介绍工作原理（回滚还是备份快照恢复）

测试方法（2）：目标主机开启文件共享，共享文件夹内存放样例文件。攻击者从外部访问共享文件，进行批量文件加密。观察产品是否能够拦截加密行为、保护文件完整性。

## 4. 自我保护能力

测试目标：验证产品在被攻击者获取终端权限后，自身进程与配置是否具备足够的抗破坏能力。

测试方法：使用火绒剑、PCHunter、TDSSkiller、EDR-Freeze等工具尝试结束进程、删除安装文件，评估产品是否能维持防护功能正常。为保证应对未知恶意工具能力，须将测试样本文件添加到白名单后测试，不得进行查杀处理。

## （三）应急响应的检测与响应能力

## 1、对于免杀处理后的C2攻击框架后面的监测

假设攻击者利用钓鱼邮件、漏洞利用后上传等方法，将免杀处理后的C2攻击框架的客户端上传并执行，并运行whoami、ipconfig等基础命令。能否检测相关事件并响应。

测试方法：

我们选择免杀处理后的CobaltStrike、Brute Ratel C4、Vshell等常用攻击框架，对后门免杀处理后，在测试靶机运行。并运行whoami、ipconfig、添加粘滞键后门等基础命令。能否检测相关事件并响应，能否展示流程，完成根本原因分析。

## 2、能否对攻击者的合法工具利用进行检测记录

攻击者获取靶机权限后，使用合法关键进行数据窃取等操作，能否检测或者阻断到相关行为。

测试方法：

在靶机上直接部署百度网盘等软件，验证能否阻断访问百度网盘主页，同时无法运行百度网盘程序。

## 3、实现标准化的Open IOC格式排查，验证快速检测与响应能力。

在网内排查指定哈希（md5和sha256），DNS，指定进程名等指标的排查，并设置响应措施（仅告警；可删除文件、进程等）
