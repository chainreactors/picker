## Summary

`go test ./...` on clean master fails locally on random `TestE2E_FullMatrix/REVERSE_PROXY/*` leaves (~30s read i/o timeouts). Root cause is twofold, both test-infra — no product code changed.

### Root cause

1. **Unbounded matrix concurrency** — every FullMatrix leaf calls `t.Parallel()`, so total in-flight pairs was only limited by `go test -parallel` (= GOMAXPROCS). A high-core box launches far more crypto+compress pairs than CI's 4-vCPU runners.
2. **Reverse-only startup window** — server `processLogin` runs `iniService` (inputer listens + forwards OPEN) **before** sending LOGINRSP; the client only builds its outputer **after** processing LOGINRSP. An OPEN arriving in that ~100ms gap is silently dropped (no outputer yet) and the conn stays half-open until timeout. Confirmed via timestamps: OPEN at :46.948, LOGINRSP received at :47.107, client outputer created at :47.147. PROXY/SOCKS5/HTTP have no such asymmetric window and never failed.

* **Global matrix gate** `matrixGlobalSlots` defaulting to **4** (= CI vCPU), override via `SPP\_MATRIX\_PARALLEL`; ricmp keeps a host-scoped serial slot. Replaces each underlay's local semaphore which could not bound cross-mode/underlay concurrency.
