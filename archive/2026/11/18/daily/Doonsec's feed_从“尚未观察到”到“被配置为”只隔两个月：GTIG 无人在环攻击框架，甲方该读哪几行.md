11 月 16 日，Google 旗下威胁情报小组 GTIG 发布新一期季度《AI 威胁追踪报告》，标题是《智能体威胁活动跨越重要门槛》。第二天媒体报道铺开，多数标题落在同一组词上：首次、无人在环、AI 自动开发攻击代码。

这些报道传递了报告的核心信息。在此基础上，有一个措辞细节值得留意：GTIG 描述这套框架时用的动词是“被配置为”，指向的是能力设置，而非已完成的攻击。两个月前，同一份季报的上一期还表示，尚未在实际环境中观察到针对目标部署的完全自主攻击流程。两个月过去，报告的表述发生了怎样的变化、哪些进展得到确认、哪些仍缺少实例，值得逐层核对，这也关系到甲方用户近两周的应对安排。本文尝试把报告拆开细读，区分已确认与未确认的部分，供读者参考。如果只带走一条建议，我们倾向于：互联网侧资产的补丁对表，可以从这周起按天来做。

**一台服务器上的两样东西**

先把事实钉住。GTIG 在一台暴露在互联网上的中转服务器里，发现了一套代号 exploit\_agent 的多智能体框架，接入多个前沿大模型和本地部署的模型。报告原句是 “is set up for continuous differential analysis of popular web application software”——这套框架被配置为持续比对流行 Web 应用软件每次补丁发布前后的代码差异，识别潜在漏洞，起草利用代码，并在无人干预的情况下自动执行。

注意这个动词：“被配置为”描述的是设计意图和能力设置，不是已经完成的攻击记录。

同一台服务器上，GTIG 还找到了别的东西：从受害者处窃取的数据，用于内部侦察、暴力破解、安装网页后门的脚本，甚至还有一段专门删除其他攻击者网页后门的脚本。受害者数据指向法国的媒体、娱乐和教育网站。框架配置文件里有一行俄语注释，提醒设置者把密钥直接填在文件里，不要留在聊天记录中。

这些痕迹说明，服务器的运营者已经入侵过那些法国站点。但报告没有说入侵是 exploit\_agent 干的。翻遍全文，GTIG 没有给出这套框架写出并打通目标的实例，没有把任何一个 CVE 记到它名下，也没有给出成功率。报告里那张截图显示的是框架在分析 WordPress 插件 Spectra 2.19.25 的访问控制代码——它在读代码，不在打服务器。GTIG 也没有给运营者命名，没有把活动归因到任何国家。

事实到这里是齐的，缺的东西也在明面上。

**“首次”首次在哪里**

归因没有给，节拍给得很清楚。上一期季度报告发布于两个月前，当时的表述是尚未观察到完全自主的攻击流程。这一期报告名直接叫“跨越重要门槛”。翻过去的部分是：这类框架在真实环境里跑了起来，全流程不需要人参与。

没翻过去的部分同样写在报告里。确认的是分步自动化：开源渗透框架 CAIRN 被用于针对美国航空航天行业的入侵；基于 PentAGI 定制的平台在 8 月底到 10 月初对亚洲大量机构做侦察和漏洞扫描；清单里还有 ARTEX——这个被持续追踪的多智能体渗透平台，原作者 10 月把代码库下了架，之后靠分支和一个收费版本继续传播。但端到端无人参与的“打穿”，报告没有给出实例。GTIG 对这类框架现状的判断是 “trade stealth for velocity”（以隐蔽换速度）：它们跑得快，但会留下可取证的流量与代码痕迹。

两层分开读，标题的口径就有了着落：“首次出现无人在环攻击框架”成立，“首次 AI 全自动攻击得手”不成立。对甲方用户来说，这个区分不是文字游戏，它决定这两周的动作是对表升级，还是应急响应。

**利用窗口在压缩，不用等“全自动”**

对表的那一侧，报告给了更硬的证据。补丁比对是攻击者做了几十年的基本功：修复前后的版本对照，等于把缺陷位置画出来，n-day（已披露但未必修复到位的漏洞）利用就是这么来的。GTIG 在报告里判断，已修复漏洞的源材料有限，攻击者可能发现，用大模型挖 n-day 比找零日更高效。

这个判断有案例托底。PaperCut 的两个漏洞 8 月下旬被当作零日串联利用，研究方和 Huntress 用大模型在披露后一天内生成了可用的利用代码。安全公司 GreyNoise 追踪的一次活动发生在漏洞披露后四天，攻击者很可能用模型构建并测试了利用代码，攻击了数百家机构，其中一次从初始入侵到拿到域管理员权限只用了几分钟。10 月 21 日两个 PHP 高危漏洞修复后，几天内出现了数百个利用 PoC，多数不可用，GTIG 认为大概率由 AI 生成。

零日的月均数字也在抬升：2025 年月均 8 个被利用零日，2026 年升至 11 个，8 月单月 22 个。（这组数字在多份英文转述中一致，GTIG 官方页面本次未能直接取得，引用按转述级对待。）披露与利用的整体数量在 1 月到 8 月间接近翻倍。

窗口压缩不是预告，是正在上映的片段。

而这些数字没有一个来自 exploit\_agent。这正是要害：不用等“全自动”落地，窗口压缩已经发生在每一台打了补丁但没人复核的服务器上。

**这几天做的五件事**

第一件，把互联网侧的 Web 应用从资产清单里单列出来，补丁周期与内网资产分开定。这份报告盯的就是流行 Web 应用，PHP、WordPress 这类部署量大的系统，更新慢半拍的存量跟着也多。

第二件，补丁当天对表。互联网侧资产不能继续按月度批量窗口走，出补丁当天核对暴露资产的版本，受影响就当天排修复。上面案例的时间尺度是一天和四天，月度窗口在这个节奏里等于不设防。

第三件，查 Web 目录的新增文件。那台服务器上的脚本组合说明两个面都在被打：登录面靠暴力破解，文件面靠网页后门。那段删除别人后门的脚本还提示一件事——一台失陷机器可能被多个攻击方同时盯上，排查时不能找到一个后门就收工。

第四件，管理面收口。暴力破解脚本出现在工具箱里，意味着弱口令和暴露的管理入口仍在攻击者的默认动作清单上。

第五件，检测和加固不从头做。Mandiant 发布了应对 AI 辅助攻击工具的加固指南，GTIG 也指出这类框架目前以速度换隐蔽，会留下取证痕迹。把这个特征写进现有告警规则，比在“AI 攻击”上重新立项省事。

五件事没有一件依赖“全自动攻击已经成功”这个前提。它们依赖的只是报告里坐实的部分：工具链在自动化，补丁到利用的窗口在缩短。

**【安全牛观察】**

这份报告真正的信号不在法国那台服务器，在节拍上。人工的补丁比对要休息、要工资、要熟练度，agent 版本三样都不要，成本还会随模型价格下探。无人在环从演示环境走到真实环境只隔了两个月，从真实环境走到首次得手，差的可能只是时间。如果后续两期季报仍然没有 agent 写出并打通目标的实例，“全自动攻击已落地”的说法就不成立，甲方用户按现有节奏应对即可；一旦出现第一个记到这类框架名下的 CVE，应急流程就要按“无人链路、无休息窗口”重写。在那两个证据出现之前，先把互联网侧的补丁对表改成按天做——这一步不用等任何人。
