## What's New in v2.7.4

> **v2.7.4 fixes plain list file input (`-f targets.list`)**: canonical service names like `rdp:` and `mssql:` are accepted again ([#360](https://github.com/x90skysn3k/brutespray/issues/360)), alongside the scanner names scanners emit.

### Fixed: Plain List File Service Names (`-f`)

* **Canonical module names accepted** — `service:ip:port` lines such as `rdp:10.0.0.1:3389` now parse; previously `ParseList` validated the post-mapped name against the raw scanner-name table, so every canonical name (`rdp`, `mssql`, `smbnt`, `winrm`, `ftps`, `mongodb`, `teamspeak`, `xmpp`, `vmauthd`, `ldaps`, `rexec`/`rlogin`/`rsh`) failed with `unsupported service`
* **Scanner aliases still work** — raw names (`ms-wbt-server`, `ms-sql-s`, `microsoft-ds`, `wsman`, ...) resolve through the same alias map as `-H` targets; both spellings land on the canonical module
* **Single source of truth** — list validation now runs through `DescriptorForService`, the same service set `Host.Parse` uses for `-H service://` targets; the parallel allow-list drift is gone
* **Clearer errors** — unsupported-service errors quote the token as typed, not the mapped name; scanner names with no registered module (e.g. `pcanywheredata`) are rejected at parse time instead of failing at dispatch

### Upgrade Notes

* No behavior changes for GNMAP, XML, JSON, masscan, or stdin inputs; only `-f` plain list validation changed
