With tabs open, Oriel never shows the start view.

* **At launch:** the session that was in front comes back, or the first open tab when that one is gone or there is no record of it. The record is missing, for example, on the first launch after upgrading from a build that predates `tabs.json`. That launch previously restored the tabs but landed on the start view.
* **Afterwards:** whenever tabs are open and none is in front (the front tab closed by an event rather than its ✕, tabs restored with none in front), the first tab comes to the front.
* **Back and forward:** stops with no session (the start view) are skipped while tabs are open.
* **Logging:** launch logs which way it went (`launch: …`), and a failed move onto the session is logged instead of dropped.

Tests:

* A window closed with a session in front, a host restarted from disk, and a new window opened empty comes back on that session.
* With tabs open and none in front, the window opens on the first tab and never draws the start view.
* With the front tab closed directly, another tab comes to the front.
* `TestLeftOnTheStartViewItOpensThere` is replaced: that behaviour is what this PR removes.

The tabs help page is updated.
