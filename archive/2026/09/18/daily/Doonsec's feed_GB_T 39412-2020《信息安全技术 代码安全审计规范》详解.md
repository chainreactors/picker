定位：我国第一部面向"代码层"的系统化安全审计国家标准，规定了审计过程与四大类典型审计指标及证实方法。

第3章 关键术语

|  |  |
| --- | --- |
| 术语 | 定义要点 |
| 代码安全审计 | 对代码进行安全分析，以发现代码中存在的安全缺陷或违反代码安全规范的行为 |
| 安全缺陷 | 代码中破坏软件安全能力的问题或错误 |
| 跨站脚本攻击（XSS） | 攻击者向 Web 页面插入恶意 HTML 代码，用户浏览时被执行 |
| 缓冲区溢出 | 向缓冲区写入超出其长度的内容，破坏程序堆栈，可能导致获取系统控制权 |
| 死锁 | 两个或以上进程因竞争资源或通信造成的阻塞现象 |

术语定义精简，避免与 CWE/OWASP 体系冲突——这一点对该标准的工程化落地很关键：它不定义新的漏洞分类学，而是定义"审计动作"。

第4章 审计概述

4.1 审计说明

针对\*\*结构化语言（如 C）与面向对象语言（如 Java）\*\*两类语言形态，制定共 97 条审计条款，覆盖安全功能、代码实现、资源使用、环境安全四个方面。

4.2 审计目的

发现代码安全缺陷、降低安全风险，形成审计报告并提出改进建议。

4.3 审计时机

·内部审计：由开发团队自身执行；

·外部审计：由第三方机构开展；

·建议时点：代码编写完成后、系统集成测试之前。

这是全标准最具工程价值的判断之一——它把代码审计锚定在"编码完成但尚未集成"的窗口，此时修复成本最低，且不会与系统测试的资源争抢冲突。

4.4 审计人员

应具备相应专业知识；客观呈现问题；保守代码秘密（对应 5.2 环节的保密协议）。

4.5 审计方法

工具审计 + 人工审计结合，采用\*\*检查列表（checklist）\*\*逐一核对，避免误报和漏报。

第5章 审计过程

5.2 审计准备

1.明确审计目的——采购测试、合规自查、上线前评估，目的决定广度与深度；

1.签署保密协议——保护被审代码不被滥用；

1.背景调研——了解代码应用场景、开发者遵循的编码标准；

1.制定检查列表——把 97 条裁剪为本次适用的检查项。

5.3 审计实施（四个子环节）

|  |  |
| --- | --- |
| 子环节 | 要点 |
| 5.3.1 入场介绍 | 向被审方说明审计目标与所需资料清单 |
| 5.3.2 信息收集 | 通过访谈获取代码及需求分析、设计、测试文档；据此区分核心代码与一般性代码（核心代码=涉及核心业务功能/核心软件功能的代码） |
| 5.3.3 代码安全缺陷检测 | 依据检查项，采用工具审计 / 人工审计 / 人工结合工具三种方式检测，检测后做安全性分析 |
| 5.3.4 特殊情形审查 | 存在软件外包 / 采用开源软件 / 合作开发情形时，必须对开源或外包部分做代码安全审计 |

审计强度分级：核心代码→重点审计；一般性代码→一般性审计。这是标准中唯一的"资源分配"机制，实操中直接决定人日投入。

5.4 审计报告

·审计实施完成后组织评审会，将初始结果提供给被审计项目成员，给予澄清误解的机会，允许补充信息；

·评审会后依据评审意见调整结果，形成正式审计报告；

·报告内容：总体描述 + 审计结论，并对安全风险做高/中/低三级分类描述；

·审计结论必须对每条审计条款给出「符合 / 不符合」的描述（还应包含"不适用"及其理由）。

「先给被审方申诉机会，再定稿」——这一条常被忽略，但它是报告能否被采信的分水岭。

5.5 改进跟踪

·对发现的问题进行修改；未修改的应提供理由；

·对代码的有效变更记录存档；

·修复后可通过再次审计确认问题是否解决。

第6章 安全功能缺陷审计（37条，"该有的安全机制是否健全"）

6.1 数据清洗（21条）

6.1.1 输入验证（18条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 审计指标要点 |
| 6.1.1.1 | 关键状态数据外部可控 | 避免将与用户信息或软件自身安全密切相关的状态信息，存储在非授权实体可访问的地方 |
| 6.1.1.2 | 数据真实性验证 | 宜验证数据源/通信源、数字签名、完整性检查；验证文件内容而非文件名或扩展名；验证未校验的 Cookie |
| 6.1.1.3 | 绕过数据净化和验证 | 防止以大小写混合方式绕过净化与验证 |
| 6.1.1.4 | 在字符串验证前未进行过滤 | 宜在验证字符串之前先过滤，防注入类攻击 |
| 6.1.1.5 | 对HTTP头Web脚本特殊元素处理 | 应对 HTTP 头中 Web 脚本语法特殊元素过滤验证 |
| 6.1.1.6 | 命令行注入 | 正确处理命令中的特殊元素（数据来自非可信源、被当作命令执行、赋予攻击者不应有的权限） |
| 6.1.1.7 | 数据结构控制域安全 | 避免对数据结构控制域的删除或意外增加 |
| 6.1.1.8 | 忽略字符串结尾符 | 保证字符串存储空间足以容纳字符数据与结尾符 |
| 6.1.1.9 | 对环境变量长度做出假设 | 不应对环境变量长度做特定值假设（用户可修改） |
| 6.1.1.10 | 条件比较不充分 | 执行比较时不应部分比较或不充分比较，防逻辑绕过 |
| 6.1.1.11 | 结构体长度 | 不应将结构体长度等同于各成员长度之和（存在无名填充字符） |
| 6.1.1.12 | 数值赋值越界 | 避免数值赋值超出数值类型范围 |
| 6.1.1.13 | 除零错误 | 避免除零操作 |
| 6.1.1.14 | 边界值检查缺失 | 数值范围比较时不宜遗漏最小值/最大值边界检查 |
| 6.1.1.15 | 数据信任边界的违背 | 宜避免将可信与不可信数据组合在同一结构体中 |
| 6.1.1.16 | 条件语句缺失默认情况 | 条件语句中不宜缺失 default |
| 6.1.1.17 | 无法执行的死代码 | 不宜包含无法执行的死代码 |
| 6.1.1.18 | 表达式永真或永假 | 不应出现逻辑永真/永假表达式 |

6.1.1 是整份标准颗粒度最细的一节，18 条中过半是 C/C++ 内存与数值语义问题。这解释了为什么该标准对 C 代码的审计覆盖率明显高于 Java/C#。

6.1.2 输出编码（3条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 6.1.2.1 | 跨站脚本 | 用户提交数据放入页面送浏览器显示前，应验证或过滤 |
| 6.1.2.2 | Web应用重定向后执行额外代码 | 不宜在重定向后执行额外代码 |
| 6.1.2.3 | URL重定向 | 不应开放到不可信站点的 URL 重定向 |

6.2 数据加密与保护（5条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 6.2.1.1 | 密码安全 | 密码相关实现技术应符合国家密码管理部门相关规定（对应商用密码合规，非一般意义上的"加密算法强度"） |
| 6.2.1.2 | 随机数安全 | 采用能产生充分信息熵的算法；避免随机数空间太小；避免 CSPRNG 使用相同/可预测种子（进程ID、系统时间）；避免将有密码学缺陷的 CSPRNG 用于加密场景 |
| 6.2.1.3 | 使用安全相关的硬编码 | 不应使用安全相关硬编码（代码泄漏后被利用） |
| 6.2.2.1 | 敏感信息暴露 | 检查 15 类暴露途径：发送数据、数据查询、差异性（响应/行为/时间）、错误消息、不恰当跨边界移除、进程信息、调试信息、释放前未清除、输出流或日志、缓存、日志文件、源代码及注释、HTTP 请求传递、备份文件；Web 登录表单宜禁止浏览器口令自动填充 |
| 6.2.2.2 | 个人信息保护 | 应符合国家相关法律法规（衔接 GB/T 35273-2020） |

6.3 访问控制（9条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 6.3.1.1 | 身份鉴别过程中暴露多余信息 | 注册/认证过程不应暴露多余信息（防暴力破解） |
| 6.3.1.2 | 身份鉴别被绕过 | 不应存在被绕过的路径或通道，鉴别算法关键步骤不得被省略/跳过 |
| 6.3.1.3 | 身份鉴别尝试频率限制 | 应对连续登录失败频率做限制 |
| 6.3.1.4 | 多因素认证 | 宜使用多因素认证机制 |
| 6.3.2.1 | 登录口令 | 登录过程中口令不可明文显示 |
| 6.3.2.2 | 明文存储口令 | 避免明文存储口令 |
| 6.3.2.3 | 明文传递口令 | 避免明文传递口令 |
| 6.3.3.1 | 权限访问控制 | 13 项检查：缺失认证/授权机制、违背最小特权、放弃特权后未检查是否成功、文件访问权限不正确、关键资源不正确权限授予、欺骗/重放绕过认证、不恰当信任反向DNS、C/S 架构下仅在客户端执行认证、过于严格的账户锁定机制（反被利用做 DoS）、信道两端身份认证不充分导致中间人、通信通道源验证不当、未正确指定目的地致伪装服务器 |
| 6.3.3.2 | 未加限制的外部可访问锁 | 宜对外部可访问锁加以限制，防拒绝服务 |

6.3.3.1 是标准中单条检查项最多的条款（13 项子检查）。其中"不宜过于严格的账户锁定机制"值得注意——它同时防暴力破解与"账户锁定型 DoS"，是双向约束。

6.4 日志安全（2条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 6.4.1 | 对输出日志中特殊元素处理 | 应对输出日志中的特殊元素过滤验证（防日志注入/信息泄露） |
| 6.4.2 | 信息丢失或遗漏 | 宜避免安全相关信息丢失或遗漏（截断安全相关信息、不记录关键日志），否则影响攻击溯源 |

7.1 面向对象程序安全（5条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 7.1.1 | 泛型和非泛型数据类型混用※ | 不宜混用具有泛型和非泛型的数据类型 |
| 7.1.2 | 包含敏感信息类的安全 | 包含敏感信息的类不应可复制（如 Java 实现 Cloneable）且不应可序列化 |
| 7.1.3 | 类比较※ | 判定对象所属类时不宜仅基于类名称比较 |
| 7.1.4 | 类私有可变成员的引用 | 应禁止返回类私有可变成员的引用（防内部状态被非预期修改） |
| 7.1.5 | 存储不可序列化的对象到磁盘 | 不应试图将不可序列化的对象写入磁盘 |

7.2 并发程序安全（5条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 7.2.1 | 不同会话间信息泄露 | 避免不同会话（尤其多线程环境）间信息泄露 |
| 7.2.2 | 发布未完成初始化的对象 | 不宜在初始化完成前对象即可被其他线程访问 |
| 7.2.3 | 共享资源的并发安全 | 11 项检查：共享数据同步访问、共享对象存储持续期、并发上下文使用不可重入函数、检查时间与使用时间（TOCTOU）冲突、死锁、敏感操作前检查加锁状态、敏感信息存于未锁定/错误锁定内存（可能被写入磁盘交换文件）、关键资源多重加锁、多重解锁、对未加锁资源解锁、异常发生时是否释放已持有的锁 |
| 7.2.4 | 子进程访问父进程敏感资源 | 调用子进程前应关闭敏感文件描述符（子进程会继承打开的 fd） |
| 7.2.5 | 释放线程专有对象 | 应及时释放线程专有对象，防内存泄漏致 DoS |

7.3 函数调用安全（6条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 7.3.1 | 格式化字符串 | 避免外部控制的格式化字符串 |
| 7.3.2 | 对方法或函数参数验证 | 宜对参数做合法性/安全性校验 |
| 7.3.3 | 参数指定错误 | 参数数量/顺序/类型/值错误 |
| 7.3.4 | 返回栈变量地址 | 不宜返回栈变量地址（函数结束即释放） |
| 7.3.5 | 实现不一致函数 | 不宜使用在不同版本实现不一致的函数/方法 |
| 7.3.6 | 暴露危险的方法或函数 | API 或外部交互接口不应暴露危险方法/函数 |

7.4 异常处理安全（≥1条）

·7.4.1 恰当地进行异常处理（6 项检查）：是否检查并处理异常；是否采用标准化、一致的异常处理机制；错误发生时是否提供正确的状态代码或返回值；是否检查执行文件 I/O 的返回值；是否检查函数/方法返回值是否为预期值；是否返回定制错误页面给用户以预防敏感信息泄露。

7.5 指针安全（5条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 7.5.1 | 不兼容的指针类型 | 不宜使用不兼容类型指针访问变量 |
| 7.5.2 | 利用指针减法确定内存大小 | 宜避免（两指针类型不同则计算不正确） |
| 7.5.3 | 将固定地址赋值给指针 | 不宜把 NULL/0 以外的固定地址赋给指针（降低可移植性、便利注入攻击） |
| 7.5.4 | 试图访问非结构体类型指针的数据域 | 不应把非结构体指针强转为结构体指针并访问其字段 |
| 7.5.5 | 指针偏移越界 | 不应使用偏移越界的指针 |

7.6 代码生成安全（3条※）

标准目次确认存在该节（7.6 Code Generation Security），指向自动化代码生成场景的审查要求。注意：本标准为 2020 年发布，原文语境是"代码生成"（框架/工具自动生成代码），并非针对大模型 AI 编程；

八、第8章 资源使用安全缺陷审计（32条，"资源申请/使用/释放是否安全"）

8.1 资源管理（10条）

覆盖资源重复释放、资源未及时初始化与清理、无限循环/递归等。已核实条款：

·8.1.9 算法复杂度攻击：宜避免最坏情况下复杂度极高的算法被精心构造的操作触发；

·8.1.10 早期放大攻击：宜遵守正确的行为次序，避免在授权或认证之前执行代价高的操作。

8.2 内存管理（9条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 8.2.1 | 内存分配释放函数成对调用 | 如 malloc/free 应成对 |
| 8.2.2 | 堆内存释放 | 释放堆内存前应采用合适方式清理敏感信息（如 realloc 调整敏感缓冲区会复制旧内容，可被"堆检查"攻击读取） |
| 8.2.3 | 内存未释放 | 宜及时释放动态分配内存，防内存泄漏致 DoS |
| 8.2.4 | 访问已释放内存 | 不应引用或访问已释放内存（UAF） |
| 8.2.5 | 数据/内存布局 | 不宜依赖底层数据/内存组织形式的无效假设（平台或协议版本变动即失效） |
| 8.2.6 | 内存缓冲区边界操作 | 避免越界（缓冲区溢出） |
| 8.2.7 | 缓冲区复制未检查输入大小※ | 进行缓冲区复制时应检查输入数据大小 |
| 8.2.8 | 使用错误长度访问缓冲区 | 应使用正确长度值访问缓冲区 |
| 8.2.9 | 限制堆空间消耗※ | 防止堆空间耗尽：内存泄漏、死循环、不受限制的反序列化、创建大量线程、解压超大压缩文件 |

8.3 数据库使用（≥2条）

·8.3.1 及时释放数据库资源：宜及时释放数据库连接或采用连接池，否则可能造成数据库拒绝服务；

·8.3.2 SQL 注入（应正确处理命令中的特殊元素）：用户可控输入构造命令时，未处理特殊元素则可能被解释为命令而非普通数据，被用于绕过安全检查或插入额外语句。

8.4 文件管理（4条）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 要点 |
| 8.4.1 | 过期的文件描述符 | 不应使用已关闭的文件描述符（fd 被释放后重用会指向其他文件/设备） |
| 8.4.2 | 不安全的临时文件 | 3 项检查：是否创建/使用不安全临时文件；程序终止前是否移除；是否在不安全权限目录中创建 |
| 8.4.3 | 文件描述符穷尽 | 3 项检查：打开的 fd 是否未关闭；关闭前是否失去所有引用；进程完成后是否未关闭 |
| 8.4.4 | 路径遍历※ | 应避免路径遍历 |

8.5 网络传输（6条）

覆盖端口多重绑定、网络消息容量控制（防 DoS）等。已核实条款：

·8.5.5 会话过期机制缺失：宜制定会话过期机制，否则存在保护绕过风险；

·8.5.6 会话标识符随机性：宜确保会话标识符随机性，防止被穷举。

第9章 环境安全缺陷审计（3条，"供应链与配置"）

|  |  |  |
| --- | --- | --- |
| 编号 | 条款 | 原文要点 |
| 9.1 | 遗留调试代码 | 代码中不应遗留调试代码；应检查部署到应用环境的代码是否含调试或测试功能代码，该部分代码是否会造成意外的后门入口 |
| 9.2 | 第三方软件安全可靠 | 应对第三方代码来源情况进行审计，确保引入的第三方软件安全可靠 |
| 9.3 | 保护重要配置信息 | 宜对重要的配置信息进行安全保护；保护不当可能带来信息泄漏风险 |

三条，却是现代软件供应链风险的主战场：调试后门、开源组件 CVE、明文密钥。标准把 SCA（软件成分分析）与密钥泄露归入"环境"而非"代码"，逻辑上属于"代码之外但随代码交付"的风险面。
