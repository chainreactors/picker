# 渗透测试和等保测评不是二选一，也不能互相替代。前者站在攻击者视角验证防线管不管用，后者依据国家标准判定安全措施达不达标。对准备过三级的系统来说，顺序是：定级备案 → 差距分析 → 整改 → 测评前渗透测试开展自查 → 正式测评 → 整改复测。渗透测试可以系统测评前开展，这样系统在真正测评过程中系统就会减少漏洞的爆出。

**等保测评判定的是「该有的控制项有没有、达不达标」，渗透测试验证的是「这些控制项以及系统逻辑层面在真实攻击下管不管用，是否可以防御攻击」；两者前后衔接，不能互相替代。**

从依据和输出物上最看得清差别：

| 对比维度 | 渗透测试 | 等保测评 |
| --- | --- | --- |
| 目的 | 发现可被利用的漏洞与攻击路径 | 判定安全措施是否符合等级保护要求 |
| 依据 | 书面授权范围、测试方案 | GB/T 22239-2019、GB/T 28448-2019 及定级备案材料 |
| 实施方 | 具备攻防能力的安全服务团队 | 具备资质的第三方等级保护测评机构 |
| 输出 | 漏洞清单、利用路径、修复建议、复测结果 | 逐项判定与等级保护测评报告 |
| 特点 | 深，聚焦授权资产与攻击面 | 广，覆盖技术与管理全部测评项 |
| 周期 | 一般 1–2 周（含复测），视系统规模浮动 | 三级整体含整改通常 2–3 个月，现场实施 1–2 周 |

容易混淆的是：测评会核查漏洞管理、入侵防范的落实记录，现场也可能用扫描工具做验证性检查，但测评机构做的是符合性判定，不会替你做完整攻防演练。

按五步排，基本不走回头路：

1. **先定级备案**

   。定等级、划边界、列资产清单，产出备案材料。没定级就做渗透，范围说不清，钱花得没依据。
2. **逐条做差距分析**

   。对照 GB/T 22239-2019 的通用与扩展要求，把云防火墙、WAF、堡垒机、数据库审计、日志审计、主机安全和制度文档逐项打勾，产出《三级测评项自查表》。这一步决定要补多少东西。
3. **整改先补硬性条款**

   。日志留存不少于六个月（《网络安全法》第二十一条）、身份鉴别与访问控制、审计覆盖范围，这些是「有没有」的问题，靠渗透测试补不上。
4. **正式测评前做渗透测试与漏洞扫描**

   。书面授权、圈定范围与测试窗口，避开业务高峰；拿到报告后把高危项闭环修复并复测，一般留 1–2 周。
5. **再进正式测评，不合格项整改后复测**

   。三级一般每年至少测一次，重大变更后要重新评估是否补测。

**常见问题**

Q：渗透测试能替代等保测评吗？A：不能。渗透测试是技术验证手段，等保测评是具备资质的第三方机构依据 GB/T 28448-2019 做的符合性判定，输出物与合规效力都不同。

Q：到底先做哪个？A：先定级备案和差距分析，整改后、正式测评前-做渗透自查（也可在系统上线前就要开展渗透测试），高危项才能在进场前闭环。

Q：测评前多久做比较合适？A：预留 1–2 周做渗透与高危项修复复测；三级整体含整改通常按 2–3 个月排期，视系统规模浮动。

顺序理清了，企业的等保工作才能事半功倍。
