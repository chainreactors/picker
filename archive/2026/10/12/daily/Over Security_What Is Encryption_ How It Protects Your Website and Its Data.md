# What Is Encryption? How It Protects Your Website and Its Data

If you run a website, you’ve already met encryption even if you’ve never used the word. It’s the 🔒 padlock in the browser bar, the reason your host told you to stop using plain FTP, and the checkbox on your backup settings that says “encrypt archive.”

Encryption is one of the few security controls that works quietly and almost never needs your attention, which is exactly why it’s easy to misunderstand. Plenty of site owners install an SSL certificate, see the padlock appear, and assume the site is now “secure.” That’s the gap we want to close here.

In this guide we’ll define encryption in plain language, walk through how it actually works, cover the main types you’ll run into, map each one to a specific place on your website, and, just as important, be clear about the attacks encryption does nothing to stop.

## What is encryption?

Encryption is the process of taking readable data and transforming it, using a mathematical algorithm and a secret value called a key, into output that can’t be read without that key. The readable version is called **plaintext**. The scrambled version is called **ciphertext**. Reversing the process is **decryption**.

The important part isn’t the algorithm; it’s the key. Modern encryption algorithms are public and published; anyone can read exactly how they work. Security comes from the fact that you hold the key and an attacker doesn’t. That’s a deliberate design choice, because an algorithm that’s been reviewed by thousands of cryptographers for years is far more trustworthy than one kept secret.

So when someone says data is “encrypted,” the useful follow-up question is always: encrypted with what key, and who else can get to it?

## How does encryption work?

Start with a toy example. Take the word **`LOGIN`** and shift every letter forward by three places in the alphabet: you get `ORJLQ`. The algorithm is “shift each letter,” the key is “three,” and the ciphertext is `ORJLQ`. Anyone who knows both the algorithm and the key can shift back and recover the original.

That example is trivially breakable because there are only 25 possible keys, and you could try them all by hand. Real encryption keeps the same shape but changes the scale. Instead of shifting letters, algorithms like AES operate on blocks of raw bytes, mixing and substituting them through many rounds. Instead of 25 possible keys, the key is a long random value with an astronomical number of possibilities, so guessing is not a practical attack.
