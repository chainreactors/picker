## 00引子：两件事都栽在IP库上

上周在现场连着撞见两件尴尬事。第一件，一个安全阻断产品给我弹了条高危告警，IP 后面孤零零挂着个归属地，写着"未知"——明明是境外地址，它连"哪个国家、哪个区省"都给不出来，后面的封禁策略自然无从下手。

第二件，一个客户提了很合理的要求：境外全封、港澳台加强、某几个省份单独走白名单。配置界面上确实能按"地区"勾选，结果跑起来才发现，产品底层拿到的地区码经常错——境内外没有具体省市、把境外判成境内，策略越封越乱，最后客户自己都分不清到底是拦住了还是放过了。

两件事往回追，根子都在同一个地方：你用来判断"这个 IP 从哪来"的那个库，到底准不准、新不新。说句实话，很多人把 IP 归属地当成和"源端口"一样的确定事实，其实它跟天气预报更像——有依据、有概率、会过时。今天把这件事拆开讲清楚，省得你哪天也站在客户面前解释"为什么该封的没封"。

## 01阻断与封禁，底层都靠IP定位

安全阻断产品干的事，本质上每一步都依赖 IP 定位。告警的时候，它得告诉你"攻击来自哪个国家/地区"，你才好判断是普通扫描还是定向攻击；做地域封禁的时候，它得更直接——"这个 IP 属于被封的地域吗"，命中就拦、不命中就放；再往深里说，识别 VPN、代理、Tor、数据中心 IP，判定"这是真人还是机房流量"，也全是基于 IP 元数据。

⚠️ 难点就在这：归属地不是查字典，是做推断。IP 地理定位靠的是 IANA/RIR 分配记录、BGP 路由表、主动探测和大量用户反馈交叉比对，任何单一来源都不完整，结论是"最接近"而不是"就是"。

所以一个阻断产品报出来的"归属地"，准不准、跟不跟得上现实，完全取决于它背后那张 IP 库的质量。库烂，上层所有策略都是空中楼阁。

## 02精度真相：国家级能信，城市级别迷信

这是最容易被误用的一点。很多人以为"IP 库能精确到街道"，那是把付费商业库的宣传当成了免费库的实力。几个实打实的数字：

|  |  |  |
| --- | --- | --- |
| 维度 | 典型准确率 | 说明 |
| 国家级（GeoIP2） | 约 99.8% | 最稳的一层，"境外全封"策略的底线 |
| 美国城市级（50km内） | 约 63%–78% | 不同测评口径差异大，远不到"精确" |
| 国内城市级（免费/通用库） | 普遍偏低 | 纯真实测常低于 70%，通用国际库境内偏差更大 |
| 移动网络 IP | 极不可靠 | 基站在城市间动态分配，城市级对手机用户基本失效 |

![IP地理定位精度边界](https://mmbiz.qpic.cn/sz_mmbiz_jpg/yJLbez93flicwvf2wf0OiaqElBr4ZCh2EycOcn6Arr2DYybqkDGNFmknTLfEu8VPibg1Os2PCPHzficIxibrUDFpnkJwqiay5vvpINd0Xx1DLOBfc/640?wx_fmt=jpeg)

还有几个会让你翻车的变量：VPN 和代理把流量导到出口节点，查出来的是出口位置不是真实位置；CGNAT 把一堆用户塞到一个公网 IP 下，城市级直接糊掉；数据中心 IP 能靠 ASN 认出来，但城市字段往往是机房地址而不是用户所在地。

> 📌 老宋数据：一个银行风控的真实案例——攻击者用数据中心 IP 发起登录，归属地显示"北京"，和受害者常驻地一模一样。城市级判断在这里彻底失效，差点放行。城市级定位不是不能用，是只能当"参考"，不能当"判决"。

## 03选库的坑：境内境外不是一套库通吃

回到开头那两件尴尬事，问题往往出在"用错了库"。国际库（MaxMind GeoLite2/GeoIP2、IP2Location、DB-IP）全球覆盖好，但境内城市级精度普遍偏弱——有测评说 MaxMind 在部分服务区国家级准确率一度低到 70.5%，国内城市级更是飘。如果你拿免费版 GeoLite2 去判断"这个境内 IP 是哪个市"，结果大概率会离谱。

境内要想准，得看本土库：纯真 IP 库（免费但更新慢、精度有限）、ipip.net（亚太 BGP 校正准、城市级，但免费版功能有限、商业版偏贵）、IP数据云这类带"区县 + 网络类型 + 风险评分"多维度的库。

⚠️ 老宋建议：别迷信"一套库走天下"。境外拦截看国家层，用国际库的国家级精度就够稳；境内要做省市级策略，老老实实补一套本土库。两条线并行，比拿一把不准的尺子量全世界强。

还有一个坑：免费库月更、季更，而黑产的数据中心 IP、住宅代理 IP 每天大量轮换。等你那套库更新过来，脏 IP 早就换了几轮。做风控用的库，更新频率本身就是精度的一部分。

## 04地域封禁怎么落地才不翻车

客户要的"境外全封、某省白名单、港澳台加强"，落到配置上有三条纪律：

**第一条，封禁的底线只用国家/省级。**国家层 99.8% 的准确率足够撑住"境外一律拦截"这种粗粒度策略。越往细了封，误封友军的概率越高——把境内地址误判成境外拦掉，业务方第一个找你。

**第二条，城市级只做"加分项"不做"判决项"。**比如"同一城市短时间大量登录"可以提权风控，但别拿它直接放行或封死。

**第三条，把"网络类型"和"匿名流量"当成一等公民。**真正该警惕的是数据中心 IP、VPN、Tor 出口，而不是某个具体城市。一个境外住宅 IP 可能比一个境内机房 IP 安全得多。好的 IP 库会直接给你标 ASN、ISP、是否代理，这些字段比城市名值钱。

> 💡 提示：如果产品本身不吐网络类型字段，光给个地名，那它再怎么"地域封禁"都是半成品。选型时先问厂商：你的 IP 库带不带 ASN / 代理 / Tor 标签？不带的话，所谓的精准定位就是个壳。

## 05库不更新，比没有库更危险

最后说最容易被忽略的一点：IP 库是会过期的。IP 段在运营商之间转让、重新分配，今天属于甲的段明天可能划给乙。MaxMind 的 GeoLite2 免费库以"周"为单位迭代，ASN 库每个工作日都更。更硬的是它的 EULA 里有一条：新版本发布后 30 天内，你必须删除本地旧数据库——"下载一次用一年"不只在技术上会跑偏，在许可协议层面也违规。

工程上几个真实约束，照着做能少踩坑：自动更新优先于手动下载，配 geoipupdate 让库定时覆盖旧库；容器镜像里打进 mmdb 的，镜像不重建数据就永远停留，要么挂卷让宿主机更新，要么用 sidecar 跑更新；长驻进程（Python 服务、Nginx 的 geoip2 模块）是把库映射进内存的，库换了要 reload，否则继续查旧数据自己还不知道；License Key 就是全部写权限，泄露等于别人用你的配额，配置文件 600 权限、密钥按环境分开。

// 老宋说：这不是一个"IP 库怎么装"的技术问题，是一类被长期低估的数据质量风险——你上层所有安全策略的可信度，天花板就是底层那张 IP 库的精度和新鲜度。行业里很多人把归属地当确定事实用，等到误封友军、放过攻击者才回头查，发现根子在库。只要还把"免费+陈旧"的库当作精准依据，这类错就还会再犯。现在去翻一下你们阻断产品的 IP 库版本号和更新时间，看它是不是还停留在去年。这件事半小时能查完，但能挡掉一大半"为什么该拦的没拦住"的扯皮。

🔧 最小可用：Debian/Ubuntu 装 geoipupdate 的 deb 包，写三行 GeoIP.conf（AccountID / LicenseKey / EditionIDs），crontab 每周三、周六跑一次，更新完顺手 reload 你的服务。十分钟，换来的是"定位永远跟得上现实"。
