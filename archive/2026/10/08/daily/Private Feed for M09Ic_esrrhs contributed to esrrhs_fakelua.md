## 背景

与真实 Lua 5.4 的差分测试发现 4 个输出层语义差异。语义均对照 Lua 5.4.6 官方源码核实（`lobject.c::tostringbuff`、`lstrlib.c` 的 `str_format`/`str_gsub`）。

## 修改内容

* **float → string 对齐 Lua 5.4**：此前各路径分别用 `%.17g` / `std::format` / `std::to_string`，且从不补 Lua 的 `.0` 后缀——`tostring(1.0)` 得到 `"1"`，导致 `tonumber(tostring(1.0))` 静默变成 integer。
  新增统一的 `FormatLuaFloat`（`%.14g`，结果只含符号和数字时补 `.0`，等价 Lua 的 strspn 判定），覆盖全部 Lua 值→字符串路径：`Var::ToString`（tostring/print/native）、interp `BinConcat`、`table.concat`、log，以及 JIT C 运行时头里的 `FlVarToStr`（TCC 按 C89 兼容写法）。json/xml/csv/ini 等序列化格式**刻意不改**。
* **print 不再给字符串加引号**：改用 `ToString(false, false)`，使 `print(x)` 与 `print(tostring(x))` 一致。
* **`string.format("%s", x)` 对齐 `luaL_tolstring`**：bool/nil/number 均合法并走 tostring（此前 bool 报错、float 固定 6 位小数 `2.5→"2.500000"`）；仅 table（无 `__tostring`）仍报错。
* **`gsub(s,p,r,n)` 负数 n**：此前任何负数都被当作不限次数。Lua 缺省/nil 时默认 `srcl+1`，循环条件 `n < max_s`，因此显式负数或 0 表示 0 次替换。
